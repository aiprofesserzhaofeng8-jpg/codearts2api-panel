# 同步后调用新型号

账号池 → 更多 → 同步上游模型：打开只读上次结果，点击同步成功即保存。参照 Sub2API 的账号白名单合并语义，保留上次已保存的调用来源。

## 全平台实施与来源

1. 按账号复用适配器的目录读取方法；CodeArts 使用其原生账号会话。
2. 按本次返回的目录类型保存快照、显示差异。只有实时聊天目录可以发布新来源，并保留其协议、流式、上下文和能力信息。
3. 以模拟上游验证账号隔离、失败保留、非聊天目录不进入聊天路由；生产账号需单独验收。

| 平台或账号类型 | 同步结果 |
|---|---|
| CodeArts、WorkBuddy、Trae、Qoder、Kiro、ChatGPT/Codex、Claude、MobileClaw、Gemini API、Antigravity、Grok、OpenCode、CommandCode、Cline | 从各平台适配器读取聊天目录 |
| DeepSeek、智谱、Kimi、MiniMax | 优先请求上游；适配器确实返回备用目录时标注为预置参考 |
| Bedrock | 无指定型号时请求上游，有指定型号时显示账号配置目录 |
| Vertex | 账号配置目录 |
| TeleAgent、Gemini CLI | 预置参考目录 |
| TypeSafe | 访问决策模型目录，结果用于查看，不发布为聊天型号 |

- 以前从未内置的新 ID 作为“平台/区域/上游 ID”发布。已有原始型号、别名、统一名称优先；允许裸名称且来源唯一时可直接用上游 ID。多个区域或平台同名时用全称。
- 对新增来源，列出模型、解析请求与分配账号均必须与当前分组取交集。不绕过模型白名单、不将同区其他账号视为该型号的提供者。重试也遵守同样约束。
- 同步失败不提交；成功但漏列保留既有映射。历史只读快照不自动发布，升级后显式同步生效。既有目录型号沿用原有权限和派发逻辑，不因漏列失效。
- 观察时间和目录差异继续按最近两次成功响应计算，不把它们当作永久下架信号。成功转发也不代表已经验证价格、上下文及所有多模态能力。

验收：模拟上游返回一个网关此前无法解析的新 ID。账号 A 保存后，授权密钥无需重启即可调用；只有 B 权限的密钥既看不到也不能调用。漏列、失败与重启不丢已保存来源。
