# 分组模型目录：账号型号、别名与统一模型

目标：管理员把账号加入分组后，可以直接展示该组的原始型号；采用兼容命名的组还可以展示已有的自定义别名。只有跨平台融合等需要统一名称的场景才需要配置统一模型授权。

## 参考与边界

[Sub2API 的模型列表](https://github.com/Wei-Shaw/sub2api/blob/main/backend/internal/handler/gateway_handler.go)依据密钥分组和平台规则生成，[账号映射汇总](https://github.com/Wei-Shaw/sub2api/blob/main/backend/internal/service/gateway_service.go)收集客户端使用的名字。借鉴这一点，不复制其平台默认型号兜底或渠道页面。本项目的自定义别名由全局配置持有；别名指向的来源必须属于本组展示范围。统一模型的显示、调用和来源授权继续独立。

## 实施顺序

1. **补齐目录。** 用户端和密钥端已使用同一个分组模型投影。基础目录已有别名；账号同步发布的额外型号也应列出可解析的配置别名。沿用请求解析器，无法解析或目标歧义时不列出；同一名称仅一行。继续按目标的账号归属、白名单、可见性和名称模式过滤。完整型号模式不宣传无法调用的裸别名。
2. **调整分组编辑。** 在管理员新建分组表单中默认勾选“默认显示原始型号”，保留完整型号命名模式。把展示和名称模式移到账号选择旁，已有组按保存值回显。分组列表移除只统计统一模型授权的“模型范围”列。不给已有组改设置，不修改 API 缺省值、账本、路由或数据格式。
3. **验收。** 同一权限下比对用户接口与密钥目录的型号集合；验证零统一授权的组可列原始型号，兼容模式可列别名，严格模式不列裸别名，隐藏状态和组外来源不会泄漏。测试仅用本地夹具，不调用真实上游。检查新建和编辑分组表单、列表以及保存后的回显。

## 现有组如何启用

编辑目标分组，勾选“默认显示原始型号”。只有确实需要裸名或自定义别名时，才选择“兼容旧裸名称与别名”；它会改变此组接受的请求名称。无需新建同名统一模型。已有原始可见性覆盖和白名单继续生效。
