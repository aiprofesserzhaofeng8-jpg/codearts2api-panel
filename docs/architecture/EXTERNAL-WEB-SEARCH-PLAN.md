# 多服务商外部搜索实施计划

状态：独立搜索入口、管理页、分组授权和 Pi 扩展已实现。隔离实例的 DeepSeek 管理测试返回 HTTP 200。Pi 已使用模拟搜索服务和模型完成工具往返测试。真实联网验收已通过。Pi 使用 19087 实例的 codearts/glm-5.3-flash，显式选择分组授权的 DeepSeek 服务，调用一次 web_search，模型收到结果后引用了 https://ar5iv.labs.arxiv.org/html/1706.03762v5#1 。网关搜索记录为 HTTP 200，耗时 448 ms。

## 1. 第一版交付结果

管理员在「配置 → 外部搜索」保存多条搜索服务配置，先支持 DeepSeek Search，并保留已存在的 SearXNG。每个分组明确获准使用哪些服务，客户端只注册一个 `web_search` 工具；未指定服务时使用管理员设置的默认服务。模型渠道的原生搜索继续按原渠道执行。

第一版完成范围：

- 多配置的新增、编辑、测试、启停、默认选择和删除。
- DeepSeek 独立 Search API 适配；SearXNG 沿用现有传输。
- 独立外部搜索入口、分组授权、使用记录，以及 Pi 工具接入。
- 为 Exa、Brave、Tavily 留适配接口；未实现的服务商不能保存为可用配置或被调用，界面不放无效按钮。
- 不增加自动切换、并行多引擎搜索、模型代搜、自动注入提示词、网页读取或自动重试。

验收体验：Pi 使用任意支持工具调用的已授权模型，调用 `web_search` 后得到 DeepSeek 搜索结果，再由原模型回答。搜索不需要 DeepSeek 聊天模型，也不使用其他平台的模型账号凭据。

## 2. 两条搜索链路

### 独立外部搜索

```text
Pi 模型产生 web_search 调用
  → Pi 工具执行器 POST /v1/search
  → 网关校验密钥、用户、分组、搜索服务授权及请求限额
  → 选定的一条搜索服务配置
  → DeepSeek Search / SearXNG
  → 统一结构化结果
  → Pi 回传工具结果给原模型
```

### 模型渠道原生搜索

GPT、Claude、Grok 等渠道已经支持的服务端搜索，仍随原模型请求声明工具、由上游执行。WorkBuddy、TeleAgent、MobileClaw 的独立原生搜索入口也继续使用各自账号和原有权限。

两条链路不隐式互转。客户端显式选择原生搜索或外部搜索；Pi 安装器遇到同名工具时报告冲突，不覆盖用户已有工具，不同时注册两个 `web_search`。网关不能仅凭“模型名是 DeepSeek”推断实际入口支持官方原生搜索。

## 3. 配置与权限模型

### 搜索服务配置

| 字段 | 含义 |
| --- | --- |
| `id` | 服务端生成的稳定标识；改名不影响授权 |
| `name` | 管理员可读名称 |
| `provider` | 第一版只接受 `deepseek`、`searxng` |
| `enabled` | 是否接受新的调用 |
| `api_key` | 独立搜索凭据；仅写入、不回传 |
| `endpoint` | 仅 SearXNG 需要；DeepSeek 固定官方地址 |

全局保存 `default_service_id`；每个分组增加 `search_service_ids` 白名单，缺省为空。搜索配置属于独立设置，不再放在 CodeArts、Trae 的 ProviderSettings 中，不加入模型目录、统一模型或模型账号池。

规则：

1. 新增配置默认停用，添加成功不自动授权任何分组。
2. 设置默认服务必须指向已启用且配置完整的服务；默认不代表全员授权。
3. 不指定服务时解析全局默认，再检查所属分组是否获准使用；不从白名单里偷偷换另一个服务。
4. 指定服务不存在、停用或未授权时拒绝；不退回默认，也不泄露未授权服务的名称、密钥和地址。
5. 停用或删除默认服务时，同一存储事务清空默认引用；删除同时清理分组引用，不要求手动解绑。之后默认调用明确报未配置。
6. 删除分组后，其密钥仍按既有规则拒绝访问，不获得公共搜索权限。
7. 管理配置与分组编辑采用现有 revision / 冲突检查模式，避免旧编辑表单覆盖新授权。

密钥更新采用 PATCH：字段缺省表示保留；非空字符串表示替换；显式清除操作仅允许同时停用服务。管理响应只提供 `api_key_set`，不返回明文或可用于重放的片段。沿用 Store 的私有状态文件与写入机制，不创建第二份凭据文件。

## 4. 接口契约

### 管理接口（复用管理员认证）

- `GET /admin/api/search-services`：服务列表、默认服务及版本；全部脱敏。
- `POST /admin/api/search-services`：新增配置。
- `PATCH /admin/api/search-services/{id}`：更新名称、凭据、地址或启停。
- `DELETE /admin/api/search-services/{id}`：删除并原子清理引用。
- `PUT /admin/api/search-services/default`：设置或清空默认服务。
- `POST /admin/api/search-services/{id}/test`：使用已保存配置执行一次短搜索，返回耗时、结果数和少量结果。

“测试搜索”可能消耗服务商额度；按钮旁或确认内容明确这一点，不在页面标题下堆说明。管理员测试不要求服务已启用，但不能绕过凭据和地址校验；不计入普通用户用量，单独记录测试操作。

### 客户端接口

`POST /v1/search` 使用现有网关 Bearer 密钥，不接收上游密钥、任意 URL 或供应商自定义请求体。

```json
{
  "query": "Attention Is All You Need site:arxiv.org",
  "max_results": 5,
  "service_id": "search_example"
}
```

`service_id` 可省略；`max_results` 默认 5，第一版统一 1–10；搜索词采用实际服务商限制。DeepSeek 为 1–128 个 Unicode 字符，不静默截断，不自动拆成多次付费请求。

```json
{
  "request_id": "request_example",
  "service_id": "search_example",
  "provider": "deepseek",
  "results": [
    {"title": "Attention Is All You Need", "url": "https://arxiv.org/abs/1706.03762", "snippet": "论文摘要"}
  ]
}
```

只返回非流式 JSON；合法空结果是成功。结果归一化为标题、HTTP(S) 链接、摘要，并去重、过滤无效地址。保留 request_id 便于排障。

错误语义：无效密钥 401；权限拒绝 403；输入不合法 400；本地限流 429；默认未配置或服务停用 503；上游连接、协议或凭据故障映射为带稳定原因码的 502/503，限流可保留 429 与 Retry-After。上游余额不足不能直接包装为本地用户预算耗尽 402。不回传原始上游错误正文和认证信息。

## 5. 执行、预算与费用边界

当前 `gateway.RunSearch` 的外部搜索仍走模型账号租约；`storage.CheckSearchBudget` 会拒绝设置 Token、美元预算或钱包的用户。这是旧接口行为，不能照搬到新的独立服务入口。

新入口复用现有认证、用户启停、有效分组、请求频率、请求次数预算和用户并发机制，但不选择或占用模型账号，不解析模型凭据，不影响模型账号健康、冷却或模型目录。复用现有请求预留与幂等释放，不为搜索建立第二套用户并发计数器；必要的“无模型账号”准入由 Store 窄方法完成。

**第一版明确采用管理员承担外部搜索成本：**

- 上游搜索费用从管理员配置的服务商账户扣除。
- 分组授权代表管理员允许该组使用此搜索服务；页面分组授权处说明费用归属。
- 用户的搜索请求计入既有请求次数限额和搜索记录；不从用户模型钱包、Token 预算或美元预算扣费。
- 有模型钱包或费用预算不因此被禁止搜索；是否可搜索由搜索授权及请求限制决定。此规则仅适用于新外部搜索入口，不修改普通模型计费与旧搜索入口契约。
- 记录 `kind=search`、实际服务 ID、供应商、状态、耗时；日志与统计不得伪造模型账号或把未知 Token 写成实测零值。
- 外部搜索记录不得触发模型账本的“用量缺失”封锁，也不能污染模型成功率、模型 Token 和模型费用汇总；复用现有记录/结算入口并按明确的操作类型处理，不另建财务账本。
- 按已知单价计算的金额只能标为参考估算，不能当作供应商实扣或用户扣费。第一版不增加转售倍率和用户搜索钱包。

如果以后需要向普通用户收取搜索费，应单独实施按次计费及账本验收，不把它混入这次接入。

每次请求只调用一个服务、一次上游请求，沿用 20 秒搜索总超时，并响应客户端取消；不在取消后继续搜索。失败、超时和取消都释放本地请求预留与并发占用。请求发出前使用最新的配置及授权快照；之后停用影响新请求，不承诺撤销已发出的付费请求。

## 6. DeepSeek 适配与扩展点

第一版请求 `POST https://api.deepseek.com/v1/tools/search`，Bearer 使用该条搜索配置的密钥。发送 `query`、`count`、`need_content:false`，优先使用响应 `summary`，缺省时用 `snippet`；不另外调用聊天、Fetch 或其他搜索服务。

复用 `internal/websearch`：

- 保留现有 SearXNG `Client.Search` 调用契约，让旧调用方继续工作。
- 增加统一外部搜索调度与 DeepSeek 实现，输入为选定服务配置及搜索请求，输出继续复用中立搜索结果结构。
- 供应商差异留在该包：鉴权、请求构造、限制、结果与错误映射。HTTP handler 不按服务商复制整套逻辑。
- 固定注册已实现适配器；以后增加 Exa、Brave、Tavily 时实现同一接口与契约测试。无需动态插件系统，也不生成空适配器。
- 禁止跟随携带密钥的重定向；沿用有界响应读取，超限明确失败。

官方协议依据：[Search & Fetch](https://api-docs.deepseek.com/guides/search/)。价格依据：[Models & Pricing](https://api-docs.deepseek.com/quick_start/pricing/)，独立 Search API 按每千次成功且有结果的请求收取 0.75 美元。HTTP 200 且结果为空时，网关按成功返回空列表，DeepSeek 不收取此次搜索费。价格仅供管理员估算。

## 7. 页面和 Pi 接入

在现有配置页添加一个「外部搜索」管理区，暂不增加独立侧边栏页面。列表列为：名称、服务商、状态、默认、操作。操作包括测试、编辑、启停、设为默认、删除；标题下不加说明小字。

编辑弹窗只显示当前服务商需要的字段：DeepSeek 显示密码框，SearXNG 显示地址。密钥保存后清空输入框并显示“已设置，留空不修改”；有显式清除操作。分组编辑器增加搜索服务多选，不与一百多个模型混在同一列表。

扩展既有 `scripts/connect-client.py pi`，以显式选项安装项目提供的 Pi 搜索工具；普通模型同步不自动安装或切换搜索。工具只持有网关地址及既有网关密钥引用，不复制 DeepSeek API Key。提供可选服务 ID，缺省使用默认服务。

实施前核对当前 Pi 扩展接口，使用正式注册方式，不靠提示词假装已有工具。备份待修改的客户端配置；重复安装幂等；发现同名工具时停止该项安装并说明位置。卸载只移除本项目工具。工具接入验收必须观察真实调用及返回内容，不能只验证 `/v1/models`。

## 8. 存储、迁移与暂停草稿

当前状态 schema 为 11。实施时新增独立搜索配置、默认引用与分组授权字段，升级到 12，并复用既有迁移链及高版本拒绝机制。旧版本会忽略新增授权字段，不能直接拿新状态回退运行。迁移前备份，失败不覆盖原状态；上线后的回退需处理新数据，不能简单改版本号。

旧状态迁移：

- 外部搜索列表及分组白名单默认空；不自动启用 DeepSeek、导入账号池凭据或授权全员。
- 原 CodeArts/Trae 的 SearXNG 配置和原 `/v1/search/{平台}/messages` 路由继续工作，保留既有 ACL、预算及账号租约契约。
- 新 `/v1/search` 使用独立配置和授权，不挪用旧默认 WorkBuddy 搜索入口。
- 旧 SearXNG 用户可显式创建新配置、授权分组、迁移客户端，验证后再关闭旧入口配置。不自动双写两份配置。

上次被暂停的修改不是可交付版本：`ProviderSettings.SearchAPIKey`、`PublicSearchSettings`、`mergeProviderPatch` 增量、`gateway.RunSearch` 的 deepseek 分支、`server/search.go` 对尚未实现 `DeepSeek` 方法的调用及对应测试改动，属于按平台存储密钥的旧草稿。

实施第一步按实际 diff 逐项撤回这些草稿，再建设独立配置；不能整文件回退，因为同文件还包含 TeleAgent/MobileClaw、提示词及其他既有工作。发布前按下列交付门槛验收。

| 批次 | 工作 | 完成条件 |
| --- | --- | --- |
| 0 | 清理暂停草稿，确认当前基线 | 无悬空方法引用，保留其他改动，可编译 |
| 1 | 独立配置、schema 迁移、分组授权、脱敏 CRUD | 重启保持；默认/删除引用一致；保存失败原子回滚 |
| 2 | DeepSeek 适配、新搜索入口及请求级准入 | 模拟端到端测试通过；不取模型凭据、不占模型账号、不回退 |
| 3 | 管理页、分组选择、管理测试按钮、OpenAPI 类型 | 实际渲染和操作通过，密钥不回显，中英文和窄屏可用 |
| 4 | Pi 工具、使用文档及真实验证 | Pi 真正发出搜索调用、获得引用、交回原模型；真实测试需要管理员安全配置 DeepSeek Key |

## 10. 必须覆盖的验收用例

1. 保存两条 DeepSeek 配置，显式选择与默认选择分别命中正确配置；更改默认不修改分组白名单。
2. 无效/停用密钥、停用用户、失去分组、未授权服务均在上游请求前拒绝；默认未授权不能换到其他服务。
3. 停用/删除默认后正确清理引用；删除分组保留密钥但拒绝调用；并发编辑返回冲突，不丢授权。
4. 无模型账号的已授权分组可以执行外部搜索；模型账号耗尽、冷却或凭据错误不影响外部搜索。
5. 用户请求次数、频率和并发限制继续生效；模型钱包/Token 预算存在时按管理员承担费用的规则允许搜索，不扣模型预算。
6. 上游 401、402、429、500、超时、取消、重定向、无效 JSON、超大响应：单次执行、错误脱敏、释放占用；随后普通模型请求不因该次搜索产生预算封锁。
7. 成功、空结果、重复/非法 URL、缺省摘要与 Unicode 128/129 字符边界；不静默截断搜索词。
8. 密钥留空保留、替换、显式清除、服务端持久化及重启；列表、审计、日志、错误、客户端配置均无上游凭据。
9. 旧 SearXNG 与平台原生搜索、GPT/Claude/Grok 原生协议透传保持原入口和权限；未实现的 Exa/Brave/Tavily 不能误显示可调用。
10. Pi 安装、重复安装、同名冲突、取消请求、工具结果回传与卸载；不能同时触发外部与原生两套搜索。
11. schema 11→12、迁移写入失败、旧版拒绝新状态及备份恢复；检查所有新增字段克隆和引用清理。

复用现有 Go 定向测试、前端构建/浏览器烟测、OpenAPI 生成检查和架构检查。真实最小验收执行一次明确的搜索，保留脱敏请求/结果和调用记录；不跑批量付费压测。
