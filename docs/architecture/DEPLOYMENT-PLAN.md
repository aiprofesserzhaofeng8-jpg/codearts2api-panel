# 单实例部署与运维实施计划

状态：D1～D4 已有首轮实现与本地隔离验收，D1、D2、D3 已完成专项复核。GitHub 发布、公网证书和 ARM 真机运行未执行，见 [首轮验收记录](../acceptance/DEPLOYMENT-2026-11-02.md) 及各阶段专项记录。

## 目标与边界

补齐 Linux 单实例的可安装、可检查、可备份、可恢复和可升级流程。参考 Sub2API 的部署职责划分、首次安装和 SSE 代理注意事项；按本项目的 JSON 状态、用量账本与统一认证实现，不引入 PostgreSQL、Redis 或第二个写进程。

保留根 Dockerfile/Compose 为源码构建入口；deploy 放生产配置和运维工具。普通推理、账号调度、凭据刷新、账本格式和前端不改。本轮不切换本机现有服务、不部署远程、不推送标签或公开发布。

## D1：一致性备份、恢复和部署诊断

- 一个 Python 标准库命令行工具集中实现运维，避免多个脚本重复解释状态格式。
- 备份专用数据目录的全部普通文件，包括状态、账本、成长检查点、安装标记和私有恢复文件；拒绝符号链接，文件清单记录大小与 SHA-256，归档权限 0600。
- 对受管 systemd/Compose 实例先停止并确认停止，再备份；操作结束恢复原运行状态。离线目录要求显式声明已停止，并检查本机写进程。不能承诺仅靠该工具识别其他主机的共享卷写者。
- 恢复只允许不存在的新目录，先验证清单、大小、摘要及安全路径，再提交；禁止覆盖现有数据或自动用旧凭据回滚。
- 只读 doctor 检查路径权限、状态 schema、附属文件和 HTTP 状态；不打印密码、密钥、账号内容或响应原文。
- 健康状态区分 running、setup_required、unhealthy；安装等待是存活，但不是可接推理流量。

验收：真实临时文件备份往返；运行进程拒绝、损坏/路径穿越/链接归档拒绝、旧数据不覆盖、异常时服务恢复；安装和运行两类健康状态。

D1 收尾：已补齐不可读目录拒绝、恢复原子不覆盖、主状态/附属文件诊断及 Compose 异常状态拒绝，并验证真实 systemd/Compose 停启和非空账本恢复只结算一次。最终结果见 [D1 专项验收](../acceptance/DEPLOYMENT-D1-2026-11-02.md)。

## D2：HTTPS 与容器生产入口

- 提供一套宿主机 Caddy 模板，默认直连 Caddy，后端仅监听 loopback；保留 Host，清理伪造转发头，SSE 不压缩、不缓冲，不设截断长生成的响应写超时。
- 提供固定镜像版本的生产 Compose 与环境样例；沿用单个专用数据卷，加入非 root 权限说明、停止等待、安装兼容的健康检查。
- 验证代理配置与真实分段 SSE：首段到达、后续分段、取消断连；验证安装状态和普通应用 HTTP。

验收：配置语法、健康检查在初始化/正常/故障状态下的结果；代理模拟上游实测。工具不可用时记录明确限制，不能把静态审查写成运行通过。

D2 收尾：已实测本地 CA 校验的 TLS 首次安装、角色登录、HTTP 重定向、四个 SSE 路径、取消、错误透传和容器三类健康状态；修复公开 origin 尚未配置时首次 HTTPS 登录 Cookie 缺少 Secure 的代理配置缺口。详见 [D2 专项验收](../acceptance/DEPLOYMENT-D2-2026-11-02.md)。

## D3：版本包、安装和升级

- Linux amd64/arm64 发布包内含二进制、版本与 schema 元信息、部署工具/模板和校验清单。
- 提供用户级 systemd 安装，版本包先验摘要再落盘，首次安装保留向导，不生成固定密码；禁止覆盖已有安装。
- 升级先验包与 schema、停服务、完整备份、切换版本、启动并核对健康/版本。失败保留诊断和旧程序；不自动回写旧状态，也不自动降级 schema。
- 增加 Release 工作流：验证、构建双架构产物与镜像、固定版本标签；实际发布由显式版本标签触发。

验收：临时目录安装、合法升级、摘要篡改、错误平台、版本/状态不兼容、启动失败等路径；构建架构与版本元信息一致。未执行 GitHub 发布和 ARM 真机运行必须列明。

D3 收尾：已补齐失败打包清理、包与摘要不覆盖、升级停机前实际进程核对和切换后失败处理；Release 附件增加独立安装工具及摘要。重新构建包含 D1/D2 修复的双架构包，并以包内 CLI 完成真实 systemd 安装/升级和未就绪候选故障验收。详见 [D3 专项验收](../acceptance/DEPLOYMENT-D3-2026-11-02.md)。
