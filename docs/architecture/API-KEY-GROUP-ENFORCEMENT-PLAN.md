# API 密钥必须经有效分组访问模型

状态：2026-11-22，源码已实施并通过隔离验收，待部署。

## 目标与对齐边界

客户端必须使用绑定有效分组的 API 密钥访问模型；未分组或分组已删除时拒绝访问，不能退回全局权限。保留密钥本体，显式改绑有效分组后按新组授权恢复。

对齐 Sub2API 的默认密钥生命周期，不复制其数据库、软删除基础设施、缓存或“允许未分组 Key 调度”可选开关。本项目仍使用现有文件存储和锁内权限复核。普通用户仍只有一个分组，旗下密钥跟随用户分组，不引入多分组用户。

参考已核对的 Sub2API 提交 `328db26f450edbdf9f8d4344a3ea903ac6396842`：

- [KeysView.vue](https://github.com/Wei-Shaw/sub2api/blob/328db26f450edbdf9f8d4344a3ea903ac6396842/frontend/src/views/user/KeysView.vue)：创建表单拒绝空分组；这不代表其后端所有创建入口都强制非空。
- [group_repo.go](https://github.com/Wei-Shaw/sub2api/blob/328db26f450edbdf9f8d4344a3ea903ac6396842/backend/internal/repository/group_repo.go)：删除关联及软删除分组，保留密钥原 group_id。
- [api_key_auth.go](https://github.com/Wei-Shaw/sub2api/blob/328db26f450edbdf9f8d4344a3ea903ac6396842/backend/internal/server/middleware/api_key_auth.go)及[middleware.go](https://github.com/Wei-Shaw/sub2api/blob/328db26f450edbdf9f8d4344a3ea903ac6396842/backend/internal/server/middleware/middleware.go)：已删除分组拒绝调用；未分组默认拒绝，但另有可选放行设置。

## 实施顺序

### 1. 收紧既有鉴权和准入入口

- 在现有密钥权限校验中统一检查非空且存在的分组，复用 Store 的锁及错误映射，不增加第二套中间件、缓存、锁或每请求网络查询。
- 缺少、无效或停用密钥返回 401；有效密钥未分组、关联分组不存在时返回 403，并给出“请绑定有效分组”的可操作提示。错误体保持各协议格式。
- 模型列表、Chat Completions、Responses、Messages、其他已注册模型调用路由、密钥使用配置入口均走相同权限判定；实施时逐一核对注册路由，避免只修 Chat。
- 准入、换号重试、摘要备用型号等继续在原入口复核权限，拒绝请求不得抵达上游。
- 管理员登录身份仍可读取全局模型目录、管理账号及分组。先确认空密钥内部调用的实际用途，不能把管理目录或合法管理探活误当成匿名客户端请求；客户端不得利用管理入口绕过鉴权。
- 删除客户端匿名放行后，移除对应可操作设置及误导说明；旧状态中的兼容字段可继续读取，但不得再授予模型访问权限。不为删除一个旧字段升级 schema 或批量改写状态。
- 当前分组没有独立启停字段，本次不新增。若实施时发现已有启停能力，则复用其检查。

### 2. 保留创建、删除与改绑流程

- 管理员创建、首次引导及管理 API 必须生成有有效分组的密钥；普通用户创建沿用用户当前有效分组。
- 删除分组继续保留密钥值与历史 group_id，不清空 group_id，不自动绑定其他组，不自动生成兜底组。
- 管理员密钥经现有改绑入口恢复；用户密钥经现有用户分组修改流程恢复。重新绑定不启用已停用密钥、不清除预算、不重置余额或历史用量。
- 已开始的请求沿原租约完成结算；删除后不得新建租约或发起重试。不增加后台收尾或延长取消期限。

### 3. 调整界面与契约

- 将“旧版全局密钥”替换为“未分组 · 不可调用”；保留原密钥启用状态，分组可用性单独展示，避免伪装成密钥被停用。
- 失效引用显示“分组已失效 · 不可调用”，提供现有分组绑定操作；用户密钥提示从用户管理重新分配。
- 使用对话框不能为无有效分组的密钥展示可用模型或生成看似可运行的模型示例；显示原因及绑定入口。
- 账号分组删除提示明确“密钥保留，关联密钥将无法调用”。已有正确文案保留。
- 同步中文、英文与现有管理/使用文档；仅在响应契约确有变更时更新 OpenAPI 和生成类型。

## 验收与完成条件

使用隔离状态、测试分组和假上游。不得删除真实分组、重置真实预算或展示密钥明文。

| 场景 | 预期 |
| --- | --- |
| 新建传空组或不存在的组 | 创建失败，不生成可用密钥 |
| 载入旧版空组管理员密钥 | 记录仍存在；目录、配置及推理均被拒绝，上游零调用 |
| 未签发密钥、本机访问、旧匿名开关为真 | 客户端模型请求仍返回 401 |
| 密钥属于 A，A/B 各有不同模型 | 只能列出与调用 A 授权范围，不能访问 B |
| 保持密钥绑定直接删除 A | 删除成功，密钥和原 group_id 保留；后续请求返回 403 |
| 原密钥改绑 B | 仅恢复 B 权限；A 权限不恢复；原密钥值不变 |
| 有效但没有账号或授权模型的分组 | 不回退全局；按现有不可用/禁止规则响应 |
| 改绑或删除写盘失败 | 原状态完整回滚，不能提前发布新权限 |
| 删除时已有在途请求 | 结算一次、槽位释放；后续重试和准入拒绝 |
| 重启后再读旧密钥与失效引用 | 权限与界面状态一致，不恢复全局访问 |
| 管理员控制台、用户资料/余额/历史 | 正常可读，不因分组失效无法登录或查账 |

复用原 `group_lifecycle_test.go`、鉴权/协议/密钥使用测试及浏览器脚本，补缺失场景，不重建测试框架。相关假上游需断言拒绝请求没有外发。检查 storage/access/server 定向测试与相关竞态测试、浏览器主链路和实际渲染，最后运行仓库要求的 `make check`；仅文档阶段检查链接，不提前标记实现通过。

## 上线影响与部署顺序

这是对旧全局密钥和匿名调用的有意收紧：未绑定分组的旧客户端将在升级后被拒绝。发布前只读列出受影响密钥的名称/引用和数量，不输出明文；由管理员明确选择目标组后，经现有管理入口绑定。不得为保持可用而自动授予全部模型。

实现验收完成后再安排部署，使用最新运行状态备份；回滚程序不回滚账本或凭据。旧程序可能重新开放全局权限，不能把回滚当作权限恢复方案；优先通过改绑修复客户端。部署与真实密钥改绑单独执行，本计划不自动进行这些操作。

## 实施验收记录

- 客户端网关统一要求有效密钥。本机请求和携带历史匿名设置的实例都返回 401。旧命令行参数保留解析兼容性，开启时输出弃用提示。
- 历史状态夹具验证了空组密钥的 403、显式绑定后恢复、删组后重启仍拒绝，以及再次改绑。模型目录、密钥使用指引和各推理协议均覆盖。
- 普通用户用同一把密钥分别通过 Chat Completions、Responses 和 Messages 调用 A 组模型。删除 A 后，使用指引和调用均返回 403，假上游调用数保持为 3。分配 B 后，使用指引只列出 B 的模型，调用旧模型被拒绝，调用 B 的模型后上游计数变为 4。
- 仓库 `make check`、storage/server 鉴权与分组定向竞态测试、协议夹具基准冒烟通过。浏览器验收通过 `console-first-call-smoke` 和 `groups-smoke`，检查了未分组行的禁用状态及绑定入口。
