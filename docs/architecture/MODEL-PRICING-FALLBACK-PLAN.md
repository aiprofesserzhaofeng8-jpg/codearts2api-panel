# 模型缺价 402 修复计划

2026-11-21 · 已实施，已在隔离实例验收

## 要解决的请求

普通用户用有效密钥请求 `kimi-k3`、`qwen3.8-flash` 和 `gpt-6.1-sol` 时，用户 USD 预算检查因实际来源缺价返回 402。管理员应能一次设置全站 Token 默认价，让已有分组授权、有可调度来源且预算充足的用户调用这些模型，并按同一套单价结算。`trae-custom_model_deepseek_chat` 的 503 表示缺少可调度来源，单独排查调度。

目前预算检查、钱包预留和用量估价都调用 Store 的估价逻辑。它先查管理员给实际模型配置的价格，再查内置表。价格编辑器也按实际模型 ID 列行。这是本次改动的共同入口。[现有估价逻辑](../../backend/internal/storage/pricing.go) · [钱包与订阅](../../backend/internal/storage/consumer_billing.go) · [现有计价约定](../USAGE.md)

## 单价怎么选

对每一次上游尝试，按**实际来源模型 ID** 顺序取第一份完整价格。单位统一为 USD／百万 Token，三项分别是未缓存输入、输出、缓存命中输入。

| 顺序 | 价格 | 匹配规则 |
| --- | --- | --- |
| 1 | 管理员模型价 | 精确匹配实际模型 ID。显式填 0 有效。 |
| 2 | 模型参考价 | 保留现有内置的已核实条目，再按已确认的提供商和原生型号精确匹配随版本发布的参考表。 |
| 3 | 全站默认价 | 管理员设置的一组三项单价，适用于前两层均未命中的 Token 调用。初始为空。 |

三层都未命中时，要求金额的用户预算、密钥预算、套餐或钱包沿用原有缺价处理。仅限请求数或 Token 数、且无需金额结算的调用按原规则放行。上游没有报告用量时，即使有默认价也不能算出费用，仍走原有待核对流程。

Sub2API 已有分组、渠道、LiteLLM 和内置价的查找顺序。它的 OpenAI 路径允许在事后结算缺价时记零费用。本项目借鉴参考价匹配，保留钱包预留时必须能报价的规则。全站默认价是本项目的管理员定价选项。[Sub2API 定价解析](https://github.com/Wei-Shaw/sub2api/blob/328db26f450edbdf9f8d4344a3ea903ac6396842/backend/internal/service/model_pricing_resolver.go#L47-L76) · [OpenAI 用量结算](https://github.com/Wei-Shaw/sub2api/blob/328db26f450edbdf9f8d4344a3ea903ac6396842/backend/internal/service/openai_gateway_usage.go#L263-L278)

## 实施顺序

1. **先打通默认价和结算。** 在持久化状态中增加可空的全站 Token 单价，旧状态缺字段即未设置。在现有估价入口统一解析价格、来源和实际模型 ID。一次尝试在准入时固定单价快照，预算检查、钱包预留和最后按实测 Token 结算都使用该快照。重试切换实际模型时为新尝试取价，已完成的尝试保留原报价。沿用现有账本和用量公式。
2. **补齐自动参考价。** 首版采用随发行版更新的本地参考表。实施时固定 LiteLLM 数据版本、保留出处和适用条款，把每 Token 价格换算为每百万 Token。按提供商和原生 ID 精确对应，不能凭统一名或相似名称跨平台猜价。缓存费未知、币种或单位不明、只有阶梯价而无法用三项单价表示时，整条跳过，交给下一层。对上述三个模型逐一记录实际匹配结果。推理请求只读本地数据。
3. **接入现有管理页。** 在「模型 → Token 价格表」增加「全站默认价」编辑入口，支持保存和清除。三项必须同时提供，复用现有数值校验。管理员接口扩展读取结果并单独保存默认价，保留旧的单模型读写契约。每行展示生效单价及来源，使用量记录能区分模型价、参考价和全站默认价。保存失败时保留原配置，错误显示在编辑器内。同步管理 API 文档和用量说明。

## 如何验收

| 用例 | 通过条件 |
| --- | --- |
| 重现三次 402 | 隔离实例中配置有 USD 上限的测试用户、有效分组和可调度测试来源。三个公开名分别命中明确记录的参考价或默认价，原 Chat Completions 请求获得回复，账本按实际来源结算。 |
| 金额能复算 | 使用测试默认价 2／6／1，输入 1,000 Token（含 200 缓存）、输出 100 Token，费用应为 0.0024 USD。用量、预算累计及钱包按既有换算规则一致。 |
| 覆盖、清除与重启 | 同时存在三层价格时模型价优先，其次是匹配的参考价。显式零价按零结算。保存后重启仍有效。清除默认价后，仅依赖它的计费模型恢复缺价响应。 |
| 重试与改价 | 同一统一名切换来源时，分别按两次尝试的实际模型和用量计费。在途改价只影响后续取得的新报价。旧用量记录保留原价。 |
| 权限与余额 | 余额不足仍触发预留失败，组外模型仍被拒绝，无可调度来源仍返回 503。缺少上游用量时仍标为未知。 |

先用隔离夹具完成验收，再在管理员页面走一遍设置、查看生效价格、清除的流程。实际部署时由管理员填写本站费率；运行中清除默认价即可停止对后续未知模型使用该费率。

## 实施与验收结果

**三次 402 已在隔离网关复现。** 使用三个同名 CodeArts 测试来源，分别通过 `/v1/chat/completions` 调用。缺价时均在请求上游前返回 402。设置全站默认价后均返回 200。测试上游在响应前清除默认价，三笔已准入的请求仍各按 0.0024 USD 结算，用户钱包和预算累计与用量记录一致。下一次调用恢复缺价保护。[HTTP 与钱包验收](../../backend/internal/server/pricing_fallback_test.go)

| 客户端模型 | 随版本交付的参考表匹配情况 |
| --- | --- |
| `kimi-k3` | `opencode/go/kimi-k3` 命中参考价 3／15／0.3。隔离用例的 CodeArts 来源使用全站默认价。 |
| `qwen3.8-flash` | `opencode/go/qwen3.8-flash` 命中参考价 0.15／0.47／0.016。隔离用例的 CodeArts 来源使用全站默认价。 |
| `gpt-6.1-sol` | 所核对的 `chatgpt/gpt-6.1-sol` 参考数据缺少三项标准单价。ChatGPT 和隔离用例的 CodeArts 来源均需管理员模型价或全站默认价。 |

价格单位为 USD／百万 Token，顺序为未缓存输入、输出、缓存命中输入。参考费率随版本离线交付，数据版本、来源和许可随表保存在 [reference](../../backend/internal/usage/reference/)。

- 存储验收覆盖重启、重试跨来源报价、手工零价、清除和保存失败回滚。[存储用例](../../backend/internal/storage/price_fallback_test.go)
- 权限和结算验收覆盖组外 403、无账号 503、钱包预留不足 402、缺用量进入核对，以及普通用户的用量来源标记。[服务用例](../../backend/internal/server/pricing_fallback_test.go)
- 浏览器用隔离管理员会话设置三项单价，查看模型行的生效数值，刷新重开后清除。首次审查发现通用按钮样式使未设置时也显示清除按钮，已修正并复测。[浏览器验收](../../scripts/pricing-fallback-browser.cjs)

复验浏览器用例时，先在 `frontend/` 构建页面，再在 `backend/` 运行 `PANEL_PRICING_BROWSER=1 go test ./internal/server -run '^TestDefaultPricingBrowser$' -count=1`。
