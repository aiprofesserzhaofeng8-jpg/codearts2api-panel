## M3、M5 的渐进替换

先建立窄接口并由旧实现提供服务，再迁移具体实现。每条请求、账号凭据和账本任一时刻只有一个写入方；禁止新旧流程同时向真实上游发请求来比较输出。

中立账号类型先解决数据边界。CodeArts 专用 Session 由兼容存储表示和适配器解释，不能为了消除一个 import 就把 CodeArts 全部字段搬进 domain。

M3 第一批已实现 `accounts.Account`、`accounts.ErrCredentialChanged` 和 `app.Build`。`codearts.Account` 暂保留类型别名供平台内部及既有测试使用；共享生产代码已使用 `accounts.Account`。旧 `session` 由 `store` 编码器加载成不可变平台值；请求路径仅做类型断言，不序列化、解析或复制凭据。`codearts.StoredSession` 是该兼容值的唯一具体类型入口。WorkBuddy/Trae 继续使用已有不透明 JSON 凭据。

前六批均未迁移刷新互斥、准入锁和账本归属；它们当时仍由原实现负责。`app` 前六批只装配依赖；第二十批再迁入启动与关闭。凭据兼容槽在持久化接口迁移阶段退出，不为新平台扩展它。

第二批以 `upstream/codearts` 借用既有不可变凭据，包装原客户端的对话与业务错误过滤；`gateway.Completions` 负责已选中账号的普通单次执行、原有空响应回退及使用回调。SSE 聚合和流式选项归 `protocol`。不新增配置、锁、重试预算、凭据写入方或网络探测。普通流式仍立即交付，只有原来需要聚合的路径聚合。

第三批以 `upstream.BindStream` 绑定 WorkBuddy/Trae 原有适配器及已解析凭据，传递实际型号、会话与请求标识；gateway 只依赖最小流式能力，不要求两平台伪造原生非流式接口。非流式聚合维持原 32MiB 上限，错误和取消直接传回，分片观察和用量顺序不变。平台原生协议及页面不改。凭据解析/刷新互斥、摘要编排、提示词恢复、全局重试和管理接口仍在 server，后续逐项迁移。

第四批将有限的提示词恢复迁入 `gateway.RunPromptPolicy`，纯摘要识别/请求准备迁入 `requestpolicy`。server 投影当前平台设置，保留摘要豁免和计量/权限预算 hook；gateway 不依赖 Store 或具体平台。恢复仍最多一次，仍复用账号、凭据、型号和租约；上游任何已观察分片均关闭恢复窗口。摘要执行、备用型号权限、缓冲完整性检查、重试/冷却和结算尚未迁移，公共提示词继承也没有在重构中隐式启用。客户端默认策略的旧测试 helper 已移到测试文件，生产不保留重复的摘要准备实现。

第五批将摘要私有缓冲、完整性校验与最多一次截断重试迁入 `gateway.RunSummary`。通过窄 hook 保留 server 的备用型号解析/同平台地区约束、最新权限与预算复核、尝试计量及冷却写入。仍复用绑定凭据和租约；损坏 JSON、超限、非完整结束不交付内容，原始分片只复制不重建，错误消息与请求级终止保持一致。当前只抽取 CodeArts 已有摘要流程，没有扩大 WorkBuddy/Trae 的摘要能力。全局换号、WorkBuddy 短恢复、凭据归属和管理业务尚待后续批次。

第六批抽取 `gateway.RunAccountRetry` 与 `RunRecovery`，分别持有单一请求期限/尝试槽/租约循环及同租约有限恢复顺序。server 以 RetryDriver 保留原子选号、公开与实际型号权限预算、平台健康分类和持久化边界。WorkBuddy 300ms/3s、错误白名单及已观察分片限制仍为独立策略，恢复占用原总尝试次数；CodeArts 原退避序列不变。已提交输出的错误仍保留包装链，在健康处理之后阻止重放。凭据获取/刷新、管理业务与进程生命周期尚未迁移；准入锁和账本仍待 M5。

第七批将 WorkBuddy/Trae 凭据协调与按账号刷新锁从 server 迁入 `accounts.ProviderCredentials`。app 连接只读快照、现有 CAS 提交和实时续期开关；server 保留原适配器选择顺序和返回形态，不缓存另一份注册表。`accounts.OperationLocks` 复用原通道锁实现，刷新、领奖、成长任务仍用独立实例，锁域不扩大。正常请求依然只规范化一次，刷新后身份/地区复核、代际拒绝、保存失败保留内存新 token 均保持原语义。CodeArts Manager 及 IDE/签名/刷新内部实现没有重写；登录管理、备用型号授权及进程生命周期仍待后续批次。

第八批将 WorkBuddy/Trae 授权会话、检查/预览/确认、取消及导入身份校验协调迁入 `accounts.ProviderLogins`，HTTP 只保留 wire DTO、大小限制、UID 脱敏和错误映射。平台仍实现原生授权、设备绑定、回调核对和身份 Verify；Store 仍原子处理重复与保存。检查不入库、同一回调只交换一次、显式替换、保存失败保留预览、重复确认复用账号 ID、删除后禁止旧授权恢复等语义不变；不合并登录会话锁和刷新/奖励锁。CodeArts 登录、其余账号管理、备用型号授权及进程生命周期仍待迁移，M3 尚未完成。

第九批将 CodeArts 登录预览、确认保存、显式替换及删除后重放保护迁入 `accounts.BrowserLogins`，原生 LoginManager 由 `upstream/codearts.BrowserLogin` 包装；STS 解析、签名身份查询和回调提交归平台适配器。沿用原管理器、不可变 Session 指针及其 Commit 锁，保存成功后仍在该锁内失效缓存；Store 仍执行唯一原子保存。HTTP 保留字段、方法、大小限制与状态码。CodeArts 普通凭据解析/刷新、其余账号管理、备用型号授权及进程生命周期仍待迁移，M3 尚未完成。

第十批将 CodeArts 凭据互斥、缓存、最新快照、条件提交和失效迁入 `accounts.CredentialRuntime[T]`，原 Manager 内嵌这一运行时，保留原构造和回调入口并单向委托。平台仍读取 IDE、执行 DPoP 刷新、解释错误和判断凭据变化；Store 保留原 CAS 与持久化失败后保留轮转凭据的行为。沿用原 mutex、TTL、提交/快照/缓存/回写顺序，不改 WorkBuddy/Trae 的通道锁，也不增加凭据编解码或网络轮次。其余账号管理、备用型号授权及进程生命周期仍待迁移，M3 尚未完成。

第十一批将账号创建/导入后的提交、删除、并发设置、启停/暂停、清错、导出和重读协调迁入 `accounts.Management`。HTTP 解码并投影既有协议，CodeArts 手工/JSON/桌面构造和导出序列化归 `upstream/codearts`，app 连接原 Manager 及动态续期设置。删除/并发的失败回滚仍由 Store 原事务保证；其他旧操作的收尾保存继续记录失败，原生轮转 CAS 的错误语义保持，不借结构迁移改变持久化保证。导出 30s 截止时间、平台隔离、失效与保存顺序保持；请求执行路径和数据 schema 不变。备用型号授权、其余管理业务、应用及后台生命周期仍待处理，M3 尚未完成。

抽取 CodeArts 适配器时复用旧客户端；核实 [ADR 0004](../adr/0004-deferred-refactors.md) 提到的 SQLite、DPoP、刷新失败测试缺口当前是否已覆盖。存在缺口先补具体行为测试，不假设旧文档的缺口仍全部存在或已经自动消失。

第二批已核对：DPoP、凭据代际与部分刷新失败已有回归；SQLite 读取/原地覆写另有依赖本地 IDE 的条件测试，其中 Windows 读取测试包含溢出页，但本轮 Linux 无法执行该项。溢出页、内部页及空闲页缺少完整的确定性合成覆盖，部分刷新失败分支也仍有缺口。因此只包装原客户端，不移动或重写 SQLite、签名和刷新内部实现，不能将对话适配验收视为内部重构的完整证明。

迁移 Store 时先委托原有准入和事务入口，保持锁顺序；之后独立替换 runtime。配置提交、权限发布、预算重置、账号删除、刷新提交各自明确线性化时刻。没有并发证据，不拆成几个互相通知但可能遗漏更新的缓存。

每个旧入口记录唯一替代方和退出阶段；迁移后删除对应重复实现，保留有明确客户端兼容用途的 wrapper，避免永久保留两套逻辑。

第十二批将摘要备用型号准备迁入 `gateway.PrepareSummaryAttempt`，纯型号替换与推理控制隔离归 `requestpolicy.PrepareSummaryModel`。server 通过窄数据源投影原始目录、当前强制型号、绑定账号冷却及型号策略，授权仍单向委托既有分组和预算进度入口，不复制权限快照。保持强制型号、目录/平台/地区、冷却、策略、权限/预算、请求准备的顺序；只有准备成功才开始计量，同型号重试也复核已消耗预算。替换请求的原始 JSON 只需解析一次即删除顶层旧推理选项，不改工具或业务内容。普通请求、Store 原子准入与持久化、平台协议和页面不改；其余管理业务及应用/后台生命周期仍待迁移，M3 尚未完成。

第十三批将分组保存前的目录归一化、缺省映射兼容、密钥引用解析、创建/删除/启停、分组绑定及预算配置协调迁入 `access.Management`。五个持久化模型归 access，Store 保留类型别名和全部原函数体；权限快照、准入、预算预留/重置、账本和落盘仍为原子入口。app 借用当前目录和别名，不新增缓存或锁；HTTP 保留方法、参数大小、脱敏、状态码和管理员认证。严格事务失败回滚与旧版密钥删除/启停仅记录保存错误的区别保持原行为。全局设置/模型策略、目录/测活缓存、积分奖励、成长任务及应用/后台生命周期仍待处理，M3 尚未完成。

第十四批将全局设置补丁校验、局部发布和保存协调，以及模型策略的目录/别名、备用目标与平台校验迁入 `config.Management`。四种规范配置类型、纯校验与默认策略迁入 config，Store 保留类型别名、DefaultSettings 原生默认投影及单向默认构造 wrapper。HTTP 参数限制、密码脱敏、原错误码与身份头/限流热生效顺序不变；密码哈希、设置发布、策略回滚、准入和账本仍由原 Store 入口负责。全局设置失败仅记录、策略严格保存的区别保留；不扩展摘要支持平台、不新增热路径调用。目录/测活缓存、价格/认证会话归属、积分/成长任务、应用及后台生命周期和整体验收仍待处理，M3 尚未完成。

第十五批将目录刷新编排、刷新状态缓存与有界模型测活迁入 `catalog.Runtime`；app 借用唯一 Registry，HTTP 仅投影平台操作、参数和结果。刷新分区与部分成功规则、失败保留旧清单和期限、三把独立锁、测活任务锁取得时点、原宽松解码、64 型号/4 并发/逐账号 30s 及两类探测参数保持原值。CodeArts 模型获取和原生 Probe 由 upstream 包装复用同一 Manager/Client，其他平台继续通过原凭据/chatOnce；不改变普通推理、目录解析/分组映射、账号探活、准入及持久化。价格/管理员会话、积分奖励、成长执行、应用后台生命周期及整体验收仍待处理。

## 性能与真实验证

同机、同工具链、同固定假上游、同请求和并发条件下，记录旧/新实现的 ns/op、allocs/op、网关处理 p50/p95、首个有效输出和吞吐。基准包含原始直调、统一名路由、三协议流式/非流式、小消息、长历史和工具数据。

迁移的硬约束：正常路径上游调用次数不增加；重试预算不增加；原始兼容透传不新增全量解析；不缓存整个流式响应后才输出；准入锁不跨网络；每个 chunk 不写磁盘；不得弱化结算恢复保证。

将同机稳定基准 p95 或吞吐相对变化超过 5% 作为复核信号，不用单次噪声宣称退化或“零损耗”。先用多轮基准及绝对耗时区分噪声，确认的退化在解释并修正或记录明确取舍前不切换生产。不同机器或真实上游延迟不用于直接计算这个比例。

每个涉及执行路径的阶段做有界真实平台验收：确认返回的逻辑名称、日志中的实际平台/型号、工具闭环、取消恢复、租约归零及用量。将账号过期、上游暂不可用、未覆盖能力明确记录；不能把 HTTP 200 或模拟测试当成真实上游已通过。

真实验收授权和费用范围沿用用户指示；常规 CI 使用假上游，不自动执行领奖或刷新共享真实凭据。

## 回退与部署切换

纯布局和委托阶段不升级数据 schema。需要改变持久化表示时，单独提供版本化迁移、启动拒绝旧/未知格式的行为和恢复验证。

先验证新二进制和前端产物，再以可回退方式切换服务。每次变更记录源码与实际部署版本，避免浏览器连到另一实例却误判代码无效。

回退软件与回退数据分开。已产生的新用量和已轮转的新凭据必须保留；优先使用能读取当前状态的旧兼容程序或经过验证的格式转换。旧程序不兼容新 schema 时停止回退操作并使用兼容恢复方案，不能直接覆盖为旧备份。
