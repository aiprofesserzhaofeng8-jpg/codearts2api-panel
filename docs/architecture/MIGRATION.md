## M1 基线

当前统一模型功能存在未提交源码、文档和测试。先审查这些已有变更，保留实际实现与证据，再形成基线；不能只给旧 HEAD 打标签就声称已固定当前工作区。

记录：Git 提交及工作区状态、编译版本、运行二进制 hash/cwd、监听入口、前端资源标识、数据 schema、账号/分组/密钥计数。服务和数据只记录必要元信息，不将真实凭据写入报告或 Git。

备份状态、账本、任务状态和访问恢复文件到私有目录。运行实例使用的状态可能与工作区不同，必须从服务参数确认。回退演练用副本，不能向真实上游并行刷新同一轮转凭据。

- 审核第三方来源许可与历史测试样本路径，避免移动时遗漏。

## M3、M5 的渐进替换

先建立窄接口并由旧实现提供服务，再迁移具体实现。每条请求、账号凭据和账本任一时刻只有一个写入方；禁止新旧流程同时向真实上游发请求来比较输出。

中立账号类型先解决数据边界。CodeArts 专用 Session 由兼容存储表示和适配器解释，不能为了消除一个 import 就把 CodeArts 全部字段搬进 domain。

抽取 CodeArts 适配器时复用旧客户端；核实 [ADR 0004](../adr/0004-deferred-refactors.md) 提到的 SQLite、DPoP、刷新失败测试缺口当前是否已覆盖。存在缺口先补具体行为测试，不假设旧文档的缺口仍全部存在或已经自动消失。

迁移 Store 时先委托原有准入和事务入口，保持锁顺序；之后独立替换 runtime。配置提交、权限发布、预算重置、账号删除、刷新提交各自明确线性化时刻。没有并发证据，不拆成几个互相通知但可能遗漏更新的缓存。

每个旧入口记录唯一替代方和退出阶段；迁移后删除对应重复实现，保留有明确客户端兼容用途的 wrapper，避免永久保留两套逻辑。

## 性能与真实验证

同机、同工具链、同固定假上游、同请求和并发条件下，记录旧/新实现的 ns/op、allocs/op、网关处理 p50/p95、首个有效输出和吞吐。基准包含原始直调、统一名路由、三协议流式/非流式、小消息、长历史和工具数据。

迁移的硬约束：正常路径上游调用次数不增加；重试预算不增加；原始兼容透传不新增全量解析；不缓存整个流式响应后才输出；准入锁不跨网络；每个 chunk 不写磁盘；不得弱化结算恢复保证。

将同机稳定基准 p95 或吞吐相对变化超过 5% 作为复核信号，不用单次噪声宣称退化或“零损耗”。先用多轮基准及绝对耗时区分噪声，确认的退化在解释并修正或记录明确取舍前不切换生产。不同机器或真实上游延迟不用于直接计算这个比例。

每个涉及执行路径的阶段做有界真实平台验收：确认返回的逻辑名称、日志中的实际平台/型号、工具闭环、取消恢复、租约归零及用量。将账号过期、上游暂不可用、未覆盖能力明确记录；不能把 HTTP 200 或模拟测试当成真实上游已通过。

真实验收授权和费用范围沿用用户指示；常规 CI 使用假上游，不自动执行领奖或刷新共享真实凭据。

## 回退与部署切换

纯布局和委托阶段不升级数据 schema。需要改变持久化表示时，单独提供版本化迁移、启动拒绝旧/未知格式的行为和恢复验证。

先验证新二进制和前端产物，再以可回退方式切换服务。每次变更记录源码与实际部署版本，避免浏览器连到另一实例却误判代码无效。

回退软件与回退数据分开。已产生的新用量和已轮转的新凭据必须保留；优先使用能读取当前状态的旧兼容程序或经过验证的格式转换。旧程序不兼容新 schema 时停止回退操作并使用兼容恢复方案，不能直接覆盖为旧备份。
