# 请求、配置与状态设计

状态：M5/M6/M7 已实施；未来发布优化和扩展目标在下文单独标注。入口见 [总览](README.md)。

## 状态归属

| 状态 | 权威来源 | 生效或更新方式 |
| --- | --- | --- |
| 账号、密钥、分组、映射、策略、价格配置 | 持久化记录，业务模块负责校验 | 配置提交后发布不可变运行快照 |
| 平台凭据与代际 | accounts 协调的专用凭据记录 | 按账号串行刷新，条件提交，持久化失败保留新凭据 |
| 原始模型目录及能力 | 各平台目录快照 | 按平台/地区独立刷新；失败保留旧目录及更新时间 |
| 账号/密钥并发、粘性、预算预留 | storage 原子事务；gateway 协调 | 短临界区内检查和更新 |
| 冷却与健康观察 | storage 中的唯一运行视图 | 请求结束报告；需要跨重启保留的字段单独持久化 |
| 实际用量、历史价格、预算已用量 | 可回放的结算账本与检查点 | 请求结束结算，持久化后发布；失败保持内存事实并停止新请求 |
| 后台任务进度、结果未知标记 | jobs 任务记录 | 按状态机保存，恢复时先与上游核对 |
| 前端筛选与编辑草稿 | 当前页面 | 不作为服务端配置或任务结果 |

## 一次请求的执行

1. HTTP 层解析协议、认证身份、建立请求 ID 和总 deadline；只读取路由所需字段，保留原始请求字节。
2. `BeginRequest` 预留密钥请求预算及并发，建立 RequestState。失败时不调用上游。现有按 Token/USD 预算限同一密钥一个在途请求的语义保留。
3. `AcquireAttempt` 在当前配置版本下复核密钥、分组、公开名/原始型号权限、能力、账号状态和并发；选择“账号 + 实际型号”，取得幂等释放的租约。所需数据都来自内存。
4. accounts 读取所选账号的凭据；必要时按账号刷新并条件提交。网络调用不持有准入锁。
5. 从原始请求构造本次尝试的请求，只应用所选平台的型号和策略；调用相应 Adapter。
6. 协议转换和输出遵守现有有效响应判定、SSE 事件顺序和保真规则。记录首包及必要时间点，不逐 Token 打同步日志。
7. 失败按错误类型、剩余 deadline、剩余尝试预算及输出状态决定是否继续；每次尝试结束释放账号租约。
8. 请求结束累计各次真实尝试用量，写结算记录，发布已用预算，再释放请求级预算预留。任意错误路径都必须最终释放资源。

`RequestState` 明确持有 logicalModel、protocol、deadline、attempts、预算预留和输出状态；`AttemptState` 持有所选平台、账号、实际型号、价格版本、耗时和用量。关键执行状态由显式参数传递，context 用于取消、deadline、追踪和不可变身份信息，不扩展成隐式全局状态容器。

同一个非流式请求可以内部聚合流式输出，但不能因为客户端尚未收到字节，就重新开放已消费上游内容后的重放窗口。保留当前更严格的重试边界。

## 原子准入与锁

现有 [Store 选号](../../backend/internal/storage/pool.go) 已将权限复核、选择实际型号与增加 in-flight 放在同一把锁下。这是迁移约束。

M5 实际实现为 `gateway.Admission` 协调、`storage.Store` 唯一持有状态和事务。`scheduler.Select` 在 storage 原临界区内借用候选读取回调，只计算选择，不自己维护计数器。没有独立的运行快照缓存，配置发布、账号暂停/删除、密钥停用与新尝试准入仍使用同一把状态锁。取舍见 [ADR 0009](../adr/0009-runtime-storage-ownership.md)。

- 管理修改成功响应之后，新尝试必须看到新版本；已开始的尝试沿用其尝试快照，除非现有逻辑已要求取消。
- 请求可以提前做只读预检，但 AcquireAttempt 必须重新根据当前版本决定；旧候选列表不具有放行权限。
- `BeginRequest` 与 `AcquireAttempt` 可以是两个原子操作，后一步失败时归还前一步预留；不能先发请求再补并发计数。
- 释放按租约身份执行且幂等，删除账号后仍能释放，不通过重新查找账号是否存在决定是否归还。
- 共享模型名与原始型号调用共用账号租约；同一个账号不能因入口不同获得两份并发额度。
- 配置快照只读，更新时替换，避免每个请求做配置序列化、内容签名或磁盘读取。

M5 保留原锁域与 `saveMu -> journalMu -> mu` 顺序；旧 store 仅是类型别名/委托，生产代码不再引用。

## 配置提交与发布

严格分组/密钥/价格/模型策略事务的当前路径是：校验后持有原提交锁与状态锁 → 更新候选 → 写盘 → 失败则回滚 → 释放锁并返回。新准入看不到失败候选；更新完成前已有请求可以持有旧尝试快照。设置/启停等历史入口仍有保存失败仅记日志的语义，不能套用严格发布保证。

未来若需要减少管理落盘对准入的等待，目标路径才是：序列化管理变更 → 校验并编译候选快照 → 持久化提交 → 在准入临界区发布 → 返回成功。持久化失败时不发布候选；提交与发布之间不能让另一个管理更新越过它。

不可变快照的编译必须在落盘前完成。运行版本由成功提交的配置确定；崩溃发生在落盘与发布之间时，重启从已提交记录重新编译。如果进程无法发布已提交版本，应停止相关新请求并报告失败，不能返回“保存成功”后无限期使用旧权限。

磁盘写入移出请求准入锁属于未来的独立优化，本次没有实施。当前全量状态中还混有凭据和用量，因此此优化只在配置、凭据、账本有明确事务归属后实施；不能拿一份旧的全量快照覆盖期间刷新的 token 或结算数据。

预算修改/重置与请求结束结算也要与准入协调。保留“有在途计量请求时不允许重置该密钥预算”的现有语义。请求结算尚未发布时不能先释放预算预留，避免下一请求用旧余额放行。

## 模型语义

当前已实现：分组内带版本号的公开名映射多个平台来源；同一平台和地区每个公开名最多一个来源；账号池联合选择账号和实际型号；配置映射的分组只展示公开名；完整原始型号在权限内可直调。详见 [当前使用说明](../GROUP-MODELS.md)。

M6 分别实现以下概念，旧配置升级不自动开启新规则：

| 概念 | 定义 |
| --- | --- |
| 原始模型 | provider + scope + upstream ID 唯一定位来源；目录总数动态变化 |
| 公开模型绑定 | Group 内的版本化名称，如 `deepseek-4.1-flash`，引用多个已确认来源 |
| 默认映射预设 | 管理员编辑时可选择的建议，来源可检查和覆盖，保存后成为显式绑定 |
| 分组默认模型 | 请求没有 model 时采用的名称；不能接管拼错或未知 model |
| 默认客户端选择 | UI/客户端偏好，与服务端请求缺省规则区分 |
| 可见性与可调用性 | 隐藏不等于禁止，允许调用也不绕过分组和来源能力校验 |
| 调度策略 | 在允许来源中选号，不代表模型别名或等价性 |

统一名称不能把不同代际、能力或付费语义的模型默认为等价。显式配置允许管理员表达选择，但页面必须展示实际来源；未配置的来源不因同名自动加入。

映射预设以版本化数据维护在 catalog，由当前目录交叉验证。目录更新不静默重写管理员已保存的映射；来源下线保留配置并显示不可用。每次请求不查询上游目录。

空 model 未配置分组默认时保持当前规则。显式 model 优先；空值使用分组默认，再沿用全局缺省；无映射分组的既有 ForceModel 优先规则不变，映射与强制模型仍互斥。未知名称保持错误；已知公开名没有可用来源保持不可用错误。调用结果的公开名称与日志中的实际 provider/model 分别保留，费用按实际来源及当时价格计算。

联网搜索独立做能力路由。WorkBuddy 原生搜索与其他平台现有外部搜索配置，不因对话模型映射自动混用。

## 提示词策略

M6 保留三个平台独立配置，并增加公共默认与平台逐项覆盖：未显式覆盖则继承公共值；覆盖存在时按字段的明确类型合并，`false` 与“未设置”不能混淆。custom、passthrough、sanitize 和受拦截恢复分别定义，互相约束在保存时校验。

旧平台配置以 prompt_overrides:null 保留为独立策略，确保行为不变；管理员可逐项勾选继承。空对象全继承，false 与空字符串明确覆盖。实现与 schema 7 回退边界见 [ADR 0010](../adr/0010-product-model-and-prompt-policy.md)。暂不新增账号/模型/分组各一层提示词优先级。

只在选定平台后应用策略。切换账号或平台重新基于原始输入准备，不叠加上次平台注入。摘要等特殊请求继续走现有明确规则。清洗保持在现有 system/developer 边界，不递归删改用户、工具参数、工具返回或推理内容。

策略本身返回准备结果，恢复尝试由 Gateway 执行。重试次数和超时是否统一收口必须单独通过行为测试，不能在结构迁移中悄悄多一轮上游调用。

## 凭据与后台任务

凭据使用账号 ID、代际、provider、scope 和不透明内容表示。accounts 管刷新互斥，平台实现刷新协议，storage 实现条件提交。重新登录、删除、导入或另一轮刷新之后，旧代际结果不得覆盖新状态或复活账号。

上游已经轮转 token 而落盘失败时，保留新凭据在内存并报告未持久化状态，重试保存；不能因“事务回滚”恢复已失效 token。回退版本也必须使用最新凭据记录或兼容转换，而不是直接恢复旧备份。

后台任务维持账号内串行、跨账号有界并行，使用独立任务状态，不占用推理专属状态机。任务中的真实对话通过网关取得同一账号租约并记录用量；需要固定账号时仍受对应授权、并发和预算约束。

领取接口成功需保留上游确认和状态核验。操作中断或响应未知时记录未知状态，先核对再继续；不把重启后再次发送当成“恰好执行一次”。已有协议确认流程和活动前置条件继续有效。

## 协议、错误和结算

结构迁移保留 RawMessage/原始字节策略及现有协议桥。禁止把所有请求转换为封闭的强类型结构后再序列化，以免丢弃扩展字段或改变大整数。普通文本中的代码围栏和工具专用响应都是合法数据，不做全局修复。

平台错误至少保留上游状态、标准错误类别、是否可重试、账号或模型影响范围。HTTP 层负责映射到对应客户端协议。取消与 deadline 先于上游故障分类，不能把用户断开当成账号失败。

结算保留当前“账本追加并同步 → 更新累计用量 → 返回”的持久性语义及失败保护。序号/检查点防止重放重复计费；一次结算包含各尝试明细，汇总和明细不能各扣一次。价格快照留在历史记录，修改价格只影响新请求。

Token/USD 预算是按实际用量结算的软预算，保留一次在途请求仍可能超额的说明。未知用量不等于零；无价格不等于免费。搜索没有相应计费回执时保持现有限制。

普通诊断日志可以批量写；预算账本不能为了速度改为无恢复保证的异步丢弃。整个客户端响应与本地结算无法组成一个跨网络事务：已经输出的内容不能收回，结算失败必须进入可恢复故障状态。

## 多用户与多实例的进入条件

扩展管理员/用户身份前，定义资源归属、角色和审计主体；不能用现有账号分组冒充租户隔离。

允许多个实例前，需要替换准入和凭据协调实现，使账号并发、密钥预算、任务认领和刷新所有权具备跨实例的原子性与过期/代际保护。PostgreSQL 等持久化存储只能解决其中一部分问题；仅更换存储或增加 Redis 镜像不满足条件。

这些是后续阶段的验收条件，当前仍按单进程、单状态写入者设计。

## M7 单实例用户

普通用户身份、慢哈希和独立会话归 access；storage 在原锁中复核用户启用状态、当前分组、预算和实际选号。请求只携带不可变 user_id 用于结算；日志先写账本，再同时累计密钥及用户预算。删除密钥后仍按该身份结算。用户历史先按身份过滤再统计和脱敏，预算累计不受历史保留影响。没有额外权限缓存、推理密码哈希或逐帧记录。边界、容量和 schema 8 受限回退见 [ADR 0011](../adr/0011-single-instance-consumer-users.md)。
