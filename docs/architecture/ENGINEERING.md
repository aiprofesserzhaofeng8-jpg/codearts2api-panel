# 前端、API、构建与部署

状态：M4 前端工程已实施，见 [前端说明](../../frontend/README.md) 和 [M4 验收](../acceptance/STRUCTURE-M4-COMPLETE-2026-11-02.md)。下文未涉及的存储及扩展保证仍为后续目标。入口见 [总览](README.md)。

## 前端工程

采用 Vue 3、TypeScript、Vite、pnpm。实施时固定工具版本并提交 lockfile，不在设计阶段猜测具体补丁版本。前端可有构建依赖；Go 后端的标准库约束继续独立适用，见 [ADR 0007](../adr/0007-modular-monolith.md)。

Vue 的单文件组件支持把相关模板、逻辑和样式放在一起并预编译；Vite 提供开发与生产构建的后端集成机制。参考 [Vue 官方说明](https://vuejs.org/guide/scaling-up/sfc.html) 和 [Vite 官方说明](https://vite.dev/guide/backend-integration)。这里采用静态 SPA 产物嵌入 Go，生产不需要 Node 服务。

```text
frontend/src/
  app/                       入口、路由、会话初始化
  api/
    client.ts                认证失效、错误、取消的统一处理
    generated/               管理 API 类型，生成文件不可手改
  features/
    accounts/                列表、创建/编辑共用字段、登录流程
      providers/             平台专属表单和交互
    groups/                  成员、白名单、统一模型映射
    models/                  目录、测活、价格和能力展示
    keys/                    密钥与预算
    usage/                   用量查询
    settings/                设置页及分区表单
    jobs/                    成长任务状态、执行和反馈
    logs/                    运行日志与管理审计视图
  components/                Button、Dialog、Select、Table 等通用组件
  layouts/                   导航、页头、响应式布局
  styles/                    浅黄色主色、明暗主题变量
```

每个 feature 通过明确导出使用其他功能，避免跨目录直接引用页面内部状态。平台选择用注册式表单组件；普通字段与校验共用。暂不构建一个能描述所有平台流程的通用表单 DSL。

服务器数据、编辑草稿、展示偏好分开：

- 服务端数据由 API 返回；保存成功后更新，失败不伪装成成功。
- 编辑草稿留在表单，后台刷新不能覆盖用户未保存内容。
- 全局只持会话、主题和必要路由状态；每个平台登录进度不放在全局大对象里。
- 页面卸载取消自己的查询；取消查询不等于取消已启动的后台任务，任务状态要能重新查询。

先用现有 CSS 变量和布局完成等价迁移，再逐页组件化。过渡期旧页面与新页面各自独占挂载根、事件和轮询生命周期；不能让旧 console.js 与 Vue 同时控制同一 DOM。通过内部路由/构建选择迁移页面，不要求普通用户切换兼容开关。

现有管理 Cookie、明确允许的同源校验、登录失效处理与本机特例分别验证。开发代理覆盖实际使用的 `/admin`、`/v1`、`/health` 等路径；代理 Host/Origin 与 Cookie 行为需要测试。生产 CSP 不因 Vite 的开发热更新而放宽，生产模板预编译、资源同源提供。

## 管理 API 契约

管理接口继续使用现有路径、认证与错误格式。工程迁移不会自动改成 Sub2API 的 API 路径，也不将版本号目录变化传播给客户端。

目标 `api/admin.openapi.yaml` 记录真实管理接口；按功能逐步覆盖，生成前端类型，并通过 handler 契约测试检查实现。Schema-first 用于迁移后的管理契约维护，不通过字段名称推导运行账户的完整内部结构。

- 请求、返回 DTO 与内部持久化结构分开，默认响应不含完整凭据。
- 定义缺失、null、空数组的语义。特别是当前更新分组省略 `model_mappings` 表示保留、`[]` 表示清空；新表单必须保持兼容。
- 单位写入字段说明：时间戳、时区、Token、USD、积分不可混用。
- 并发编辑校验 revision 是未来可加的独立行为，旧客户端兼容方式需先定义，不在搬目录时强制新增。
- 后台任务 API 返回明确的运行状态、账号/任务结果及未知状态，不能只以 HTTP 200 判定领奖成功。

推理接口单独维护兼容矩阵：协议、流式、工具、thinking、搜索、已知不支持参数。管理 OpenAPI 生成器不用于对推理请求做封闭字段过滤；保留现有 RawMessage 和转换保真规则。

## 构建与发布

目标构建顺序：

1. 根据前端 lockfile 安装固定依赖，执行类型检查、组件测试、构建。
2. 生成 `frontend/dist`，受控复制到 `backend/internal/webui/dist`；只复制本次构建的静态文件。
3. 在 `backend` 编译 `cmd/panel` 并嵌入资源；产物携带后端版本和前端构建标识。
4. 包装平台二进制或 Docker 镜像，执行实际产物的健康、登录和静态资源冒烟。

源代码以 `frontend/src` 为准，两个 dist 都是生成产物，不手工维护、不提交。缺失前端产物时，标准发布构建应失败；仅用于测试的 API-only 构建需要明确标识，不能默默发布空页面。

保持一个 Go 模块，迁入 `backend` 后模块名仍为 `codearts2api`，所以已有 `codearts2api/internal/...` 导入前缀不增加 `backend`。只有确实移动包的阶段才调整包路径。

`go:embed` 不能跨越父目录；因此复制产物至 Go 包内。版本注入仍需核对 `main.version` 实际所在入口，避免移动 main 后发布显示错误版本。

根 Makefile 的当前命令：

| 命令 | 职责 |
| --- | --- |
| `make dev` | 启动本机前端和后端，退出时正确清理子进程 |
| `make build` | 前端 + 后端的可发布产物 |
| `make check` | 后端、前端、协议、依赖边界的常规离线检查 |
| `make race` | 后端并发验证 |
| `make e2e` | 隔离测试数据的浏览器/全栈验收 |
| `make bench` | 稳定的路由、流式处理、结算性能基准 |
| `make docker` | 统一镜像构建 |

真实上游验收继续使用明确的单独命令，不放进默认 `check` 或常规 CI，以免产生不可控积分消耗。上述命令已接通实际脚本；直接执行 Go 前先运行 `make frontend`。

## 部署和运行数据

根 `Dockerfile` 是唯一基础镜像构建入口，根 `docker-compose.yml` 是唯一基础 Compose 配置。`deploy/` 放 systemd、HTTPS 反代和环境覆盖示例，所有路径以同一产物和运行目录约定为准，不维护重复 Dockerfile。

默认发布单二进制/单应用容器，保留本机启动、systemd、Docker、SSH 隧道与 HTTPS 反代方式。`build.sh` / `start.sh` 保留为薄入口，路径以脚本位置或显式数据参数确定，不能因新 cwd 在另一处创建空账号库。

运行目录与源码、构建产物分离。账号/凭据、访问恢复文件、用量账本和任务状态按现有保护要求保存。升级记录二进制版本、状态格式版本和数据目录；完成健康验证后才切换服务入口。

正常关闭停止新任务和新请求，等待现有请求到有界期限，结算已知用量并保存最新凭据，最后退出。后台模型同步和令牌刷新使用统一生命周期管理，避免关机后仍覆盖状态。

指标分别覆盖存活、就绪、在途、准入拒绝、上游失败、首包/总耗时、账本健康和任务结果。不把高基数完整密钥、会话或错误正文当成指标标签；请求日志继续使用请求 ID 关联实际型号。

## 支持文件

| 位置 | 维护规则 |
| --- | --- |
| `docs/architecture` | 目标及已实施状态，阶段完成时更新 |
| `docs/adr` | 重要取舍和替代关系，沿用现有编号 |
| `docs/acceptance` | 实际证据、环境、版本、限制，不能用设计预期代替实测 |
| `configs` | 最小示例及配置语义；不新增另一份默认业务配置真相 |
| `scripts` | 构建和运维自动化入口；现有 tools 逐项归并，避免复制后双维护 |
| `tests` | 跨进程验收和脱敏样本；Go 单测继续放源码旁，前端组件测试靠近组件 |
| `AGENTS.md` | 实际目录、开发命令、模块边界、测试要求、禁止泄露凭据等项目约定 |
| `skills` | 经常重复且已有脚本支撑的开发/验收流程，成熟一个加入一个 |
| `CONTRIBUTING.md` | 人工开发者入口，链接实际规范，不复制一份相同命令表 |

`AGENTS.md` 和 skill 是开发辅助，不是运行时模块，也不承载产品提示词、用户账号配置或任务状态。不会为了“齐全”加入没有实际用途的技能文件。

## CI 与维护标准

保留 Linux/Windows Go 构建、单测、race、vet，保持 CodeArts 的 Windows 实现可编译和验证。前端增加类型、组件、生产构建和关键页面 e2e。检查生成 API 类型是否同步、静态资源是否完整、禁止依赖是否出现。

Docker/二进制冒烟验证构建后的真实产物。运行测试使用固定假上游和临时数据，凭据不写入 CI。升级依赖与业务重构分开提交，来源 LICENSE 随文件移动保留。

行数是拆分提示，不是质量指标：页面超过一个完整业务职责时先拆组件/组合函数；通用逻辑出现第二份实现时评估共享。避免依赖反射、全局注册副作用和泛型 CRUD 框架掩盖实际调用关系。
