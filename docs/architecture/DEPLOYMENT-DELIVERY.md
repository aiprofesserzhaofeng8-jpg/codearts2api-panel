# 安装、更新发现与交付收尾

状态：功能、隔离验收和本机迁移已完成；正式发布待工作流结果。承接 D1～D3，见 [交付验收](../acceptance/DEPLOYMENT-DELIVERY-2026-11-02.md)。

## 目标

新机器可下载校验后安装，管理员可查看实际版本及稳定版更新，已有源码实例可迁入受管目录并保留完整数据。安装、备份、恢复、升级仍由 panelctl.py 统一处理。

## 实施顺序

1. 增加 deploy/install.sh 轻量入口和发布获取模块：固定本项目 GitHub 来源，选择稳定版本/指定版本，识别 Linux amd64/arm64，下载同一 Release 的程序和 SHA256SUMS，校验后委托本地 panelctl。查询失败、缺附件、摘要不符不得停机。支持仅下载及离线安装；不猜测最新版本，不将预览版自动视为稳定升级。
2. 增加管理员只读版本接口和配置页版本卡片：当前版本取自运行二进制，显式检查 GitHub 稳定版。未知开发版本、缺发布资产、网络失败分别提示；显示发布说明链接。短缓存、请求超时和响应大小有界；不接收用户传入的下载地址。普通用户无权访问，网页不获得进程升级权限。
3. 增加源码实例迁移命令：校验候选、识别旧服务及数据目录，停止并确认旧进程结束，完整备份后恢复到新目录。保留原数据；新服务启动成功后禁用旧服务，禁止两份实例同时写同一状态。失败保留诊断和最新数据，禁止自动回写旧备份。演练包含已有管理员与账本。
4. 补齐发布附件和文档，构建真实候选包，完成从下载、校验、安装、登录到升级的隔离验收，再切换本机实例。公网发布以真实 GitHub 工作流和 Release 附件为准，不能用本地测试包代替发布证据。

## 验收

- 下载：稳定版本、指定版本、缺失/重复附件、恶意 URL、摘要篡改、错误架构、网络失败；无失败路径执行未校验工具或停止旧服务。
- API：管理员成功，未登录/普通用户拒绝；当前版、较新/较旧版、开发版、无资产、超时、缓存及并发行为。
- 页面：显示真实版本；按钮加载及错误可见；退出后不更新已卸载页面；不因检查更新标记配置为未保存。
- 运维：真实用户级 systemd 隔离安装、正常升级、迁移；原密码、数据和账本保留；旧服务停止且禁用；失败不覆盖新数据。
- 回归：make check、相关 race 测试、部署测试与发布包验证。记录实际本机版本、发布状态及未验证的公网/ARM 范围。

## 范围限制

单实例 Linux。无网页执行升级、无跨 schema 自动迁移/降级、无自动数据回滚、无多副本或新增支付功能。运行态数据、备份与安装凭证不进入 Git/公开产物。
