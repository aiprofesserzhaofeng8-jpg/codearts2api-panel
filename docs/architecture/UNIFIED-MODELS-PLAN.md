# 全局统一模型实施计划

日期：2026-11-05。状态：U1–U6 已完成（隔离验收与本地包）；后续已完成 WorkBuddy/Trae 同一公开名的首批真实验证，未发布/部署。证据见 [U1 验收记录](../acceptance/UNIFIED-MODELS-U1-2026-11-05.md)、[U2 验收记录](../acceptance/UNIFIED-MODELS-U2-2026-11-05.md)、[U3 验收记录](../acceptance/UNIFIED-MODELS-U3-2026-11-05.md)、[U4 验收记录](../acceptance/UNIFIED-MODELS-U4-2026-11-05.md)、[U5 验收记录](../acceptance/UNIFIED-MODELS-U5-2026-11-05.md)、[U6 验收记录](../acceptance/UNIFIED-MODELS-U6-2026-11-05.md) 和 [真实验证范围](../acceptance/UNIFIED-MODELS-LIVE-2026-11-05.md)。

## 1. 最终目标

管理员在模型页面定义一次带版本号的公开名称，并绑定多个已确认属于同一型号的上游来源。客户端用同一个地址、密钥和公开名称调用，网关在权限范围内选取对应来源和账号。

以 `deepseek-4.1-flash` 为例：WorkBuddy、Trae 和 CodeArts 的真实对应型号都可以成为来源；前提是当前目录存在该型号、对应关系已确认。示例不是对现有账号可用性的承诺。

完成本计划必须同时达到以下目标：

| 编号 | 具体目标 | 可观察的验收结果 |
| --- | --- | --- |
| G1 | 一个公开名称绑定至少两个平台来源 | 同名请求能分别由两个假上游处理，收到各自正确的原始型号 |
| G2 | 不分组密钥可以调用全局统一模型 | 无须创建分组映射，列表、推荐参数和请求均识别该名称 |
| G3 | 分组权限不因全局化而扩大 | 原账号范围、来源限制、白名单、visible/callable 和预算测试全部通过 |
| G4 | 同型号来源间有界切换 | 注入可重试错误后成功切换；达到现有总次数/期限后停止，输出提交后不重放 |
| G5 | 客户端看到一致的模型定义 | Chat Completions、Responses、Messages、模型列表、client-profile 使用同一名称解析 |
| G6 | 旧状态可迁移且错误可解释 | 无冲突迁移幂等、失败无半写；404/403/422/503/上游错误能区分 |
| G7 | 交付状态可核验 | 独立记录代码测试、真实上游验证、安装包验收和实际部署结果 |

## 4. 目标结构与规则

### 4.1 数据归属

| 对象 | 目标字段/职责 | 归属 |
| --- | --- | --- |
| 统一模型 | 稳定 ID、公开名称、启用状态、来源绑定、配置 revision | 纯配置类型放 `config`，管理协调与解析放 `catalog` |
| 来源绑定 | 原始目录 ID、启用状态；平台/地区由唯一目录解析 | 统一模型配置；不复制原始目录和凭据 |
| 原始模型 | 平台、地区、原始 ID、上游能力元数据 | 现有 `registry` |
| 分组授权 | 统一模型 ID、可见/可调用、允许来源 ID、账号范围、默认模型/客户端偏好 | 现有 `access` |
| 客户端策略 | 上下文、输出、压缩参数及其依据 | 现有 `config.ModelPolicy`；按统一模型引用，不复制第二份 |
| 账号与运行状态 | 凭据、额度、健康、租约、预算和账本 | 现有 `accounts` / `storage` |

具体 JSON 字段及端点已在 [契约 v1](UNIFIED-MODELS-CONTRACT.md) 定稿，架构依据见 [ADR 0018](../adr/0018-global-unified-models.md)，迁移和权限真值表见 [迁移与验收矩阵](UNIFIED-MODELS-MIGRATION.md)。将纯配置类型放在现有 `config` 中，避免 `access` 导入其他业务模块；`catalog` 通过窄接口读取/提交，不能直接导入 `storage`。`app` 装配现有实例。

```text
公开名称 -> catalog 解析候选来源
         -> storage 原子复核权限、实际型号和账号并占位
            （内部复用 scheduler 纯选择算法）
         -> gateway 执行现有有限重试流程
         -> 平台适配器接收原始型号
```

### 4.2 固定的产品约束

1. 统一名称带版本号，不含空白、控制字符或斜线；重复和大小写冲突沿用严格校验。原始 ID 保持平台原样，不能全局转小写。
2. 第一版沿用每个统一模型 1–16 个来源、每平台/地区一个原始型号的限制。不同账号由账号池提供，无须重复建来源。
3. 来源必须直接引用原始型号，不允许“统一名称 -> 统一名称”的链式映射或循环。目录刷新不能覆盖人工确认的绑定。
4. 公开名、旧别名、原始短名发生歧义时，保存/迁移报告冲突，禁止悄悄改变旧名称指向。旧完整平台 ID 继续受同样的权限检查。
5. 分组的来源范围区分“跟随全部来源”与“显式列表”；显式空列表表示不允许任何来源。迁移后的旧分组一律固定为原允许来源列表。
6. 新增全局来源不会扩大固定列表分组的权限。管理员选择跟随全部来源时，界面明确说明新来源会加入该组候选。
7. `visible` 与 `callable` 独立；列表隐藏不是调用权限。请求默认值与客户端偏好保持不同语义，显式模型不得被客户端偏好替换。
8. 管理员设置上下文不能制造上游能力；未知图片/工具/上下文能力保持未知。只有支持请求能力的来源才能执行，图片和工具参数不能静默丢弃。
9. 统一模型引用的策略必须经过适用来源校验；没有明确策略时，来源建议完整才合并为保守公共值，否则 client-profile 返回 422。健康状态短暂变化不得使推荐上下文忽大忽小。
10. 列表表达授权后的模型目录，不承诺实时可用。管理界面分别展示“已配置来源”“当前可调度来源”“最近测试结果及时间”，不在列表查询时执行付费探测。
11. 对外响应中的模型标识使用公开名称；管理日志保留请求名称、实际平台/型号和尝试结果，不能泄露凭据。历史计费和账本语义不重新计算。

## 5. 实施阶段

U1 -> U2 -> U3 -> U4 -> U5 -> U6。每阶段完成需附变更文件、检查命令与结果；不得以“代码已写”代替验收。

### U1：冻结契约与基线

**目标：所有歧义在写业务代码前有唯一处理规则。**

- 核对原始目录、旧分组映射、别名、默认/强制模型、模型策略、定价和原子准入的引用关系。
- 写 ADR，固定数据字段、管理 API、来源限制的缺省/空值、名称冲突、配置 revision 和错误契约。
- 列出旧状态迁移用例与权限真值表，包含无映射、无账号、同名不同来源、裸名称碰撞、visible/callable 不一致。
- 记录本轮实际工作树与依赖基线；保留启动器现有未提交修改，不混入本计划提交。

**完成标准：** ADR、接口草案、迁移清单和验收矩阵齐全；每项规则都有明确输入与预期输出，没有“实施时再猜”的名称解析顺序。

### U2：全局定义、原子保存与迁移

**目标：统一模型只保存一份，升级不丢数据、不扩大权限。**

- 在 `config` 增加纯值类型/校验；`catalog` 增加管理协调；`storage` 增加读取与严格原子提交，复用已有锁和保存机制。
- 以当前 schema 10 为基线规划 schema 11；实施时若已有新 schema，占用下一个版本，不能复用旧版本号解释新权限。
- 提供迁移预检查：相同公开名、相同来源集合可以合并；同名不同来源、与旧裸名称/别名冲突必须显式解决，不能自动取并集。
- 为原分组保存固定来源限制，迁移原白名单、默认模型、客户端偏好、独立可见/调用规则和策略引用。
- 新模型 CRUD 支持 revision 冲突检测；删除被引用模型返回冲突，不自动修改用户/密钥的授权和默认值。
- 升级工具在切换版本前检查迁移；冲突阻止切换并给出处理报告，原服务继续使用原数据。未解决时不写半迁移状态。

**完成标准：** 新建/修改/重启往返一致；重复迁移结果不变；权限矩阵前后一致；磁盘写失败及冲突不发布新配置；凭据、钱包、预算和账本夹具保持原值；旧程序拒绝新 schema。

### U3：统一解析、准入和同型号切换

**目标：一个名称真正贯通多个平台，且不会越权或扩大重试。**

- 扩展 `catalog.Routing`：全局定义与分组限制共同生成一次请求的 `ModelPlan`，不复制 Registry、不缓存权限、不在解析中访问上游。
- 扩展 `storage.AcquireMappedAccount`：锁内复核最新定义/revision、来源授权、账号范围、健康和并发，再选择原始型号并占位。
- 复用 `gateway.RunAccountRetry` 的总期限、总次数和租约释放；不增加外层循环。公开名称、原始型号及所选账号沿现有请求上下文传递。
- 配置在解析后变更时先复核最新权限；仍有权但定义/策略 revision 改变返回 409 `model_configuration_changed`，本轮不另开重解析/重试循环；组权限变化只能收缩旧候选。
- 普通同型号来源切换保留现有错误分类；上游 403 不自动等价于网关分组拒绝。网络瞬断不永久停用账号，客户端取消及时释放租约。

**完成标准：** 两平台假上游均收到正确型号；注入可重试故障可切换；分组外来源零命中；配置并发修改、并发上限和预算测试通过；SSE 输出提交后不重放；同一逻辑请求结算与租约释放不重复。

### U4：列表、推荐参数与 HTTP 契约

**目标：同一密钥、同一名称，在所有入口有一致含义。**

- `/v1/models` 以公开名去重；完成迁移的映射来源默认不再重复推荐，未映射模型沿用原目录。完整原始 ID 的兼容调用仍有独立权限校验。
- `/v1/client-profile` 使用同一模型解析与策略计算；显式请求名称可追踪，不默认改用另一模型，缺失推荐参数不阻止其他本来有效的原始 API 请求。
- 对齐 `/v1/chat/completions`、`/v1/responses`、`/v1/messages`，包括非流式和 SSE 响应中的公开模型名。
- 管理接口沿用统一角色认证、写入校验及审计，更新 `api/admin.openapi.yaml` 与生成类型。
- 错误分类按契约输出：未知名称 404、无权限 403、缺少客户端推荐参数 422、已知模型无可调度来源 503；保留准入限额 429、能力/参数 400 和平台执行错误的独立分类。

**完成标准：** 同一夹具下列表/profile/三协议解析一致；非流式与 SSE 共 6 类请求验证通过；普通用户访问管理端点失败；错误包含可定位原因且不暴露账号凭据。

### U5：模型页与分组页

**目标：管理员在一处配置模型，再给分组分配权限。**

- 在现有 `features/models` 添加统一模型列表与编辑：版本化名称、实际目录来源选择、启停、客户端策略入口和来源测试结果。
- 已绑定但暂时不在目录中的来源保留并标记不可解析，不能因刷新失败丢失配置；新绑定只能从真实目录选择。
- `features/groups` 改为选择统一模型和账号，来源限制放在展开项；保留默认模型/客户端偏好及独立可见/调用控制。
- 旧映射编辑入口在迁移完成后撤下，避免两处同时编辑同一关系；提供迁移报告和冲突定位说明。
- 测试复用现有显式模型探测，展示平台、原始 ID、成功/失败与时间，不能把一次文本成功宣称为图片/工具能力验证。

**完成标准：** 浏览器完成创建统一模型、绑定两个来源、授权分组、设置客户端偏好、禁用来源、刷新后保留配置的完整流程；覆盖窄屏与桌面、空目录、权限拒绝和保存冲突；生成类型和页面检查通过。

### U6：综合验收与可安装交付

**目标：证明统一模型可用、升级可维护，并明确真实上游覆盖范围。**

- 用隔离状态和两个假平台跑完整三协议、失败切换、并发、取消、权限变更及迁移回归。
- 用既有 Pi 启动器连接隔离网关，验证公开名的 profile 获取、短文本与一次工具调用闭环；此测试不改变用户当前客户端配置。
- 构建安装包，在临时实例验证 schema 升级、重启后映射、缺参数诊断、旧版本拒绝与失败恢复操作。
- 检查列表/解析热路径没有新增网络请求、凭据解析、逐分片写状态或第二层重试；用现有 benchmark 比较同等候选规模，记录额外开销及原因。
- 实际上游验收只在确有两个同型号来源且有测试额度时进行；一次来源成功不能代表跨平台通过。没有合适账号时明确标记“真实跨平台未验证”，不伪造映射。
- 输出验收记录、管理员使用说明和升级说明。记录包版本、提交、schema、运行实例及验证时间；发布和实际部署是独立状态。

**完成标准：** G1–G6 自动化证据齐全、所需检查通过、隔离升级可运行；G7 报告明确指出真实上游/发布/部署是否完成。存在已知越权、迁移丢失、请求重放或结算缺陷时不得验收。

## 6. 必测矩阵

| 编号 | 场景 | 预期 |
| --- | --- | --- |
| T01 | 同名绑定 A/B 两平台 | 均可选中且使用各自原始型号，响应保持公开名 |
| T02 | 不分组密钥 | 能识别全局模型，实际可调用仍受启停、额度及账号可用性约束 |
| T03 | 分组仅允许 A，B 正常 | 不调用 B；A 不可用时明确失败 |
| T04 | 全局新增 C，旧组固定 A/B | 旧组无法使用 C；显式选择跟随全部的组可按权限使用 |
| T05 | visible=false/callable=true 及反向配置 | 隐藏不等于禁止；显示不等于允许 |
| T06 | 同名不同来源/别名或裸名称冲突 | 预检查报告并拒绝自动提交，不改变旧路由 |
| T07 | 显式空来源范围 | 拒绝调用，不解释为全部来源 |
| T08 | 所有来源离线、冷却或没有账号 | 无可用来源诊断，不要求用户登录错误的平台 |
| T09 | 图片/工具请求只适配部分来源 | 只选有明确能力的来源；无匹配时拒绝，不丢弃内容 |
| T10 | 来源缺少上下文资料或策略矛盾 | profile 明确 422 或保存拒绝，不猜测 1M 参数 |
| T11 | 三协议流式/非流式 | 同名解析一致，工具参数与大整数不因映射损坏 |
| T12 | 解析后禁用来源、移除分组账号或修改授权 | 原子准入/下一次重试复核最新权限，无过期计划越权 |
| T13 | 首段前故障、首段后故障、取消、预算不足 | 有界切换或终止，输出提交后不重放，释放/结算幂等 |
| T14 | 保存失败、进程中断、迁移重跑、旧程序读取 | 无半写、可诊断恢复、幂等、不忽略新权限 |
| T15 | 旧完整型号与默认/强制模型配置 | 兼容行为明确且不绕权限；冲突不能静默改路由 |

## 7. 验证命令与运行约束

## 8. 备份、失败与恢复

- 实际迁移前按现有部署工具停写，完整备份数据目录和账本；备份是恢复材料，不是继续服务后的自动降级手段。
- 写入 schema 11 后旧版本拒绝读取。恢复旧状态会丢失之后的凭据轮转、权限和账本变化，因此运行后优先前向修复，禁止直接覆盖旧快照。
- 只有尚未接受流量、未发生凭据刷新/账本变化的隔离失败升级，才能按已验证工具恢复升级前整体快照；其他情况先导出最新状态并制定兼容恢复。
- 源码构建、安装包验收和本机/远程服务更新分别记录。实际部署前核对 PID、二进制、端口、状态目录，不根据仓库版本推定运行版本。
