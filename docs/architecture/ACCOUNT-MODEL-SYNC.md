# 按账号同步上游模型：实施与验收

同一地区的两个 Qoder 账号可能得到不同的模型清单。管理员需要知道“这个账号列出了什么、与上次有什么变化”，而不是再刷新一次整个平台。第一版交付点是**管理员可以同步并查看账号清单**；不因此增加或删除任何用户的模型权限。

## 当前基线

[全局刷新](../../backend/internal/catalog/refresh.go)按平台和区域选取成功的结果，供平台目录使用。[Qoder 适配器](../../backend/internal/upstream/qoder/models.go)已支持用账号凭据查询目录，并过滤禁用、不支持的来源。直接复用其结果，保留原始 ID；显示名、积分倍率以及统一模型别名都不能作为比较键。

参考 Sub2API 的[账号模型选择器](https://github.com/Wei-Shaw/sub2api/blob/main/frontend/src/components/account/ModelWhitelistSelector.vue)：同步入口放在账号操作里。本项目已用分组和统一模型管理授权，因此不把同步结果直接写进白名单。

## 1. 读取指定账号，比较型号清单（已实现，内部服务）

[实现](../../backend/internal/catalog/account_discovery.go)接受账号 ID 和凭据感知的模型读取操作。仅对已启用的 Qoder 账号调用该操作；失败直接返回，不从池中换另一个账号。返回账号、平台、区域、成功时间，以及模型 ID、显示名、上游报告的上下文和最大输出。未报告的数值不据名称推断。

第一次成功的结果作为基线。后续比较同一账号、平台和区域的两次成功结果，按原始 ID 列出新增、此次未返回和仍在列出的型号。显示名变化不会造成虚假的新增或消失。“此次未返回”只描述两次查询的差异，不等于永久下架。接口成功并明确返回空清单与网络或解析失败分别处理。

[隔离性测试](../../backend/internal/catalog/account_discovery_test.go)覆盖同区不同账号、失败不换号、错误账号不查询、按 ID 比较及平台目录不变。在 backend/ 下运行：
```sh
go test ./internal/catalog ./internal/upstream/qoder
```

## 2. 保存最近成功快照，接入管理员接口（已实现）

由 storage 随账号维护最近一次成功结果。读取快照不访问上游；显式同步时才通过现有 providerCredentials 和 adapter.Models 查询，不接受浏览器传入的凭据或任意上游地址。按账号串行同步；网络调用不占用 Store 写锁。提交前检查账号仍存在且身份、区域未变，防止删除或换绑过程中回写旧结果。账号删除同时清理快照。

管理员 GET 查看已有快照，POST 发起同步；沿用 withAdminAuth，在 OpenAPI 中定义请求、成功结果及错误，更新前端类型。成功后原子写入并返回与上次成功结果的差异；失败返回原因和可查看的旧快照，不更新成功时间。存储设计需明确旧状态加载、备份恢复和升级兼容性。

验收：重启后能读回清单；超时后成功时间和旧清单不变；普通用户不能调用；同步中删除账号不会重新创建记录。测试用本地模拟上游，不发送推理请求。

## 3. 在账号池交付查看和同步入口（已实现）

Qoder 账号的“更多”提供“同步上游模型”。结果面板显示上次成功时间、原始型号及差异；首次显示“首次同步”和目录总数，不把首次结果误称为平台新发布。失败时保留旧清单并注明本次失败。其他平台按实际发现能力开放；只有内置列表的来源标为“内置目录”。

验收：同区 A 返回 X、Y，B 只返回 Y，管理员分别看到两份结果；B 同步失败不影响 A。页面刷新只读快照，不自动重拉、测活或消耗推理额度。新增来源可对策略允许的密钥可见；分组授权不被同步改写。

### 已交付接口与迁移行为

管理员调用 `GET /admin/api/accounts/models?id=<账号 ID>` 读取上次成功结果（未同步时 snapshot 为 null）；同一路径 POST 同步，不传凭据。失败返回非 2xx，GET 仍可读取上一次成功结果。不同账号的同步独立；同一账号按顺序提交。前端在「账号池 → Qoder → 更多 → 同步上游模型」打开快照，点击弹窗内的同步按钮才发起 POST。

schema 保持 11。快照持久化在对应账号记录的可选 `model_snapshot` 内，随状态备份、恢复和删除。升级时无需迁移；旧版可读取账号，但重新保存后可能丢弃该可重建快照。该字段不携带凭据、分组及路由配置。

已通过本地模拟上游的 HTTP 测试（首次、差异、失败保留、重新打开状态文件、删除后的过期写入），并使用浏览器验证入口、差异展开和失败展示。没有用真实账号做测活或推理。

## 4. 追加可调用来源（已实现）

只读阶段的“目录不完整不能作为拒绝依据”继续适用；成功同步的新 ID 现在可作为正面路由来源。实现和验收见[同步后调用新型号](ACCOUNT-MODEL-PUBLICATION.md)。此规则取代原先“快照仅供查看”的限制；旧快照需重新同步。Qoder 和 ChatGPT（包括 Codex 授权）支持。
