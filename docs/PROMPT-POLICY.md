# 提示词管理

需要保留客户端规则、只补充一句要求时，打开侧边栏「提示词」，选择应用平台，
将处理方式设为「追加」，填写文本并保存。不要为这个用途选择「替换」。

## 三种处理方式

| 模式 | 行为 | 文本留空 |
|---|---|---|
| 透传 `passthrough` | 保留客户端系统指令；保存的自定义文本不用于正常请求 | 不增加内容 |
| 追加 `append` | 保留原指令，补充配置的要求 | 不增加内容，不启用内置提示词 |
| 替换 `custom` | 用配置文本替换客户端系统指令 | 使用内置工程助手提示词 |

Chat 在现有 system/developer 消息之后插入补充的 system 消息；Responses
在 instructions 后补充文本，保留 input 中的开发者指令；Messages 保留现有
system 文本块及缓存元数据，再增加一个文本块。工具定义、参数、大整数、签名
与普通对话不由提示词功能改写。该功能不加载客户端工具或执行 Hook 脚本。

## 公共默认值和平台覆盖

公共值是默认设置。平台的模式、文本、拦截恢复、清洗四项分别决定是否继承，
未继承的项目保持独立。现有配置的继承关系、空文本与明确关闭值均保留，移动
页面不会自动把旧替换模式改成追加，也不会自动启用新模式。

CodeArts、WorkBuddy、Trae、Qoder、Kiro、ChatGPT/Codex、Claude、TeleAgent
可在页面单独配置；其余已接入推理平台使用公共默认值。此版本沿用平台作用域，
没有新增按分组绑定或提示词包安装。请求切换平台时，采用所选平台的有效配置。

「配置」页继续管理搜索、调度等运行参数，提示词相关内容只有独立页面一个编辑入口。
页面切换、后台刷新不会覆盖未保存草稿；重新读取会提示丢弃草稿。保存只更新
提示词字段，磁盘写入失败回滚；并发编辑冲突返回 409，草稿保留供核对。

## 预览和兼容性

「注入预览」可选择三种协议，使用当前编辑内容处理示例 JSON，展示原始与处理后
的请求。它复用实际纯处理函数，不发起上游调用、不保存配置；JSON 字符串传递
保留大整数。预览不模拟上游平台自身的参数规范化或真实模型回答。

兼容性设置收在折叠区，默认值和既有配置保持：

- 拦截恢复只在透传模式、明确内容策略拦截、未消费任何分片时，最多换中性提示词
  重试一次；追加和替换模式不触发该恢复。
- 清洗仅针对系统指令中的已知客户端模板，不是通用脱敏或内容审核。
- 已识别的摘要请求继续豁免系统指令替换/追加及中性提示词恢复。
- 每次尝试从原请求准备，不往已处理请求上叠加；不会将追加内容写回客户端历史。

## 管理接口

- `GET /admin/api/prompts`：读取公共值及平台提示词配置。
- `POST /admin/api/prompts`：提交 `expected`（读取时的快照）及 `configuration`
  （编辑后的配置）；只比较提示词字段，运行配置变化不构成冲突。
- `POST /admin/api/prompts/preview`：传入 `protocol`、`mode`、`text`、`sanitize`
  及 `request_json` 字符串；返回 `request_json` 保留原始 JSON 数值精度。

这些接口仅允许管理员使用。原 `/admin/api/settings` 的提示词字段继续兼容；
新运行设置页不再提交这些字段。`prompt_overrides:null` 仍表示旧独立配置，
对象中的 null/缺省字段继承公共值，false/空字符串表示明确覆盖。

状态文件结构保持 schema 11。启用新增 append 模式后，不应直接回退到不识别
该模式的旧程序；先在新版本明确选择所需的兼容模式，不能靠删配置回退。
