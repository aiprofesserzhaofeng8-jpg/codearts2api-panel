# 账号管理审计修复（2026-11-12）

## 范围与实现

1. **管理员变更持久化**：启停、暂停/恢复、清错（包括模型冷却）在 storage 原有 saveMu → mu 锁内保存；失败恢复在线字段并向接口返回错误。批量导入整批提交，失败不失效凭据缓存；去重仍保留原账号 ID 和调度设置。缺失账号的清错返回 404。原生凭据重导入保存失败也明确返回错误，但不回滚已轮转的新凭据。
2. **构建来源**：Linux/Windows 打包均重新构建当前前端，随后构建同一工作区后端；manifest 新增 source.commit/dirty/sha256/channel。正式版本拒绝未提交修改，本地验证使用 `vX.Y.Z-local.YYYYMMDDHHMMSS`。本轮候选包含当前完整工作区，不再采用旧 HEAD 加部分 UI 的拼装方式。源码提交号与 dirty=true 必须一起解释，不能把本地包说成已发布正式版本。
3. **额度查询负载**：默认刷新和翻页只请求当前可见页 ID；一分钟缓存抑制反复翻页查询，手动刷新按钮强制刷新本页。接口支持重复 id，最多 100 个，去重且维持顺序；空/不存在的显式 ID 拒绝，绝不退化为全量查询。最多四个 worker，取消后不继续发起剩余上游请求。旧接口无 ID 的全量调用保留兼容。
4. **数据时效**：恢复上游提供的额度更新时间显示，没有时间戳时不伪造。查询失败不等于额度耗尽。
5. **导出说明**：非原生账号导出没有提供续期字段时显示“未知”，不能推断为“否”；提示文案不再承诺每份导出都含 refresh_token。
6. **手机端操作**：增加独立本页全选入口，与桌面复选框共用选中、部分选中、禁用状态；不跨页选择。
7. **升级顺序**：本地候选低于同基号正式版，同基号较新的本地候选可升级；仍拒绝降级、重复安装、未经支持的 schema 迁移。后台检查更新识别本地候选与同基号正式版的升级关系。

## 验证方式

- `make check`：前端类型/单测、Go vet/单测、架构/API 合同、部署测试。
- `go test -race`：账号操作保存故障、批量额度有界并发/取消、显式 ID 查询。
- 浏览器隔离验收：accounts-table-smoke、quota-smoke、teleagent-rewards-smoke、account-create-smoke、frontend-smoke。新增 43 账号分页额度范围、额度时间戳可见、导出未知状态及手机全选断言。
- 部署测试覆盖 dirty 正式包拒绝、源码元信息、本地候选到同基号正式版，以及原有备份/失败恢复边界。
- 测试使用临时状态和假上游；未执行真实推理、领奖、账号刷新或写入线上 state.json。

## 保留的边界

账号基本列表仍通过 `/admin/api/state` 全量快照加载，分页仍在前端；本轮消除的是每次浏览触发全部上游额度请求，不宣称已经实现服务端列表分页。大量账号时快照传输和过滤仍可能需要后续分页设计。

既有本地 v0.4.7–v0.4.10 不修改安装记录或伪造降级。下一本地候选使用 v0.4.11-local.*，之后可升级到 v0.4.11 正式版；GitHub 尚未发布的版本仍不能用远程 upgrade 获得。

本地源码、验证包、系统服务与 GitHub 发布是四个状态。升级系统服务要通过新版 panelctl 校验、停机备份和健康检查，保留旧程序和最新数据，不手动覆盖凭据/账本。本记录不表示已部署或发布。
