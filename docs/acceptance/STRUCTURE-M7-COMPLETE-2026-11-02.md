# M7 完整验收：单实例多用户

日期：2026-11-02。状态：完成。版本 `0.3.0-structure-m7`，schema 8；比较基线 `c837981`（M6），定版标签 `milestone/structure-m7-complete-20261102`。

用户选择方案 1：一个管理员管理多个普通用户，共享已有平台账号池。没有增加数据库、多副本或用户自管平台凭据。M1–M7 当前约定范围均已完成，多实例另行设计。

## 实现与边界

- 管理员侧新增「用户管理」，设置用户密码、一个强制分组、启停和共享预算。普通 `/user` 控制台只操作本人的密钥、用量和模型；无公开注册，不向用户开放平台凭据、奖励或系统配置。
- `access.Users` 持有有界密码工作及独立随机会话，storage 在原锁中复核用户/密钥/分组、预算和实际选号。旧管理员密钥不分配用户，原三平台协议/刷新/任务锁域不变；无额外推理网络调用、密码哈希或逐帧用户日志。
- 用户共享请求预算跨密钥原子预留。Token / USD 为软预算，有任一计量限额时，用户跨密钥最多一个在途请求；一次请求仍可能超额。所有已报告尝试累计，未知用量和缺价格按原规则拒绝相应后续请求。
- 请求固定用户 ID，同步账本结算用户及密钥预算，删除密钥后仍可结算和查历史。用户历史先按身份过滤，再以明确字段投影、统计及分页；默认模型省略时仍保留请求当时的公开名称。管理员保留实际型号及完整尝试信息。
- 停用、改密、退出、重启与跨站请求均已验证。密码修改保留 API 密钥；停用阻止新请求/新尝试，不撤回已开始的上游请求。用户存在时即使删完密钥也不能恢复匿名推理。

设计见 [ADR 0011](../adr/0011-single-instance-consumer-users.md)，使用及容量/保留限制见 [用户指南](../USERS.md)。

## 性能

与 M6 在相同 CPU 亲和性、GOMAXPROCS=2 下交替 5 轮比较 21 个微基准和 9 类真实 socket 容量场景，共 90 条容量记录；所有场景零失败、零残余租约，并发峰值保持 2。

首轮出现空历史结算 +5.57%、无重试流式摘要 P95 +8.55% 的信号，未抹去原样本。分别以 9 轮、7 轮针对复测，结算中位数 6775 → 6783 ns（+0.12%），摘要 P95 +0.77%、吞吐 -0.09%，未复现稳定超过 5% 的回退。结算分配次数仍为 12，记录归属/公开模型字段带来少量字节增量；完整样本见 [JSON](STRUCTURE-M7-COMPLETE-2026-11-02.json)。

新用户认证加预算预留/释放采用真实长度的用户 ID，最差位置查找，5 轮中位数：

| 用户数 | 微秒/次 | B/次 | 分配次数 |
| --- | --- | --- | --- |
| 1 | 0.281 | 112 | 3 |
| 100 | 0.864 | 112 | 3 |
| 1024 | 5.765 | 112 | 3 |

这不是上游响应速度保证；不限计量预算的用户沿用原账号池并发，启用 Token / USD 限额后的单用户在途限制属于明确预算语义。

## 真实上游

最终隔离验收 11 个客户端请求全部成功，共 16 项检查：WorkBuddy/Trae 各流式和非流式 Chat、Messages、流式 Responses；WorkBuddy 两次工具闭环和一次原生搜索。实际模型均为各自平台的 `deepseek-v4.1-flash`，通过请求 ID 对应到管理员日志，核对用户归属、公开模型显示、跨密钥累计、隐藏清单、禁用/未知型号在上游前拒绝及零残余租约。

本轮执行 3 轮，共 33 次真实客户端请求；前两轮上游请求均成功，后置验收误把没有上游尝试的 403/404 记录纳入统一型号/预算等式。修正验收后最终通过；同时补了默认模型日志的公开名称回归。临时用户/密钥和真实账号副本已删除，不修改正式账号或轮转共享凭据。

CodeArts 当前临时凭据过期，本轮未执行真实调用或刷新；其三协议、租约和用量归属由假上游受控验证，不能声称本轮真实可用。未执行真实成长任务或领奖。
