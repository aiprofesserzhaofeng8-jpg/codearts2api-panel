# 用量与预算强杀恢复验证（2026-10-30）

**已确认缺陷，尚未修改生产持久化逻辑：定时保存前强杀进程，会丢失已完成请求的日志、用量和 API 密钥预算计数；重启后原本耗尽的预算可以再次放行。** 正常退出、定时保存完成后再强杀的对照组均完整恢复。

本轮只增加独立验收脚本与证据，不改请求路径，不重新部署或重启生产服务。

| 场景 | 停止时间（启动后） | 恢复的已完成记录 | 重启后的请求次数 / Token / USD 预算 |
|---|---:|---:|---|
| 保存前 `SIGKILL` | 0.417 秒 | 0 / 3 | 全部重新放行，HTTP 200 |
| 正常 `SIGTERM` | 0.371 秒 | 3 / 3 | 全部继续拦截，HTTP 402 |
| 定时保存后 `SIGKILL` | 30.089 秒 | 3 / 3 | 全部继续拦截，HTTP 402 |

每组分别通过 Chat、Responses、Messages 完成 3 个请求，并配置三个独立密钥：请求次数预算 1 次、Token 预算 16、USD 预算 0.000016。模拟上游对每次推理返回输入 12、输出 4、其中缓存输入 3；三项参考单价均为 USD 1 / 百万 Token，得到每请求费用 0.000016。所有请求用量已知、价格完整、没有重试。

强杀前，三条响应均已返回，管理接口也已确认结算完成：输入 36、输出 12、缓存输入 9、费用 0.000048；每个密钥消耗 1 请求 / 16 Token / 0.000016 USD。再次请求均被 HTTP 402 拦截，且没有到达模拟上游。此时磁盘仍为零记录，强杀重启后恢复为零。对照组则逐项保留这些数值，并核对了三个 `request_id`、请求日志和独立用量历史，未出现重复结算。

共执行 27 次推理入口 POST，其中 12 次到达本地模拟上游：9 次初始请求、3 次强杀重启后预算回退产生的额外请求。15 次预算拒绝均未到达上游。**真实上游调用为 0。**

根因定位：

- `internal/server/chat.go` 的统一 `record` 调用 `Store.Record`。
- `internal/store/store.go` 的 `Record` 在内存中更新日志、累计统计、用量历史和密钥预算，没有即时持久化。
- `main.go` 每 30 秒调用 `Store.Save`，收到 SIGTERM 时等待 HTTP 处理结束后再次保存。SIGKILL 无法运行该退出逻辑。
- `Store.Save` 已有临时文件、文件同步和原子重命名。当前证据指向“尚未保存的内存数据丢失”；未复现已有状态文件损坏。

丢失范围取决于最近一次成功保存，而非固定三条；其他管理操作可能提前触发保存。30 秒是定时调度间隔，保存耗时、调度延迟或保存失败会影响实际窗口，不能承诺最多仅丢 30 秒。本轮没有测试推理进行中强杀、磁盘写入失败、宿主断电或真实提供商在途账单恢复。

复现方式（需 Python 3、OpenSSL 和已构建的二进制，约 32 秒）：

```bash

  --binary bin/codearts2api-panel \
  --output artifacts/persistence-crash/results.json
```
