# 账号基础管理协调分离验收（M3 第十一批）

日期：2026-11-01。基线 `2649078`，版本 `0.3.0-structure-m3.11`。M3 尚未整体完成。

## 改动与边界

`accounts.Management` 通过窄 Store 接口协调账号创建/导入后的提交、删除、并发设置、启停/暂停、清错、导出和重读。HTTP 保留既有请求 DTO、字段、状态码、错误类型及凭据导出提示；删除成功后才清理原积分视图缓存。CodeArts 手工/JSON/桌面凭据构造及原生导出/重读由 `upstream/codearts` 包装，app 装配同一个原生 Manager，并按调用读取当前续期配置。WorkBuddy/Trae 导出直接返回原不透明凭据字符串，不规范化、不进入 CodeArts 解析器。

Store 仍是唯一事务方，不改变锁顺序、准入或凭据代际；普通请求不调用账号管理服务。CodeArts、WorkBuddy、Trae 原生文件、Store、gateway、protocol、requestpolicy、页面逐字节不变；`server.go` 除新增依赖和装配外全部方法不变，其余 admin handlers 也不变。没有增加凭据 JSON 表示、缓存、网络探测或重试层，也没有启用自动续期或修改启动参数。

保留操作差异：删除、并发设置使用原严格保存事务，失败回滚；创建/导入、启停、暂停、清错，以及重读成功后的收尾保存仍沿用旧版保存失败记录日志、保留内存修改的语义。原生凭据轮转的 CAS 保存失败仍返回错误并保留已轮转的内存凭据。本批不将这些旧行为悄悄改成另一种持久化保证。重复导入继续复用账号 ID，保留启停、暂停和并发上限；批量导入仍逐个 upsert/失效后保存一次。导出与重读仍先查找账号、失效原缓存、建立最长 30s 的调用上下文，再解析原生凭据；非 CodeArts 导出不进入该流程。

`make check`、全量 `go test -race -count=1 ./...`、Windows vet/交叉构建、启动器 9 项、Pi 回归通过。实际 Store 故障注入确认：删除与并发保存失败不改账号、并发上限及凭据缓存；删除成功才清除缓存且重启后不复活；旧版保存失败仍保留内存修改，重复导入保留调度控制，目录恢复后可以保存并重新加载。原生导出响应当前续期开关，明确重读仍保留既有强制允许续期策略；相关令牌接口使用假上游，核对真实原生 DPoP/轮转/Store 提交流程，没有刷新共享凭据。

HTTP 检查确认缺失账号、错误状态/类型和提示保持原契约，删除失败不清除积分视图，非原生导出保留空白、大整数等原凭据字符串。另用 M3.10 旧二进制与本批二进制分别运行相同隔离状态，比较 **37 项**管理接口与保存结果，除随机 ID、ID 派生展示名和临时目录归一化外一致。覆盖方法拒绝、缺失账号、并发校验、手工永久凭据及去重、JSON 导入/导出、启停/暂停、清错、重读和删除；上游代理阻断，不使用真实凭据。

providers、trae、trae-device、groups、account-create、growth-multi 六组页面通过。二进制从独立 cwd 启动，登录、资源字节一致和重启恢复通过；Docker UID 10001，登录、静态资源及重启通过。Windows 仅交叉构建，未做运行验收；原生桌面 SQLite/DPoP 内部实现不改，其条件依赖的读取/回写覆盖没有在本批扩展。

## 真实请求

用户重新登录 CodeArts 后，使用私有状态副本关闭导入、自动续期、IDE 回写和领奖。三平台各两次普通生成（流式/非流式）及一组工具调用/回填，共 **12 次真实生成通过**，核对公开名、实际型号、真实用量、工具参数和回填，租约归零。实际型号为 `deepseek-v4.1-flash`、`workbuddy/cn/deepseek-v4.1-flash`、`trae/cn/deepseek-v4.1-flash`。临时状态结束后删除，共享状态和轮转凭据未改动。

这是新登录凭据的真实调用验收，**不是自动续期验收**。续期材料齐全不能证明上游已接受续期；本机仍保留 `-no-refresh` 和关闭的自动续期配置。本轮不执行真实续期、交互登录或领奖。
