# 安装附件下载错误与重试验收

2026-11-03，用户在获取 v0.3.8 后下载 Linux amd64 附件失败。独立请求复现原 GitHub 附件地址返回 HTTP 500；对同一附件添加防缓存查询后得到 HTTP 200，下载主机为 release-assets.githubusercontent.com。由此确认附件存在；仅凭此次观察不能确定错误源于哪层缓存或 GitHub 内部节点。

## 修改

- 附件遇到 408/429/500/502/503/504/618、连接错误、超时及下载不完整，最多 3 次尝试，重试等待 1 秒、2 秒。
- 每次从原可信附件地址重新获取签名链接，重试添加唯一防缓存参数，并携带 Cache-Control: no-cache。API 查询仍只尝试一次后按既有规则使用公开备用通道。
- 完整读取后检查 Content-Length（若存在），失败删除本次创建的残缺临时文件；不覆盖原先存在的目标。来源、大小上限和 SHA-256 校验保持不变。
- 错误区分 404、5xx、限流与临时链接失效，显示状态码、主机和文件名，不输出签名查询参数或 Token。不再将所有 HTTP 错误归为版本号问题。

## 验证

- 86 项部署测试通过。新增测试覆盖 500 后重新获取链接、618/超时/断连/不完整恢复、重试次数上限、残缺文件清理、404/403/401/API 限流不重试、越界与来源错误不重试、既有文件不覆盖、诊断隐藏签名参数。
- 当前脚本实际 download 成功，程序与维护脚本均完成下载并通过摘要验证；随后独立 sha256sum 复核通过。该次成功下载未触发重试，重试恢复路径通过受控故障测试验证。
- sh -n 和 git diff --check 通过。

未在用户的现有系统服务上安装、卸载或升级；未修改账号数据和备份。没有覆盖 v0.3.8 附件，新行为来自 main 安装入口。重试无法保证 GitHub 或网络持续故障时下载成功，最终仍明确报错。
