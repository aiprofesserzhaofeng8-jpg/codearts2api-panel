# 用量与预算强杀恢复修复（2026-10-30）

**已修复并部署。** 已成功结算的请求先同步追加到账本，再更新内存统计和预算；即使 30 秒 JSON 快照尚未更新，进程被强杀后也能恢复。序号检查点防止重复补记，以及预算重置被旧记录覆盖。本轮没有修改提供商适配器、模型请求参数、流式帧处理或重试策略。

核心提交：`2cef204`。运行二进制 SHA256：`865590c35a21712ab8ff5765484adc42270291a1a190aa409de2d99aab435217`，与最终隔离验收的二进制一致。服务 `codearts2api-panel.service` 已重启加载，PID `3766940`；历史统计逐项保持一致，账号 12、原有密钥 4、在途 0，设置和原有预算用量均保持不变。旧二进制和升级前状态保存在本机私有备份目录，未入库。

| 复现场景 | 修复前恢复记录 | 修复后恢复记录 | 修复后预算行为 |
|---|---:|---:|---|
| 定时保存前 SIGKILL | 0 / 3 | 3 / 3 | 请求次数、Token、USD 三类预算均继续返回 402 |
| 正常 SIGTERM | 3 / 3 | 3 / 3 | 继续拦截 |
| 定时保存后 SIGKILL | 3 / 3 | 3 / 3 | 继续拦截 |

最终二进制的保存前强杀场景中，JSON 仍是零条记录，旁边的账本已经有 3 条完整记录。恢复后逐项核对累计统计、日志、独立用量历史、预算计数和请求编号，全部一致，没有重复扣费。完整结果见 [crash.json](evidence/persistence-fix-2026-10-30/crash.json)；缺陷基线见 [原始验证报告](PERSISTENCE-CRASH-2026-10-30.md)。

实现集中在 `internal/store/usage_journal.go`：

- 每次结算向状态文件旁的 `.usage.jsonl` 追加一条元信息记录并同步文件。仅保存请求元信息、用量、当时价格和密钥哈希，不写入完整 API 密钥、账号凭据或对话正文。
- JSON 快照保存结算序号。只有快照成功原子替换并同步目录后，才移除它覆盖的账本前缀；快照写盘期间新增的记录作为后缀保留。完整快照的磁盘写入不占用结算锁。
- 恢复使用记录中的价格快照，不根据当前模型价格重算历史。所有直接保存状态的管理事务也携带结算序号，因此预算重置、日志清空不会被旧账本再次覆盖。
- 账本写入失败时仍保留已经发生的内存用量，记录错误，并对新推理返回 503，避免继续使用未保存的预算。已有有效模型响应保留。后续完整保存成功且账本恢复可用后，自动恢复推理。
- schema 升到 v5，旧状态自动迁移。旧二进制会拒绝读取 v5，避免静默丢掉检查点；回退须使用配套旧快照。完整但损坏的账本阻止启动；中断写入留下的无换行尾部只保留之前已完成的记录。

借鉴 Sub2API 固定提交 `a3298b46` 的[统一结算与事务去重](https://github.com/Wei-Shaw/sub2api/blob/a3298b46ebe239fb0720b068a1eb3383955bdac2/backend/internal/repository/usage_billing_repo.go)。本项目保留 JSON 快照，新增本地账本，不引入数据库服务、第三方运行依赖或内存结算队列。Sub2API 的[有界后台队列](https://github.com/Wei-Shaw/sub2api/blob/a3298b46ebe239fb0720b068a1eb3383955bdac2/backend/internal/service/usage_record_worker_pool.go) 用于减少前台等待，但仅有内存队列不能消除本次验证的强杀丢失窗口。

新增每次约 2 KB 分配、11 次分配操作，主要来自 JSON 记录及文件操作。真实同步写盘有代价，本机结算平均新增约 0.325 ms；不能把此结果推广为所有磁盘和负载下的固定上限。历史记录增长没有让每次结算变成全量保存。

固定 20 ms 模拟上游、并发 2 的完整 HTTP 请求测试，修复前后各 3 轮，每轮 100 请求，均无失败、无租约残留；P95 的中位数由 **21.388 ms 增至 22.635 ms（+1.247 ms）**。这说明总响应完成时间存在可测量的增加。逐块输出的代码未改，新增同步工作发生在请求结束结算阶段；本轮没有单独量化真实上游首 Token 延迟或证明高并发下零性能影响。见 [benchmark.json](evidence/persistence-fix-2026-10-30/benchmark.json)、[HTTP 测量](evidence/persistence-fix-2026-10-30/http-performance.json)。
