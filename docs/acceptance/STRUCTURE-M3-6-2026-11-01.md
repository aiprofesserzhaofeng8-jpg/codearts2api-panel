# 全局换号与短恢复分离验收（M3 第六批）

日期：2026-11-01。基线 `969a2e3`，本批版本 `0.3.0-structure-m3.6`。抽取全局重试和同租约有限恢复；凭据、平台错误策略及管理业务仍保留原入口，M3 尚未完成。

## 职责与顺序

- `gateway.RunAccountRetry` 持有一个总期限、默认 3 次且最多 8 次的尝试限制、账号排除集合及租约生命周期。短恢复明确回报额外消耗的一次尝试，不重置总次数或期限。
- server 的 `accountRetryDriver` 保留 Store 原子准入、分组/预算复核、公开与实际型号上下文、平台错误分类和原健康写入。原型直调仍在准入前复核，映射仍在准入后、租约内按实际型号复核；不拆锁、不添加缓存或凭据编解码。
- `gateway.RunRecovery` 只负责首次执行、结束计量、资格检查、等待、取消复核、进入授权及一次恢复的顺序。WorkBuddy 的 500/502/503/504 白名单、首轮/未观察分片限制、300ms 等待和 3s 进入窗口仍为独立平台策略。等待时保留原租约，3s 窗口不成为生成超时。
- `CommittedStreamError` 归 gateway，HTTP 入口报告输出可见边界；包装保留原错误链。租约先释放，取消及请求级终止优先于平台分类；需要的健康处理完成后，已提交输出禁止重放。中断 CodeArts 退避仍返回原上游错误，WorkBuddy 恢复等待中断仍返回等待错误，保持原语义。
- 三平台原生实现、Store 与页面逐字节不变，schema 仍为 6。没有增加上游轮次、逐分片解析/计时、存储写入或自动刷新。
