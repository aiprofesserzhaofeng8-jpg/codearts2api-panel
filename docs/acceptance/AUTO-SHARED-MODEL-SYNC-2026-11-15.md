# 模型发现后自动归并共享名称

## 原因与变化

此前刷新只更新上游目录，默认名称归并必须由管理员再次点击应用；因此新接入 MobileClaw 虽能直接调用，已有共享名称仍只有旧来源。

按本次用户要求，成功刷新模型目录后自动复用默认目录规划与存储事务：首次发现创建共享名称，已有共享名称追加缺失来源。不需要额外运行追加脚本。账号保存后的既有目录刷新、启动刷新以及正常目录刷新均沿用此逻辑；不增加后台任务、存储格式或生成请求中的网络查询。

现有精确型号识别和已审核别名规则不变，不根据模型自述合并。没有新来源时不保存、不增加版本号。保存失败返回明确错误，下一次正常刷新可以再尝试，不自动循环重试。

## 管理员控制

- 保留共享名称、ID、启停设置、已有来源启停及客户端策略。
- 不删除目录暂时缺失的来源，不改账号分组、白名单或指定来源授权。受限用户仍受现有分组权限控制。
- 有冲突或已保存客户端策略不兼容的项不自动应用，仍在默认目录预览中显示冲突。
- 如需持续排除某个已发现来源，请停用该来源。仅删除一个仍被发现的来源后，下次成功刷新会再次追加；删除整个仍可发现的默认模型后也可能重建。此行为是自动同步的明确语义，不新增删除记忆表。
- 默认目录页面仍可手动预览和授权分组；首次安装不必为生成共享名称逐项点击应用，但普通用户的分组授权不会自动扩大。
