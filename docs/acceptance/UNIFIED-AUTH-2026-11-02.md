# 统一登录与后端角色授权验收

2026-11-02；本地版本 `0.3.0-unified-auth`，前端构建 `a53b614ec75b760eb081`。结构化结果见 [JSON](UNIFIED-AUTH-2026-11-02.json)，边界见 [ADR 0014](../adr/0014-unified-role-authentication.md)。本报告取代此前共用布局报告中的双会话、空间入口和跨角色 401 行为。

## 当前行为

- `/login` 只有用户名和密码。管理员使用保留用户名 `admin` 和原管理员密码；普通用户使用自己的账号。服务器返回角色，前端自动挂载对应菜单及工作区，没有角色选择或空间切换入口。
- `/auth/login`、`/auth/session`、`/auth/logout` 共用一个 HttpOnly、SameSite=Strict、Path=/ 的八小时会话。令牌只存摘要，管理密码变化、用户停用/revision 变化、退出和重启使对应会话失效。密码登录更换当前浏览器身份时会撤销旧令牌。
- 删除 `/admin/auth/*`、`/user/auth/*`、独立 AdminSessions、请求头/Bearer 管理密码、本机自动解锁和页面 capability 注入。管理业务接口保留，每个请求必须验证服务端 admin 角色；普通用户接口要求 user 角色及原资源归属检查。
- 登录、资料更新和用户更新不接受客户端指定角色。OAuth 只能给已有且启用的消费者签发会话，不能创建管理员身份。不更改用户持久化结构或密钥归属。
- API 生命周期由 ConsoleApplication 统一持有，身份变化时取消旧读取后再挂载页面。修复验收发现的父子组件重复初始化导致登录页显示 `Console disposed` 的问题；原生管理员 DOM 所有权保持不变。
