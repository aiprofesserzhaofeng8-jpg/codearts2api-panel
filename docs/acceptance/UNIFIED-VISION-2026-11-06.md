# 共享模型图片能力与 Pi 同步修复

2026-11-06。问题：共享模型按所有来源能力交集导出，实际路由却能按能力筛选；Pi 旧 models.json 仍为纯文本，且缺参数会令 client-profile 422 阻塞能力导出。

## 实现

- 新全局统一模型按已授权/启用候选来源声明图片和工具可用性；任一明确支持即可声明支持，全体明确不支持才声明不支持，否则保持未知。旧分组映射路径保留兼容语义。
- 原请求筛选要求单一来源满足图片、工具及输出限制的组合；没有共同来源时明确失败，禁止拼接不同来源能力或丢弃图片。新增回归涵盖候选范围和权限限制。
- client-profile 缺少数字参数时返回 HTTP 200 能力信息与 missing_limits 状态，省略未知上下文/输出值。列表仍保留独立能力字段和缺项说明；数值推荐不放松原证据要求。
- connect-client.py pi --sync-models 备份并更新当前 ~/.pi/agent/models.json 的 codearts-local 条目；先验证网关地址，保留密钥/其他 provider/已有用户参数。不执行配置里的凭据命令。新模型参数未知则跳过；已有参数保留并报告，未知图片能力也明确报告。
- 已有独立启动器仍要求完整数值推荐，收到 missing_limits 时给出明确说明；不生成虚假上下文限制。
