# WorkBuddy 成长任务执行验收 · 2026-10-30

已部署批量接取、两类真实对话任务执行、进度回查与自动领奖。当前真实账号被上游领养前置条件阻止，真实模型执行和奖励入账尚未验收；不能宣称支持参考项目的 17/18 自动完成能力。

## 实现范围

| 能力 | 行为 |
| --- | --- |
| 接取 | 单项或批量，每批 1–20 项；接取后核对上游状态，单项业务拒绝明确显示 |
| `Model_chat_GLM5.2` | 最多一次 GLM-5.2 真实对话，当前真实账号没有下发该任务 |
| `chat_5` | 根据已确认进度补足真实对话，最多五次，每次最多输出 32 Token；进度不增长就停止 |
| 其他任务 | 官方操作指引、进度查询与已达标奖励领取；不发送虚构的创建、使用模板或技能成功事件 |
| 多账号 | 浏览器每次最多两个账号并行，同账号逐项串行；服务端真实执行还有全局双账号上限，与接取/领奖共用账号任务锁 |
| 费用与并发 | 遵守积分模型开关，使用正常账号并发名额；真实尝试写入用量日志，可按“成长任务”筛选，不扣客户端密钥预算 |
| 防重 | 付费调用前保存独立 0600 执行检查点；进度未增长时跨刷新、重启阻止重放，状态读取/保存失败不发起新对话 |
| 关闭 | 取消执行请求、停止后续对话与排队任务，已发出的模型请求仍可能消耗积分 |

接口、维护文件和使用方法见 [成长任务说明](../WORKBUDDY-GROWTH.md)。查询/领奖不隐式执行动作；没有新增后台任务排程，主状态仍为 v5。

## 真实验证及限制

真实账号返回 19 项任务，其中本地支持动作的只有 `chat_5`；没有 `Model_chat_GLM5.2` 体验任务。点击单项“执行任务”后，上游接取接口的响应为 HTTP 200、`code=0`，但 `data.results[]` 明确给出：

```json
{"task_code":"chat_5","status":"error","message":"prerequisite not met: first_buddy"}
```

回查仍为 `not_accepted`、`current=0`、`target=0`。已修复总状态成功掩盖单项失败的问题，部署后的真实页面返回 409，明确提示先在官方应用完成“领养第一只 Buddy”。接取未确认时没有发起模型请求、报告或领奖；真实模型调用 0，奖励 POST 0，积分消耗 0。临时浏览器会话已退出。

因此，真实任务完成及奖励入账仍未验证，多账号执行仅通过隔离夹具验证。当前账号需要先在官方应用阅读领养协议并完成实际领养，再进行后续真实验收；没有自动代为同意协议或伪造前置解锁事件。
