# CodeArts 对话边界验收（M3 第二批）

日期：2026-11-01。基线为 M3 第一批 `183bb14`，本批版本为 `0.3.0-structure-m3.2`。完成 CodeArts 原生对话包装、普通单次执行和协议聚合分离；整个 M3 的 HTTP/业务分离尚未完成。

## 变更与兼容

- `upstream/codearts` 包装既有签名客户端，绑定已选中账号的不可变会话指针。保留请求原始字节和凭据代际，不解析或重新序列化凭据；业务错误在分片交付前使用原有规则识别。
- `gateway.Completions` 通过使用方定义的 `ChatSession` 执行普通单次对话。保留一次非流式请求遇空响应后的一次流式回退；不另选账号、不刷新、不增加全局重试，也不自行结算。
- 普通流式仍立即回调，顺序仍为输出观察、用量捕获、下游回调；消费者错误和取消直接传回。原有需要聚合的路径才聚合，借用的分片仍复制后保存。
- SSE 聚合和流式请求选项迁入 `protocol`。与基线逐段比较，除导出函数名及等价随机 ID 帮助函数外，实现不变。旧 `codearts.AggregateSSE` 只作单向兼容委托，没有第二套实现。
- `app.Build` 创建包装器和执行器，所有调用方共享原客户端和模型注册表。CodeArts 摘要只切换传输入口，摘要判断、截断恢复和调用上限仍保留原实现。
- WorkBuddy、Trae 继续原有传输和凭据接口，聚合改用同一协议实现。页面资源逐字节不变；schema 保持 6。权限复核、选号、租约、提示词、超时、刷新和账本归属不变。

## 性能

详细数据见 [结构化记录](STRUCTURE-M3-2-2026-11-01.json)。同机、同工具链、固定上游延迟 20ms、并发 2、每轮 100 请求，各三轮：

- p95 中位数：22.497ms → 22.470ms，约 -0.12%；失败和剩余租约均为零，实际最大并发均为 2。
- 流式计时基准约 +1.48%；1MiB 非流式约 -2.21%，8MiB 约 +1.70%，此处不把小幅变化解释为可靠提速。
- 初次选号微基准有两项超过 5% 的波动，因此构建独立的新旧测试程序并交替五轮。复测旧入口约 +1.99%、映射组原型号入口约 +0.85%，分配次数相同。
- 同组交替复测的 1KiB 单次 CodeArts 调用为 34.899µs → 35.926µs，约 +2.94%；141 → 142 次分配、约增加 16B。该接口边界有小成本，没有新增网络往返、凭据 JSON 转换或每分片写盘。未发现超过 5% 的稳定退化，不宣称零开销。
