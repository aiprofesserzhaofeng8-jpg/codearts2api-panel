# 保存结果与账号续期：阶段 1～3

范围：交付已完成的设置/密钥保存修复，核对剩余管理写路径，接入独立登录会话的续期。未进入模型兼容性验收，不增加数据库、文件上传存储、后台刷新进程或推理重试层。

## 阶段 1：既有修复交付

设置与密钥删除/启停使用 Store 串行事务；写失败回滚，HTTP 返回失败，身份头/限流参数仅在成功后更新。源码、故障注入测试、完整检查已完成。本批统一打包交付，不将前一版本的安装包当作包含本次修复。

## 阶段 2：管理写路径审查

| 路径 | 本次处理/核对 |
| --- | --- |
| 设置、密钥删除/启停 | 严格保存后成功；失败恢复内存 |
| 账号新增/导入/删除/启停/暂停/清错/并发 | 已有严格事务，复用原实现 |
| 分组、密钥绑定/预算、用户、权益、模型映射/策略、价格 | 沿用已有返回错误的保存事务，未重构 |
| 清空运行日志、重置汇总统计 | 新增串行保存事务；失败回滚；保留用量历史和结算账本 |
| 账号探活 | 最终保存失败返回 HTTP 500，保留逐账号真实探活结果；不回滚已轮转凭据 |
| CodeArts 原生领奖 | 上游执行后保存失败不再报成功；明确要求先核对上游，不自动重放 |
| 外部平台领奖 | 已有保存错误传播，未改变领奖协议 |
| 凭据重读、登录确认、轮转 | 已有错误传播/CAS；轮转后的新凭据不回滚为已失效旧令牌 |
| 动态模型目录、积分查询缓存 | 属于运行时观测，不伪称持久化配置 |
| 推理健康标记、周期保存 | 仍为运行时日志/持久化流程，不属于管理员保存成功响应；没有扩大修改 |

这次覆盖已发现的管理写路径问题，不等于所有磁盘/断电/跨实例情况都获得强事务保证。未改 JSON 单实例存储架构，也未宣称上游领奖和本地保存可形成跨系统原子事务。

## 阶段 3：账号续期

- MobileClaw：已安装官方 1.9.8 确认 `/desktop/manager/auth/refresh`；新扫码登录保留独立设备和刷新令牌。普通桌面导出仍不含刷新令牌。用户已反馈手机授权成功，要求对应手机号蜂窝网络。
- TeleAgent：已安装官方 3.0.0-rc.4 确认 `/superCowork/sapi/cowork/auth/token-refresh`；独立临时浏览器登录使用 X-Token 换新，保留现有 API key、设备/安装信息。官方明确禁止 KMS 会话走普通续期接口，本项目不自动升级旧导入/KMS 凭据。
- 两者通过现有 ProviderCredentials 到期前 5 分钟按需刷新，受全局自动续期开关控制。无调用时不增加定时器。一次刷新不自动重放，不做额外目录查询。
- 同账号互斥、身份/地区校验、凭据代际 CAS、删除/替换后拒绝旧结果沿用现有实现。磁盘失败保留已轮转的新凭据并报告错误；周期保存恢复后可以落盘。
- 旧 MobileClaw 扫码版本已丢弃刷新令牌，无法凭空恢复；旧 TeleAgent 没有独立会话标记。升级后需各重新登录并确认覆盖一次，不能直接改旧凭据字段开启续期。
- 无效会话、绝对有效期到期、损坏响应仍需重登。网络异常不解释为账号永久失效。

## 验证及交付边界

- `make check`：通过（资源限制 GOMAXPROCS=2、GOFLAGS=-p=2）。
- 保存故障、登录、续期及并发相关 `go test -race`：通过。
- 两平台实际适配器→公共凭据协调器→磁盘链路：模拟上游验证并发单次轮转、正常落盘、落盘失败不回退旧令牌、存储恢复后重启读取。
- 本次不读取/打印真实令牌，不写官方客户端配置，不直接离线轮转正在运行的服务凭据。
- 真实自动续期尚未验证：运行数据属于服务用户且 sudo 需要交互密码；新流程也需要用户完成扫码/浏览器认证。不得将模拟上游测试称为真实上游通过。
- 安装包与脚本准备后，由管理员执行备份升级；未执行前不视为运行版本已替换。

真实验收顺序：升级→重新登录两个平台并显式保存→确认页面显示可续期且全局自动续期已开启→到期窗口执行一次探活或正常请求→确认到期时间延长、错误未被隐藏→重启后核对新期限。不要用另一个进程直接刷新 state.json 中的令牌，以免与服务争用轮转代际。完成后再进入模型兼容性验收。
