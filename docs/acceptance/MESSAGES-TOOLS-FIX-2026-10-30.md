**修改范围与行为**

仅修改业务文件 `internal/server/anthropic.go`，增加 97 行、删除 30 行；测试、真实分片夹具和本报告单独保存。没有修改账号池、请求策略、默认提示词、重试次数、其他协议或上游适配器。

- 每个上游工具 index 保存独立 ID、名称、参数及下游内容块 index；相同函数名的不同调用仍严格分开。
- 参数按所属工具逐片发送。ID 或名称晚于参数到达时，先暂存该工具参数，信息齐备后发出 start 和已有增量；其余正文无需等待。完全缺失 ID 时，沿用网关补充调用 ID 的兼容思路，在完成阶段生成独立 ID。
- 工具内容块保持开放到本次流完成，再逐一 stop。这样第二个工具或正文开始后，先前工具的迟到分片仍可正确落入自己的块，不会向已关闭块写入增量。
- 重复声明相同 ID/名称允许通过；同索引换 ID、跨工具重复 ID、工具名称发生冲突会报告上游协议错误。
- 只在正常完成时校验累计工具参数 JSON 和必要名称；不会每片解析完整参数。空工具输入保留为 input={}，不要求必须存在正文或非空参数。
- `max_tokens` 截断保留部分参数和截断结束语义；不把合法截断伪装成完整 tool_use。异常完成通过 SSE error 结束，不发送成功的 message_stop，日志记录 502；响应头已经发出时仍为 HTTP 200，符合流中报错方式。错误沿用上游临时故障分类，已输出后不重放，不把它误认成账号凭据故障。

设计参考了 [Sub2API 的工具索引/内容块映射](https://github.com/Wei-Shaw/sub2api/blob/a3298b46ebe239fb0720b068a1eb3383955bdac2/backend/internal/pkg/apicompat/chatcompletions_anthropic_bridge.go) 和 [Anthropic 内容块流式协议](https://platform.claude.com/docs/en/build-with-claude/streaming)。本项目保留每个工具的开放状态直至完成，并通过官方 SDK 进行独立兼容性验证。
