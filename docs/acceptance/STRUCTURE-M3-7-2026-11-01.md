# WorkBuddy/Trae 凭据协调分离验收（M3 第七批）

日期：2026-11-01。基线 `e5fa02f`，本批版本 `0.3.0-structure-m3.7`。仅迁移原有凭据解析/刷新协调及按账号操作锁；CodeArts 原生 Manager、平台协议、登录管理、Store 条件事务和页面没有改写，M3 尚未完成。

## 职责与行为

- `accounts.ProviderCredentials` 持有每账号刷新锁。获得锁后读取当前 Store 快照，再经平台 `Normalize` 校验身份、地区和有效期；剩余不足原有 5 分钟提前量时，按当前续期开关调用原生 Refresh，复核新身份/地区并执行原 CAS 提交。排队请求读取新一代凭据，不重复使用已经轮转的 refresh_token。
- app 注入 `ProviderCredentialStore` 窄接口及实时设置回调；HTTP 层只按原顺序查找注册表、委托解析并返回原适配器。不缓存第二份注册表，不创建并行写入方，也不变更错误链和上游请求次数。
- `accounts.OperationLocks` 原样保留按账号的可取消通道锁。刷新、领奖、成长任务各有独立实例，没有合并锁域；不同账号可并行，Store 准入锁不跨网络。原有锁条目仍随进程存活，本批没有引入锁回收策略。
- 正常凭据路径仍仅 Normalize 一次；刷新路径仍在返回调用方之前条件提交。保存失败向上传递，同时保留内存中的已轮转凭据，禁止用旧备份恢复旧 token。CodeArts 的不可变 Session、IDE/DPAPI/DPoP 和专用代际校验保持原实现。
- 三平台原生实现、Store、gateway、upstream 包及页面与基线逐字节一致；schema 仍为 6。没有增加逐分片工作、正常路径落盘、网络探测或自动刷新范围。
