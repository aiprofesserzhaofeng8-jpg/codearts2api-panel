# CodeArts 浏览器登录协调分离验收（M3 第九批）

日期：2026-11-01。基线 `b48c2d4`，版本 `0.3.0-structure-m3.9`。本批分离 CodeArts 已有的分阶段浏览器登录协调，M3 尚未完成。

## 改动与边界

`accounts.BrowserLogins` 负责预览、确认保存、显式替换和删除后重放保护。使用方定义 Store 与原生流程窄接口；`upstream/codearts.BrowserLogin` 包装同一个原生 LoginManager，负责 STS JSON 解析、身份查询及回调/授权码提交。app 注入当前登录端口读取函数和原缓存失效回调。HTTP 保留原参数、字段、状态码、1MiB 回调/64KiB 确认限制、鉴权及同源校验。

原生 PKCE/DPoP、回调校验、监听器、超时、授权交换及单会话 Commit 锁逐字节不变。保存与失效仍在同一原生 Commit 锁内，失败不会记为已保存；Store 的查重、锁顺序、原子写入与回滚保持原实现。Store 的 `FindAccountSession` 只将参数改为中立快照并做原生类型断言；重复账号错误以同一 sentinel 别名兼容原调用方。旧 Session 指针直接借用，不经过 JSON 编解码。

本批未迁移普通 CodeArts Manager 解析/刷新，也未改页面、普通对话、摘要、提示词和重试路径。三平台原生包、gateway、protocol、requestpolicy 和页面文件与基线逐字节一致；accounts 不导入 HTTP、具体 Store 或原生平台。

## 验证

`make check`、全量 `go test -race -count=1 ./...`、Windows vet/交叉构建、启动器 9 项和 Pi 回归通过。新增验证覆盖 STS 过期/缺字段、身份失败/缺失/不一致、30s 查询截止、原生签名与同一凭据指针、取消、预览指纹变化、真实 Store 写盘失败可重试、16 路同时确认只保存/失效一次、显式替换保留 ID、删除后旧授权返回 410。原有 ticket/OAuth、回调归属及授权重放测试继续通过。登录核验使用假上游，不能视为真实互动登录通过。

六组隔离页面测试全部通过：providers、trae、trae-device、groups、account-create、growth-multi。二进制和 Docker 实例验证静态资源逐字节一致、登录及重启恢复；二进制在独立 cwd 启动，容器 UID 为 10001。Windows 仅交叉构建，没有执行 Windows 运行验收。
