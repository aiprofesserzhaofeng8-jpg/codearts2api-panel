# TeleAgent 客户端窗口与输出建议

2026-11-23，通过本地网关 `127.0.0.1:10087` 对五个 TeleAgent CN 入口进行了真实请求测试。测试使用合成数字文本，在首、中、尾各放置随机标记，并使用上游 `usage.prompt_tokens` 校准输入量。输出参数探测与实际长文本生成分开执行。原始记录保存在本机 `artifacts/teleagent-limits-20261123/`，其中不包含网关密钥。

## 测试时采用的工作参数

| 精确来源 ID | 推荐窗口 Token | 推荐最大输出 Token |
|---|---:|---:|
| `teleagent/cn/chat-flagship` | 825,737 | 32,768 |
| `teleagent/cn/chat-flash` | 510,173 | 8,192 |
| `teleagent/cn/chat-lite` | 761,525 | 1,024 |
| `teleagent/cn/chat-nano` | 262,144 | 32,768 |
| `teleagent/cn/chat-pro` | 510,167 | 8,192 |

旗舰、Flash、Lite 和 Pro 的窗口取本次成功检索三处标记的最大输入量，作为客户端工作窗口；输出取拿到完整用量回执的实际生成长度。两列分别来自独立请求，客户端仍须在同一窗口内为输出预留空间。它们是本次已验证的工作参数；更大的请求可能成功。

Nano 的窗口来自边界行为推断：输入 11 Token 的小请求接受 `max_tokens=262133`，拒绝 `262134`，表现为输入与输出共享 262,144 Token。其大输入检索在 255,586 Token 下成功，512K 及以上测试返回 HTTP 400。

测试时 Lite 的输出配置为 1,024，可能较早截断长答案；管理员可在模型页自行增大。此次 8K、32K 长输出均未在 300 秒测试期限内完成，因此未把它们写为已验证默认值。

## 输入阶梯测试

目标 K/M 使用十进制，实际数值使用上游用量回执。成功请求均找回三处标记。

| 入口 | 约 256K | 约 512K | 约 768K | 约 1M |
|---|---|---|---|---|
| flagship | 254,934，通过 | 510,170，通过 | 765,517，通过 | 超时 |
| flash | 254,934，通过 | 510,173，通过 | 超时 | 超时 |
| lite | 253,865，通过 | 超时 | 761,525，通过 | 超时 |
| nano | 255,586，通过 | HTTP 400 | HTTP 400 | HTTP 400 |
| pro | 254,929，通过 | 510,167，通过 | 超时 | 超时 |

旗舰另有校准前的 825,737 Token 成功检索记录。校准前一次 412,644 Token 请求因只分配 256 输出 Token 而未返回第三处标记，未用于确定工作窗口。

网关平台 HTTP Transport 的响应头等待期限为 30 秒。大输入超时无法用于判定模型的窗口上限。Lite 的 512K 请求超时、768K 请求成功，也说明结果受当次运行状态影响。没有把任何入口标成已验证 1M。

## 输出参数边界与实际生成

| 入口 | 最大已接受 `max_tokens` | 最小已拒绝值 | 实际完整生成 Token |
|---|---:|---:|---:|
| flagship | 131,072 | 131,073 | 32,768 |
| flash | 131,072 | 131,073 | 8,192 |
| lite | 1,048,577 | 尚未发现 | 1,024 |
| nano | 262,133（输入占 11） | 262,134 | 32,768 |
| pro | 393,216 | 393,217 | 8,192 |

输出参数探测使用同一小提示词，仅改变 `max_tokens`。表中实际输出使用完整 `completion_tokens` 回执，包括平台计入的思考 Token。Flash、Lite、Pro 的 32K 实际生成触及 300 秒测试期限。Nano 初次 32K 测试触及测试工具的 8MiB SSE 缓冲，提高至 64MiB 后补测成功，用时约 241 秒。
