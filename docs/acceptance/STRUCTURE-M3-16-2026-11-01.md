# 积分查询与每日领奖编排分离验收（M3 第十六批）

日期：2026-11-01。基线 `de71f2d`，版本 `0.3.0-structure-m3.16`。M3 尚未整体完成。

## 变化与原行为

`accounts.Credits` 持有积分查询、60s 缓存、15s 查询期限及原四路批量并发/结果顺序；CreditInfo/CreditCategory 的唯一规范定义归 accounts，CodeArts 保留兼容别名及六个原生解析/查询函数体。此积分数量快照不属于 API 美元费用估算/预算账本。

原成功快照和错误的缓存规则保留：CodeArts 凭据/查询错误缓存；外部查询错误缓存，但外部凭据解析或返回 JSON 解析失败不缓存。fresh 参数只要非空便强制回源，缓存快照指针不复制，不新增查询合并或准入限制。账号删除及两处成长执行只在原位置调用统一缓存失效方法，保存失败不能提前失效。

`jobs.Rewards` 持有外部每日签到状态/确认、按账号可取消锁、30 分钟失败等待期、串行手动批量/每账号 60s，以及自动领取的单轮编排。原成长锁和凭据锁仍独立；锁内重读账号并复核删除、停用、当天确认和等待期。状态查询只询问状态，不提交领奖；确认后仍委托原 Store 严格保存，失败返回错误且不提前失效积分缓存。

CodeArts 继续使用原活动客户端，凭据失效与原生活动结果格式化由 upstream/codearts 包装；结果仍经 MarkClaimResult/Save 发布，Save 失败只记录日志。没有给原生领取新增去重锁、等待期或重试，没有改变上游个别活动结果为失败但调用自身无 error 时的历史处理规则。CodeArts 用本地日期，外部用 UTC+8；自动领取开关、时刻、账号顺序和现有定时循环不变。显式停用账号等既有差异继续保留。

HTTP 保留认证、方法、JSON 解码规则、未知账号处理、状态码及展示。平台协议、凭据表示/CAS、普通生成、准入/选号/账本和页面不改。app 注入同一 Credits/Rewards，server 仅保留使用现有平台对象的委托，未建立第二份平台注册表或运行状态。
