# 摘要执行与完整性分离验收（M3 第五批）

日期：2026-11-01。基线 `1b4064a`，本批版本 `0.3.0-structure-m3.5`。本批抽取已有摘要执行流程；全局换号、凭据和管理业务仍待后续批次。

## 职责与不变量

- `gateway.RunSummary` 通过已有 `StreamTransport` 执行摘要，持有 8MiB 私有缓冲、JSON/正文/结束原因校验和最多一次截断重试。gateway 不依赖 HTTP、Store 或具体平台。
- server 通过 Prepare/Start/Usage/Result hook 保留备用型号解析、同平台和地区约束、强制型号约束、当前冷却、预算及分组权限复核、尝试计量和模型健康写入。准备成功才开始尝试；备用型号不继承未经确认的原型号思维参数。
- 原始分片先解析、计量，再检查大小并复制原字节；保留未知字段、大整数和借用缓冲的安全边界。私有尝试失败时不交付内容，首次截断用量仍累计，备用型号按各次价格结算。
- 只有 `length` 可触发一次重试，始终复用绑定凭据和账号租约。保留旧实现对意外“工具输出且 length”的有限重试行为；工具输出不会作为有效摘要交付。本批没有借重构改变该边界。
- 错误仍为请求级终止，保留原中文消息及外层禁止换号重放规则。取消、预算拒绝、损坏 JSON、超限和不完整结束的处理顺序保持原值。
- 三平台原生实现、Store、页面逐字节不变，schema 仍为 6。没有扩展 WorkBuddy/Trae 的摘要能力，也没有增加配置项或网络轮次。

## 性能与本机部署

基线和新版编译同一份测试夹具，固定物理核 CPU 0、2，设置 `GOMAXPROCS=2`，五轮交替容量测试及五轮交替微基准。容量每轮每项 40 次请求、并发 2、固定上游等待 20ms，两段 HTTP 均使用本机 socket；八种用例全部成功，峰值并发 2，剩余租约为零。不重试用例上游 40 次，截断重试用例恰为 80 次，没有额外放大。

微基准覆盖三平台普通请求、公开模型名、CodeArts 1KiB/1MiB/8MiB 普通输入，以及 1KiB/1MiB 摘要的流式/非流式和一次/两次尝试。按时间自动校准迭代次数的摘要夹具包含账本落盘，波动明显，其耗时下降不作为提速证据。追加五轮交替固定次数摘要测试（1KiB 每项 500 次、1MiB 每项 20 次），耗时变化为 -1.19%～+2.59%，没有观察到稳定超过 5% 的退化。

回调边界有少量分配成本：固定次数 1KiB 夹具每次请求多约 10～15 次分配、340～943 字节；大输入的池化缓冲存在采样波动，不宣称零内存开销。没有增加 JSON 解析、写盘、计时或网络轮次。完整数据见 [JSON 记录](STRUCTURE-M3-5-2026-11-01.json)，本机原始日志位于忽略目录 `artifacts/structure-m3-5/`。结论限于这些夹具与并发，不承诺所有负载零开销。
