# 全目录模型能力实测

2026-11-06，本机系统服务 v0.4.4，地址 `http://127.0.0.1:10087`。使用现有 Pi provider 的网关密钥在内存中认证；没有修改 Pi 配置、生产程序或统一模型定义。

覆盖当前密钥可见的 89 个公开名称和配置中启用的 115 个原始来源。每个目录项记录三协议流式/非流式文本、三协议工具闭环、图片、工具读图和 JSON 样例，共 12 类结果。账号、配额或上游故障导致后续能力无法验证时明确标为受阻，不算通过。

## 最终汇总

| 用例 | 公开名称 | 原始来源 |

表中计数有重叠；未通过可能是能力门禁、上游拒绝、额度截断、专用型号不适用于普通聊天或前置条件受阻。不能将其一律解读为基础模型不具备该能力。

## 已确认的缺口

- 有效 PDF 以 Responses `input_file` 提交后返回 200，但随机文件常量没有被读取；转换函数未处理该内容类型。Files API 实际上传返回 404，Messages document 明确拒绝，Chat 文件块被当前 CodeArts 上游拒绝。
- 39 个“公开名称—能力”组合被共享路由拦截，但原始来源相应测试通过，涉及 34 个公开名称。需要按来源补齐现有能力字段，保持组合能力筛选。
- 7 个共享名称的 Messages 工具第二轮被原生 thinking/signature 路径拦截；部分 Qoder 型号工具结果回传后重复调用或 400。
- Trae 当前适配器只支持文本。ChatGPT 上游 429、Kiro 无效响应、Trae 部分槽位业务错误分别记录，没有伪装成模型功能已通过。

一次临时 Trae 账号冷却影响部分用例。恢复确认后，11 个来源及 3 个公开名称只补测一轮；10 个来源的文本/工具恢复通过。汇总采用最近一次完整结果，每个更新单元格保留 previous_attempt，同时保留原始汇总文件。明确的配额错误没有盲目重试。

TeleAgent flagship/nano 增加输出额度后六种文本路径通过，首次截断仍单独保留；Codewise 降到 256 Token 后仍没有通过通用对话样例，不据此推断其专用补全接口是否可用。

详细报告在本机忽略目录 `artifacts/model-capability-audit/`：REPORT.md、report.html、matrix.csv、MATRIX.md、原始请求结果及各次复核记录。报告浏览器验证覆盖 204 行、115 来源筛选、34 个图片通过结果、7 个历史兼容错误、搜索和证据弹窗，无 JS 错误。产物与凭据不进入 Git。

没有逐型号验证长上下文极限、所有图片格式/URL/多图、并行/强制工具、严格 JSON Schema、长期稳定性、全部真实客户端或完整实际费用。本轮测试不证明底模身份。没有原生 Claude 账号来源，因此也没有完成该渠道的真实验证。
