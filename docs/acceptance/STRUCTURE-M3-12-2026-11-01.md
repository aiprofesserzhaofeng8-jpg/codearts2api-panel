# 摘要备用型号准备协调分离验收（M3 第十二批）

日期：2026-11-01。基线 `eccc57e`，版本 `0.3.0-structure-m3.12`。M3 尚未整体完成。

## 改动与边界

`gateway.PrepareSummaryAttempt` 接管摘要替换的准备顺序：强制型号、目录与同平台/地区约束、绑定账号的型号冷却、备用型号摘要选项、当前权限与预算进度、请求准备。server 通过 `SummaryTargetSource` 投影既有数据与请求上下文，授权仍单向委托原 `checkRequestBudget`；分组映射、原始型号白名单、Store 准入和账本没有拆出或复制另一份快照。首次准备不重复授权，同型号重试也复核首轮已发生用量；准备成功之前不开始新尝试计量。

`requestpolicy.PrepareSummaryModel` 处理已授权目标的协议外壳。更换型号时只删除顶层旧 `thinking` / `reasoning_effort`，再应用备用型号自己的已配置选项；未配置备用型号不继承旧型号的“关闭思考”能力假定。保持调用者较低的正数输出上限，工具内容、大整数、嵌套业务字段和未知字段保留。替换请求在同一原始 JSON 解析结果中删除旧选项，省去原先换型号时的一次重复解析与序列化。

既有 Go 文件只修改 `server/summary.go`，另外增加准备模块和边界测试。平台原生文件、accounts、app、Store、registry、protocol、普通推理执行和页面逐字节不变。继续复用同一账号、凭据、总期限和租约；最多一次截断重试，不新增网络请求、凭据解析、缓存或锁，也不扩展 WorkBuddy/Trae 的摘要能力。

## 真实请求

使用私有状态副本，关闭自动续期、桌面导入/回写和领奖。最终 13 项检查共 17 次真实生成尝试符合预期：三平台各两次普通生成、三组工具调用/回填、CodeArts 显式非流式与 Pi 流式摘要，以及两种真实备用型号场景。普通和工具实际型号为 `deepseek-v4.1-flash`、`workbuddy/cn/deepseek-v4.1-flash`、`trae/cn/deepseek-v4.1-flash`，公开统一名称、实际路由和用量可关联。

真实备用测试故意将客户端输出上限设为 1 Token：原始白名单不允许备用时，首轮截断后返回 403，实际仅调用 `deepseek-v4.1-flash`；允许备用时，依次调用 `deepseek-v4.1-flash`、`GLM-5.2`，两轮截断后返回 422。两种情况均未返回半截摘要，次数和真实用量已记录。这里验证了实际切换和拒绝，**不把 422 记作完整摘要成功**；备用型号完整交付由受控回归覆盖。

保留异常观察：初次 CodeArts 工具请求返回普通回答、没有 `tool_calls`；为核对工具选择，另一次显式 function `tool_choice` 探测被上游 HTTP 400 拒绝。随后冻结的 M3.11 与当前版本采用原有自动工具请求，闭环均通过；本批未改工具适配，也未把上述两次异常改记为通过。WorkBuddy/Trae 工具闭环通过。

所有隔离副本最终租约为 0、凭据未轮转，临时状态已删除，共享状态未改。自动续期仍关闭，本批没有做真实续期验收。

## 性能

重负载测试结束后，在同机 CPU 0/2、GOMAXPROCS=2 条件下，冻结前后测试二进制交替运行五轮。容量记录 90 条，涵盖普通三平台和摘要的单轮/重试；失败和剩余租约为 0，上游并发峰值为 2，调用次数保持 40/80（CodeArts 普通容量样本为 100）。各场景 p95 中位数变化范围 **-2.29% 至 +1.42%**。

17 组微基准包括普通三平台、统一名响应、关键计时、1 KiB/1 MiB 摘要及截断重试，五轮 ns/op 中位数变化范围 **-3.99% 至 +1.33%**。临时存储固定在 `/dev/shm`，生产持久化不变。具体绝对值、分配数和五轮样本见 [机器可读记录](STRUCTURE-M3-12-2026-11-01.json)。这些是假上游下的回归证据，不能保证真实平台延迟恒定。
