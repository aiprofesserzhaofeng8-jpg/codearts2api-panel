# 分阶段登录与凭据导入分离验收（M3 第八批）

日期：2026-11-01。基线 `f9f98dc`，版本 `0.3.0-structure-m3.8`。本批抽取 WorkBuddy/Trae 现有登录/导入协调；CodeArts 登录、其余账号管理及 M3 的其他职责仍待后续迁移。

## 改动与边界

- `accounts.ProviderLogins` 持有授权会话、检查、预览确认、取消、导入身份复核及保存协调。平台继续解释凭据，执行原授权/设备/回调和 Verify 协议；Store 保持原子查重和保存。
- app 注入 Store 窄接口和原随机 ID 函数；每次操作传入当前适配器注册表，避免测试或装配更新后引用旧平台实例。HTTP 仅保留原 wire DTO、256KiB 限制、身份脱敏及原响应/错误格式。
- 保留 30s 截止时间、10 分钟会话、128 会话上限、原会话互斥、默认 cn、预览指纹和回调快照。检查不保存；替换须显式确认；保存失败保留预览；重复保存复用账号；删除后旧授权不能恢复账号。授权结束按原时机清除内存凭据及释放原生登录状态。
- 不新增普通推理路径的调用、逐分片处理、凭据编解码、写盘或网络轮次。原生三平台、Store、gateway、upstream 和嵌入页面文件与基线逐字节一致；accounts 不导入 HTTP、Store 或原生平台。

## 自动与页面验证

`make check`、全量 `go test -race -count=1 ./...`、Windows vet/交叉构建、启动器 9 项测试、Pi 摘要回归通过。新增业务用例覆盖 12 路并发检查/确认、失败重试、替换、取消、TTL/容量、回调/身份/地区、设备绑定、当前注册表与截止时间、导入验证；HTTP 覆盖原状态/错误类型、鉴权/方法/体积、真实 Store 写盘失败恢复。既有 WorkBuddy/Trae 原生假上游与 CodeArts 登录回归仍通过。

隔离浏览器六组通过：providers、trae、trae-device、groups、account-create、growth-multi。二进制和非 root Docker 实例的登录、资源字节一致、独立 cwd 及重启恢复通过，容器 UID 为 10001。

初次新增的 WorkBuddy 夹具误用了未允许域名，修正为既有允许域名后重跑通过，生产代码未因此修改。旧 `login-smoke.cjs` 写死另一个端口且不读取隔离地址，未作为页面通过证据；保留该次失败日志，CodeArts 入口另由现有服务测试及 account-create 隔离用例覆盖。

## 真实请求及限制

在私有状态副本中关闭导入、自动续期、IDE 回写和领奖。WorkBuddy 与 Trae 普通流式/非流式共 4 次请求，以及两个平台各一组工具调用/回填共 4 次请求，合计 **8 次真实生成通过**；使用的实际型号为 `workbuddy/cn/deepseek-v4.1-flash`、`trae/cn/deepseek-v4.1-flash`，公开模型仍为分组映射名。普通请求核对输出、实际型号和真实用量；工具闭环核对参数和回填，租约归零。

CodeArts 当前保存的凭据已过期；本批 4 次网关请求（普通与摘要）未能完成，首个请求为 502，之后该隔离实例返回无可用账号。上一版同一凭据、同样关闭续期的独立实例首个请求也返回 502/没有可用凭据；原 Manager 在过期且不允许刷新时拒绝调用。这个前提未满足，因此不能宣称本批三平台真实验收全部通过，也没有借验收刷新共享轮转凭据。真实交互登录、刷新和领奖未执行，登录协议验证使用假上游。

初轮与内存目录复核的全部样本、分配和控制项均保留。现有证据支持没有稳定增加的请求处理开销；磁盘夹具仍有明显耗时波动，因此不能把其全部差值归因于本次改动，也不能承诺所有负载零开销。
