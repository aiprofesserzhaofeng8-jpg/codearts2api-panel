# 同一型号跨平台统一名称修正（2026-11-06）

## 问题

默认目录 v1 只为少数预设型号提供归并，其余条目增加平台前缀。本机应用后有 111 个定义，其中 glm-5.3-flash、kimi-k3.1-pro、mimo-v2.6-pro 等相同完整型号被拆成不同的用户名称，偏离跨平台同一模型共用一个名称的目标。

## 修正

- 默认目录 v2 对明确厂商型号格式采用完整上游 ID（大小写归一）作为公开名；保留版本、日期和变体后缀，不把 flash/flashx、普通/Official 或不同版本近似合并。
- CodeArts/WorkBuddy/Trae 的 glm-5.3-flash、kimi-k3.1-pro 各归并为 3 个来源；WorkBuddy/Trae 的 mimo-v2.6-pro、minimax-m3.1-flash 各归并为 2 个来源。
- auto、dfmodel、chat-pro、custom_model_* 等内部入口不从名称猜测具体厂商型号。
- 旧自动生成的平台前缀定义保留原调用路径和授权。当标准名称覆盖它的来源、启停状态和调用者权限时，默认列表隐藏旧入口。独立手动名称/策略保留；显式查看开关可显示兼容入口。
- 默认组选择器推荐标准模型，已有旧授权仍可编辑。原始平台目录明确标记为平台原始型号。
- 归并不重新启用旧已禁用来源，不删除旧客户端使用的名称，不修改账号凭据和分组授权。

## 验证

完整 make check 通过：56 项前端测试、100 项部署测试、完整 Go 测试、vet、API 类型同步和架构检查。catalog/storage/server 的统一模型及默认目录定向 race 通过，最后补充的停用来源保护单独通过 race。真实应用装配、模拟平台的浏览器回归通过。

从本机只读提取型号定义（没有复制凭据），在隔离状态副本演练后：111 个旧定义生成 98 个默认展示模型，48 个旧平台前缀定义保留为兼容入口；目标多平台来源数量断言通过。该演练没有发起真实生成请求。

发布包、离线维护辅助工具及回执位于忽略目录 artifacts/local-update-v0.4.2/。真实部署结果由其中 deployment-receipt.json 记录；源码验收不能代替运行实例确认。此批未发布 GitHub Release。
