# Pi 上下文配置实测（2026-11-24）

通过本地网关 `127.0.0.1:10087` 测试本批修改的 17 个入口，共完成 54 次推理请求（不含目录预检）。仅发送合成数字文本和随机标记；未修改服务、账号或客户端参数。

## 方法与证据含义

先执行短请求，再用 1,024 组数字校准上游 Token 数，发送接近配置窗口的长输入；第一轮校准包含固定提示词开销，实际输入可能低于目标，因此对成功项补测。输入首、中、尾分别放置随机标记，检查完整响应中的三个值。长输入输出预算为 2,048，补测为 8,192；这次没有测试配置的最大输出能力。

“通过”要求 HTTP 200、完整结束且三处标记全部找回。已验证输入量采用上游 `usage.prompt_tokens`；成功样本只证明该长度的检索能力，不等于测出了最大窗口。Kiro 及 Qwen 统一入口未返回用量，补测采用 `cl100k_base` 本地估算，不能与上游真实 Token 数混为一谈。超时不能证明不支持窗口；HTTP 400 缺少详细原因时也不归因为上下文超限。
