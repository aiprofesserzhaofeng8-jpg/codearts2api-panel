**发现与改进优先级**

| 优先级 | 发现 | 改进与验收条件 |

| P1 | CodeArts 非流式会把异常 HTTP 200 正文当成功，已复现 | 统一校验 JSON、choices/message、错误信封和结束语义。测试非 JSON、空 choices、200+error、提前 EOF；无效上游响应应明确失败，不增加成功数。合法 tool-only/refusal 等结果按协议处理，不能简单要求非空文本 |
| P1 | WorkBuddy custom 模式主动删除客户端 system/developer | 这是显式产品策略，不是透明中转。CLI 场景优先对照测试 passthrough；按密钥/分组细化策略，记录本次实际模式、清洗发生与降级原因，验证工具指令和用户约束未丢失；不要为了缓存牺牲请求语义 |
| P1 | 首 Token、错误来源与每次尝试结果缺少足够元数据 | 增加端到端 TTFB、首个有效文本/工具分片时间、上游连接等待、每次尝试时长/状态/原因、取消分类、策略版本；按平台/模型/协议/流式分组统计 P50/P95 |
| P1 | 新版三平台的真实工具闭环证据不足 | 用合成项目分别验证读文件→工具返回→下一轮、流式/非流式、取消、长上下文、令牌刷新；预先限定请求数与消耗；CodeArts/Trae 的外部搜索需配置真实服务后独立验收，不能写成原生搜索通过 |

**两个已复现问题**

2. 构造 enabled=true、status=ok、paused=true 的账号。实际 AcquireAccountForModel 无法取到账号，但 `codearts2api_accounts_ready` 返回 1。定位：[metrics.go](../../internal/server/metrics.go#L22) 与 [pool.go](../../internal/store/pool.go#L115)。

复现使用 Go overlay 添加临时测试，没有改动业务源码。完整输出见 [reproductions.log](evidence/review-2026-10-29/reproductions.log)，测试源见 [reproduction_test.go.txt](evidence/review-2026-10-29/reproduction_test.go.txt)。复现测试显示 PASS，含义是成功确认当前缺陷行为，不代表业务行为正确。
