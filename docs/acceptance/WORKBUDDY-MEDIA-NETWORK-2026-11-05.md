# WorkBuddy 图片与连接恢复验收（2026-11-05）

## 范围

补齐 WorkBuddy 上游图片能力到客户端配置的传递，修复 Messages 工具图片文本化和无效媒体静默删除。普通传输错误不累计账号失败，推理 HTTP 的请求体读取与下游写入具有单次 30 秒期限，失败取消请求并释放账号/密钥占位。保留可关闭的本地 QPS 限流及真实上游 429 分类。

## 验证

- `make check` 完整 Go 测试、vet、前端 45 项、接口生成、架构和部署测试通过。
- 相关 WorkBuddy/协议/目录/server race 回归通过，包含原短恢复、不可重放和冷却分类用例。
- 图片：Chat Completions、Responses、Messages 普通图片和 Messages 工具图片，流式/非流式共八个模拟端到端组合到达 WorkBuddy 出口时仍为 image_url，原始 data URL 保持不变。
- 能力：上游 supportsImages 的 true/false/缺失分别保存为支持/不支持/未知；公开列表、客户端推荐、统一名称能力交集及 Pi 配置检查通过。Python 启动器 10 项测试通过。
- 网络：在本地限流启用、密钥和账号并发为 1、熔断阈值为 1 的条件下，三种协议 × 流式/非流式 × 连接失败/断流后，下一请求可正常完成，无需清除错误或重启。失败不累计账号 Failures、无账号冷却、InFlight 归零。
- 下游：真实 TCP 客户端停止上传或停止读取响应时，使用缩短到 100ms 的同一连接保护实现验证超时取消；正常请求体读完清除期限，不影响后续长时间生成。写入与 Flush 错误均取消上游，结束时清除连接期限。

## 限制与部署

未使用真实 WorkBuddy 账号做图片推理，未取得用户原失败请求、具体型号和客户端，以上是已复现代码缺陷及模拟链路证据。图片支持不等于任意 PDF、音频、视频或生图能力；当前不支持的 Messages 媒体明确报错。

升级不会自动改写已有客户端配置；应刷新模型目录，并重新运行客户端启动器。旧连接故障造成的已有冷却需要按账号核对后清错，不批量清除真实限流或凭据故障。状态 schema 仍为 10，源码修改不等于运行中的系统服务已更新。操作说明见 [图片输入与网络恢复](../WORKBUDDY-MULTIMODAL.md)。
