# 中立账号与依赖装配验收（M3 第一批）

日期：2026-11-01。本批完成账号数据边界和平台依赖装配。M3 的 HTTP/业务拆分、CodeArts 统一适配包装尚未完成；独立前端和存储拆分属于后续阶段。

## 变更与兼容

- 基线为 M2 的 `8fc84cf`，原有三平台接口、请求参数、提示词、模型映射和页面资源保持原行为。
- `internal/accounts` 定义通用账号元信息和凭据代际错误，只依赖标准库。共享生产代码使用此类型；CodeArts 包保留一个源代码兼容别名。
- 不将 CodeArts 的 AK/SK、DPoP 等字段搬进通用账号。旧 `session` 槽暂持有只读接口，只有存储兼容编码器和 CodeArts 解释具体值；WorkBuddy、Trae 保留已有不透明 JSON 凭据。
- 状态读取时一次性恢复 CodeArts 会话，账号快照共享原不可变指针，原来的代际比较继续有效；请求中读取会话只做类型断言，不增加 JSON 解析或序列化。
- `internal/app.Build` 创建平台客户端、注册 WorkBuddy/Trae，并接入既有凭据条件提交回调。`server.New` 接收依赖；进程启动/关闭仍留在 main。
- schema 保持 6；选号、权限复核和租约占位仍是原有原子入口；不拆锁、不改变重试和超时预算、不改变结算账本。

## 性能与部署

结果见 [结构化验收数据](STRUCTURE-M3-1-2026-11-01.json)。同机、同工具链、固定上游延迟 20ms 的容量测试各三轮，p95 中位数为 22.384ms → 22.395ms，失败数和剩余租约均为零。选号和流式计时分配次数未增加。短分片初测波动超过 5%，因此使用独立新旧测试二进制交替五轮复测：3029ns → 3150ns（约 +4%，增加 121ns），均为 931B/20 次分配。本轮未发现明显的整体延迟增加，也不宣称所有微基准完全无损。
