# CodeArts 凭据运行时分离验收（M3 第十批）

日期：2026-11-01。基线 `4f4bc42`，版本 `0.3.0-structure-m3.10`。本批迁出 CodeArts 凭据协调，M3 尚未整体完成。

## 改动与边界

`accounts.CredentialRuntime[T]` 持有原按账号 mutex、短缓存、最新快照读取、条件提交和缓存失效。CodeArts Manager 内嵌这一运行时，保留原构造器及 Latest/Commit/Persist/Logf 回调入口；Session 单向委托，不再复制协调逻辑。泛型参数保持原生不可变 `*Session`，不序列化、反射或复制凭据，不新增平台注册表。

平台仍负责默认 TTL/提前量、IDE 会话读写、DPoP 续期、错误解释和凭据内容比较。原 resolve 主体除 Cached/Remember 调用名称外逐字节一致，手工/桌面账号构造不变；Store、HTTP、平台协议、upstream、gateway、protocol、requestpolicy 和页面的原有文件逐字节不变。WorkBuddy/Trae 仍用原不透明 JSON 与可取消通道锁，不合并锁域，也不要求新平台使用旧 Session 槽。

保留原顺序：账号 mutex → 取消检查 → 最新快照 → 原生解析/续期 → Store CAS → 更新调用者快照 → 记录短缓存 → 可选 IDE 回写。map 查找只短持总锁，网络调用只持对应账号锁；Invalidate 使用同一账号 mutex。等待 mutex 仍沿用原阻塞语义，取得后再检查取消；本批没有改为另一套锁。Store 保存失败仍保留已轮转的内存凭据，Commit 错误原样返回；旧 Persist 回调失败仍只记录日志。内容未变化不重复保存。

## 验证

`make check`、全量 `go test -race -count=1 ./...`、Windows vet/交叉构建、启动器 9 项和 Pi 回归通过。新增装配测试通过真实原生 Refresh、业务运行时和现有 Store，使用假令牌接口核对 refresh_token/PKCE 表单、DPoP 目标及原登录密钥的真实 ECDSA 签名。

16 路请求同时续期只调用一次令牌接口，并借用同一个新代际；写盘失败保留轮转凭据，重试及缓存失效后不再消费旧 token，目录恢复后可保存并重新加载；续期期间重新登录或删除账号均拒绝旧结果。原生测试补充零值 Manager、旧 Persist 失败、未变化不重复保存、取消以及 Invalidate 等待续期但不阻塞其他账号。既有同账号刷新去重、跨账号并行、永久 AK/SK、代际和浏览器登录回归继续通过。编译器逃逸检查确认新增委托闭包可内联且不逃逸。

六组隔离页面通过：providers、trae、trae-device、groups、account-create、growth-multi。二进制及非 root Docker 的登录、静态资源字节一致和重启恢复通过；二进制从独立 cwd 启动，容器 UID 为 10001。Windows 仅交叉构建，未执行 Windows 运行验收。SQLite/DPoP 内部实现本批不重写，条件依赖的桌面读取/回写验证没有因此自动补齐。

## 真实请求与限制

私有状态副本关闭导入、续期、IDE 回写及领奖。WorkBuddy、Trae 普通流式/非流式各一次，加上每个平台一组工具调用/回填，共 **8 次真实生成通过**。实际型号为 `workbuddy/cn/deepseek-v4.1-flash`、`trae/cn/deepseek-v4.1-flash`；响应保持分组公开名，普通请求核对真实用量与实际路由，工具闭环核对参数和回填，租约归零。临时状态退出后删除，共享状态和轮转凭据未改动。

当前保存的 1 个 CodeArts 账号凭据已过期，本轮没有执行真实续期、交互登录、领奖或重复发送已知前提不满足的真实生成。CodeArts 新运行时的签名、轮转、提交与故障恢复已在假上游通过，不能据此宣称华为真实续期通过；重新登录/正常续期及模型清单恢复仍待验证。另用同一真实账号状态副本分别启动本批旧/新二进制，关闭续期并将上游代理指向不可用端口；两版均在凭据解析处返回 502/没有可用凭据，凭据不变，临时副本删除。这是过期状态兼容验证，不是 CodeArts 真实生成通过。此前的过期前提与旧/新版本对照见 [M3.8 验收](STRUCTURE-M3-8-2026-11-01.md)。

## 性能

所有竞态、页面与真实检查结束后，再单独运行五轮交替对照；固定 CPU 0、2，`GOMAXPROCS=2`。容量夹具并发 2、上游等待 20ms；每轮 CodeArts 普通 100 次，其余八种场景各 40 次，90 条记录均成功，峰值 2，剩余租约 0。带计数的一次完成恰为 40 次调用，摘要截断重试恰为 80 次。
