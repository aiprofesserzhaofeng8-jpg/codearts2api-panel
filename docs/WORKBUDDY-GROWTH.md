# WorkBuddy 成长任务

账号池顶部选择「WorkBuddy」后，筛选框旁显示「成长任务」按钮。点击后打开独立弹窗，显示上游当前下发的任务、操作说明、进度、积分/能量奖励和领取状态。任务数量和奖励不写死为 17/18 或固定总额。

集中入口列出所有支持成长任务的 WorkBuddy 国内个人账号，不受账号表格的文字搜索或状态筛选影响；多个账号时可在弹窗选择「全部账号」或单个账号。原有账号行的「更多 → 成长任务」保留，直接打开该账号。

「领取奖励」操作单个已达标任务；「领取可领奖励」领取弹窗当前范围内的可领项。同一弹窗最多同时处理两个账号，每个账号内部逐项串行。某账号查询失败或领奖待确认时显示该账号的结果，其他账号继续；发生领奖错误或待确认后，该账号剩余任务停止，需刷新确认后再操作。

未报名、未达标、未解锁、已领取以及停用账号的领取按钮禁用，停用账号仍可查询。国际版和企业版不加入成长任务列表；没有支持的账号时集中按钮禁用。CodeArts 和 Trae 筛选下隐藏集中按钮。

## 当前范围

本阶段只查询成长进度和领取已经达标的奖励。查询不报名、不上报行为、不调用模型。未完成任务按上游说明在官方应用完成；还没有接入 17 项自动执行器、小程序专属任务、夜间排程或成长任务后台队列。

打开弹窗、切换弹窗内账号、点击刷新、领奖前后才查询任务；仅选择 WorkBuddy 筛选不会查询任务。关闭弹窗会停止后续排队操作，已经提交的请求仍可能完成；重新打开其他账号，迟到响应不会覆盖新账号的任务。没有后台轮询，双账号上限属于当前弹窗，不是跨浏览器的全局管理限流。

## 领奖确认

1. 在独立的账号任务锁内，重新读取该账号的上游进度；已领直接返回，未达标拒绝提交。
2. 仅发送一次 Web 成长中心领奖请求。网络错误、无效响应或业务拒绝均不自动重发。
3. 最多回查三次领取状态，回查间隔 300 ms。只有上游任务变成已领取才显示成功；否则显示待确认，提醒刷新。
4. 确认后刷新该账号的积分缓存，刷新最多等待 3 秒。余额查询失败不撤销已确认的领奖，也不把未知余额显示成 0。

领奖状态以上游为准，不使用每日签到的 `LastClaimDate`、`NextClaimAt` 等字段，也不新增本地状态文件或 schema 迁移。重启后重新查询真实进度。管理写操作沿用现有管理鉴权、同源校验和审计。任务失败不修改推理账号健康、密钥预算或用量账本。

## 接口与维护边界

| 接口 | 行为 |
| --- | --- |
| `GET /admin/api/workbuddy/tasks?id=<账号ID>` | 查询该账号默认口径任务，必须显式指定账号 |
| `POST /admin/api/workbuddy/tasks/claim` | JSON `{"id":"账号ID","task_code":"任务码"}`；重新检查进度后领取 |

成功的领取请求返回 `state=claimed` 或 `already_claimed`；`state=pending` 仅表示已提交、尚未确认，不能当作成功。响应包含最新任务列表；确认领奖后可附 `balance`，余额查询失败附 `balance_error`。查询失败返回明确错误，不能解释成没有任务。

| 文件 | 职责 |
| --- | --- |
| `internal/provider/growth.go` | 可选能力、任务及奖励结构 |
| `internal/workbuddy/growth.go` | WorkBuddy 查询/领奖协议、响应校验与进度解析 |
| `internal/server/growth.go` | 管理路由、账号校验、互斥、回查与余额刷新 |
| `internal/server/web/growth.js` | 弹窗状态、账号切换、两个账号的并行队列、同账号串行领取 |

前端复用现有主题变量，新增 CSS 限定在成长弹窗，不替换账号、分组、用量或登录页面。没有改动推理路由与 SSE 处理，但主动查询、领奖仍会产生上游管理请求，不能保证对任意网络和负载完全零影响。
