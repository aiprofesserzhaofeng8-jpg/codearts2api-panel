# WorkBuddy 成长任务

账号池顶部选择「WorkBuddy」后，筛选框旁显示「成长任务」按钮。点击后打开独立弹窗，显示上游当前下发的任务、操作说明、进度、积分/能量奖励和领取状态。任务数量和奖励不写死为 17/18 或固定总额。

集中入口列出所有支持成长任务的 WorkBuddy 国内个人账号，不受账号表格的文字搜索或状态筛选影响；多个账号时可在弹窗选择「全部账号」或单个账号。原有账号行的「更多 → 成长任务」保留，直接打开该账号。

「领取奖励」操作单个已达标任务；「领取可领奖励」领取弹窗当前范围内的可领项。同一弹窗最多同时处理两个账号，每个账号内部逐项串行。某账号查询失败或领奖待确认时显示该账号的结果，其他账号继续；发生领奖错误或待确认后，该账号剩余任务停止，需刷新确认后再操作。

「接取未报名任务」只登记当前范围内未报名、未锁定的任务，每批最多 20 项，不调用模型或制造进度。「执行成长任务」显示当前可执行项数，按领养、GLM 体验、对话次数的依赖顺序执行；仅剩指定模型体验任务时显示「执行对话任务」。也可点击单项的「解锁并领养」或「执行任务」。无需手工配置次数或模型，其他任务按官方说明完成。

接取同时校验总状态和 `data.results[]` 的单项结果；前置条件拒绝返回 409，并显示具体操作指引。批量接取报错后，页面自动回查一次实际状态，保留已确认接取的任务，不重发接取请求。接取不隐式执行领养或付费对话；应通过执行入口处理 `first_buddy` 前置条件。

`first_buddy` 是无需手动接取的活动任务：不显示「接取任务」，批量接取也会跳过，直接使用「解锁并领养」。接取失败只阻止本轮继续接取该任务，不会把真实执行入口一起禁用；执行前仍由服务端核对前置状态；仅模型任务读取付费检查点。

首次领养显示官方活动规则链接和默认未勾选的协议确认，作用于弹窗当前所选账号，刷新、切换账号或重新打开后重置。服务端重新核对已有 Buddy 与已同意协议状态；协议尚未同意且未显式确认时，在任何写操作和模型调用前拒绝。确认后最多提交一次活跃事件，等待 1.05 秒，再提交协议、领养并回查实际 Buddy 档案；只有领养确认后才继续依赖任务。此流程不调用模型。已有 Buddy 不重新上报或领养。

弹窗只滚动任务列表，操作进度、结果和错误固定显示在底部；刷新后明确显示任务数与可领奖励数。未完成的 `first_buddy` 指引优先展示。明确拒绝显示「操作未完成」，未知结果仍显示「待刷新确认」；没有可领奖励时按钮禁用并给出原因。

未报名、未达标、未解锁、已领取以及停用账号的领取按钮禁用，停用账号仍可查询。国际版和企业版不加入成长任务列表；没有支持的账号时集中按钮禁用。CodeArts 和 Trae 筛选下隐藏集中按钮。

## 当前范围

查询和领奖保持原行为，不报名、不上报行为、不调用模型。只有显式点击接取或执行按钮才产生相应操作。可执行任务如下，不能宣称已实现参考项目的 17/18 自动完成能力。

| 任务 | 实际执行 | 上限 |
| --- | --- | --- |
| `first_buddy` | 活跃事件上报、协议确认、领养并查询 Buddy 档案；成长奖励另外核对 | 最多 1 次上报，不调用模型 |
| `Model_chat_GLM5.2` | GLM-5.2 真实对话，核验完成响应及上游响应 ID 后报告该次对话 | 1 次 |
| `chat_5` | 按上游差额提交活跃事件，每次回查到进度增加才继续 | 最多 5 次上报，不调用模型 |
| 其他任务 | 接取、显示官方操作指引、刷新进度、领取已达标奖励 | 未接入自动执行 |

指定模型体验任务的每次对话最多输出 32 Token，会真实消耗积分，正常占用该账号的并发名额，并遵守现有「允许积分模型」开关。领养和 `chat_5` 按参考项目的活动上报方式执行，不依赖模型目录、积分模型开关或付费检查点，也不产生推理用量和密钥预算消耗；两者首次组合执行最多 6 次事件上报。单次对话超时取全局请求超时与 45 秒的较小值。模型必须已在当前目录中存在，不换账号或改用其他模型；没有模型请求自动重试。完成的对话及失败尝试均记入用量日志，`protocol` 和 `request_kind` 为 `growth`，不扣任意客户端 API 密钥的预算；未知用量保持未知。真实对话会更新账号的最近使用时间，任务查询、接取及领奖不制造推理统计。

需要官方客户端的创建任务、画布、模板、专家、技能等操作保留说明；捐款由用户在官方应用决定。没有接入小程序指纹、夜间排程或成长任务后台队列，不扩展到其他任务的桌面成功事件链。

打开弹窗、切换弹窗内账号、点击刷新、领奖前后才查询任务；仅选择 WorkBuddy 筛选不会查询任务。关闭弹窗会停止后续排队操作，已经提交的请求仍可能完成；重新打开其他账号，迟到响应不会覆盖新账号的任务。没有后台轮询，双账号上限属于当前弹窗，不是跨浏览器的全局管理限流。

成长任务执行另有服务端全局上限 2，同账号与接取、领奖共用任务锁。活跃上报后最多回读 4 次原生进度，间隔 3 秒；上游进度一旦增长立即继续。未知结果本轮不重报，用户下次显式执行仍先查询实际差额。关闭弹窗会取消执行请求，服务端停止后续对话和排队任务；已经发出的模型请求仍可能扣费。进度读取失败、未增长或对话/上报结果不明时停止该账号，其他账号继续。

只有付费模型任务在执行前将检查点原子保存到状态文件旁的 `<state.json>.growth.json`（0600，不含凭据）。上游进度没有增长时，刷新或重启都不会重放该次对话；进度增长或达标后自动解除阻止。记录损坏或无法保存时停止新付费对话，正常模型请求、查询及领奖仍可使用。该文件应与状态文件一起备份，不应为重试而直接删除。

领养结果未知时停止依赖任务。重新显式执行会先重新读取已有 Buddy 和协议状态；仍未领养时，本次最多重新提交一条活动上报。历史版本的未确认前置对话记录保持原样，不删除、不重放，也不阻塞活动上报流程。领养 POST 即使报错，也只通过最多三次查询核对是否生效；本轮不自动重发。`prepared` 只表示 Buddy 档案已确认，不表示成长奖励已经领取。

## 领奖确认

1. 在独立的账号任务锁内，重新读取该账号的上游进度；已领直接返回，未达标拒绝提交。
2. 仅发送一次 Web 成长中心领奖请求。网络错误、无效响应或业务拒绝均不自动重发。
3. 最多回查三次领取状态，回查间隔 300 ms。只有上游任务变成已领取才显示成功；否则显示待确认，提醒刷新。
4. 确认后刷新该账号的积分缓存，刷新最多等待 3 秒。余额查询失败不撤销已确认的领奖，也不把未知余额显示成 0。

领奖状态以上游为准，不使用每日签到的 `LastClaimDate`、`NextClaimAt` 等字段。主状态 schema 保持 v5；执行器检查点独立保存。重启后重新查询真实进度。管理写操作沿用现有管理鉴权、同源校验和审计。任务失败不修改推理账号健康和密钥预算；真实模型尝试按实际结果记入用量账本。

## 接口与维护边界

| 接口 | 行为 |
| --- | --- |
| `GET /admin/api/workbuddy/tasks?id=<账号ID>` | 查询该账号默认口径任务，必须显式指定账号 |
| `POST /admin/api/workbuddy/tasks/claim` | JSON `{"id":"账号ID","task_code":"任务码"}`；重新检查进度后领取 |
| `POST /admin/api/workbuddy/tasks/accept` | JSON `{"id":"账号ID","task_codes":["任务码"]}`；查询归属、接取后回查确认，每批 1–20 个不重复任务 |
| `POST /admin/api/workbuddy/tasks/run` | JSON `{"id":"账号ID","task_code":"任务码","agree_buddy":true}`；协议已同意时可省略 `agree_buddy`，只接受本地白名单任务，前置依赖/活动上报或真实对话/核验领奖，单任务最多 240 秒 |

成功的领取请求返回 `state=claimed` 或 `already_claimed`；`state=pending` 仅表示已提交、尚未确认，不能当作成功。响应包含最新任务列表；`completed_reports` 表示已确认提交的活动事件数，不能解释成完成对话或已获得奖励；`completed_calls` 只统计实际模型尝试。确认领奖后可附 `balance`，余额查询失败附 `balance_error`。查询失败返回明确错误，不能解释成没有任务。

存在未领的 `first_buddy` 时，显式查询可返回 `buddy={owned,agreed}`；状态读取失败附 `buddy_error`，不伪装成未领养。执行前仍重新核对。`agree_buddy` 为本次请求授权，不写入网关全局设置或其他平台账号。

| 文件 | 职责 |
| --- | --- |
| `internal/provider/growth.go` | 可选能力、任务及奖励结构 |
| `internal/workbuddy/growth.go` | WorkBuddy 查询/领奖协议、响应校验与进度解析 |
| `internal/workbuddy/growth_actions.go` | 本地执行白名单、官方操作指引、接取协议、真实对话及相应报告 |
| `internal/workbuddy/growth_activity.go` | 活动事件格式与维护请求头，仅发往 billing 域，不调用模型 |
| `internal/workbuddy/growth_buddy.go` | WorkBuddy Buddy 档案、协议与领养协议调用及严格状态校验 |
| `internal/server/growth.go` | 管理路由、账号校验、互斥、回查与余额刷新 |
| `internal/server/growth_actions.go` | 接取/执行编排、并发名额、正常用量记录、进度核验与自动领奖 |
| `internal/server/growth_buddy.go` | 领养前置编排、同意检查、活动上报、所有权确认和依赖放行 |

| `internal/server/web/growth.js` | 弹窗状态、账号切换、两个账号的并行队列、同账号串行领取 |

前端复用现有主题变量，新增 CSS 限定在成长弹窗，不替换账号、分组、用量或登录页面。没有在正常推理路由与 SSE 处理中加入任务轮询或文件读取；公共日志函数仅增加错误返回值供执行器停止后续消费。指定模型任务会占用账号正常并发；活动执行、主动查询和领奖会产生上游管理请求，不能保证任意负载下零影响。

协议参考 [workbuddy2api-panel tasks.go](https://github.com/linguo2625469/workbuddy2api-panel/blob/73a7560efc7a88ebd9865db4c71ae7f6d85859f8/internal/upstream/tasks.go)，保留 MIT 许可和版权说明于 `LICENSE.workbuddy`。不依赖该项目的账号池、调度器或前端。

活动上报固定发往 WorkBuddy billing 域，Buddy 档案、协议和领养发往 copilot 域；这四类维护请求使用参考项目的独立请求头，不改普通推理、每日签到或其他平台协议。只有明确匹配 `first_buddy task not completed yet` 的业务错误才显示领养门槛提示；其他失败保留 HTTP/业务码，不把所有拒绝都解释为前置条件不足。协议与活跃执行还参考同一提交的 `report.go`、`travel.go`、`autotask.go`。
