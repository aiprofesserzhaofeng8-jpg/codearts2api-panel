# ADR 0018：全局统一模型与来源授权

日期：2026-11-05。状态：U1 设计采用，运行实现待 U2–U6。

本 ADR 定稿 [统一模型计划](../architecture/UNIFIED-MODELS-PLAN.md) 的 U1。具体字段、解析顺序和 API 以 [契约 v1](../architecture/UNIFIED-MODELS-CONTRACT.md) 为准，迁移以 [迁移与验收](../architecture/UNIFIED-MODELS-MIGRATION.md) 为准。相关范围覆盖 ADR 0010 的分组映射归属，不修改其提示词规则。

## 依据

唯一外部参考为 LiteLLM：客户端 `model_name` 与实际部署的型号分离，同名部署形成候选集合，凭据可复用。参考 [路由文档](https://docs.litellm.ai/docs/routing) 和 [模型管理](https://docs.litellm.ai/docs/proxy/model_management)，核对日期 2026-11-05。本次没有复制第三方源码或引入依赖；后续若复制实现必须另外固定提交和记录许可。

代码基线中，`access.AccountGroup.ModelMappings` 同时承载定义和授权；`catalog.MappingPlan` 只查当前组，导致不分组密钥不能使用别组的统一名称。`storage.AcquireMappedAccount` 已有跨来源的原子选号入口，可直接扩展。目录、策略、定价、协议、账号无需重建。

## 决策

1. 全局存储统一模型；一个稳定 ID 和公开名称对应 1–16 个原始来源。分组只持授权引用、来源范围及账号范围。
2. 统一模型的纯配置类型放 `config`；解析与管理协调归 `catalog`；权限值归 `access`；持久化和原子准入归 `storage`。`access`、`scheduler` 继续不依赖其他内部业务包。
3. 来源用具体 ID 引用唯一 Registry，CodeArts 对外来源 ID 为 `codearts/<原始型号>`，其他平台沿用 `<平台>/<地区>/<原始型号>`。内部原始型号、定价键和健康键不因此整体改名。
4. `um_` 开头的稳定 ID 与公开名称创建后不可直接修改。编辑来源/启停用 revision CAS。要改公开名称，创建新定义、显式迁移引用，再移除旧定义；本轮不新增统一模型别名系统。
5. 每个分组的统一模型授权采用显式列表，未列入即拒绝。来源范围为 `selected` 或 `all`；`selected: []` 拒绝所有来源。旧分组迁移为固定来源列表；不分组密钥允许全局已启用定义，沿用既有准入和预算。
6. 原始型号的白名单/规则继续独立控制原始调用，并作为统一模型来源的约束。公开名称禁用不等于禁用其原始来源，沿用 ADR 0010；界面必须说明二者区别。
7. 同名同来源旧映射才可自动合并；同名不同来源、与原始短名/自定义/内置别名冲突均阻止自动迁移，不取并集、不覆盖。
8. 保留现有原子选号、预算占位、重试上限和错误分类；不能把 `scheduler` 当有状态服务，也不增加候选循环外的重试层。模型定义或策略在执行前变化，旧计划按契约拒绝，不能套用旧能力声明。
9. 统一模型能力来源于适配器与型号元数据，未知不宣称支持。公共 profile 以授权后的配置来源计算，不能随临时冷却扩张上下文。统一模型缺少 profile 不等于不能执行普通 API 请求。
10. 复用现有原始型号计价和历史日志，公开名只作请求标识。原始价格未知仍为未知，不复制某一来源价格到整个统一模型。
11. 新定义与权限使用 schema 11。跨 schema 升级是显式迁移入口；普通升级继续拒绝未经支持的跨版本切换，不能删除其校验。
12. 目标是兼容接入统一模型，不是替用户猜测底层模型，也不引入自动跨模型替换或自动改写客户端文件。

## 对实施计划的细化

- 候选模型定义由 `catalog` 解析，但租约与实际型号选择继续在 `storage` 的原锁中；`scheduler` 只计算选择结果。
- 分组授权新增显式引用，与原始 `ModelRules` 分开，避免同一字符串兼任公开名、原始 ID 和稳定 ID。
- `ModelPolicies` 继续是策略唯一存储；统一模型策略键固定为 `unified/<model_id>`，不把上游策略复制到新对象。
- `ForceModel` 与任何全局统一模型定义互斥，包含已禁用定义；在空统一目录上保留原强制模型路径。默认模型只处理空请求，客户端偏好只用于推荐。
- 上线迁移必须覆盖部署工具。目前 `panelctl.py upgrade` 仅允许相同 schema，U2/U6 要增加受限的 10→11 迁移能力，而非宣称现有升级已支持。
- `/v1/models` 现有 stale 刷新可能查询上游目录。本轮保留这条原有机制，不增加推理探测或将网络查询放进名称解析；“无新增网络调用”不等于“现有列表完全离线”。

## 接受的取舍

来源确认仍需管理员参与，不能通过字符串相似度或模型自述合并。能力不明的来源可能不能承接统一名称下的图片/工具请求，原始调用兼容行为仍由原适配器控制。固定旧分组来源会增加一次显式授权操作，但避免后来添加平台扩大权限。

不采用“每组维护一份全量模型定义”“为每个账号复制模型凭据”“新增网关服务”“直接用公开名替换价格和健康索引”。这些做法分别造成重复配置、凭据冗余、双重调度或计量语义变化。

## 验收与状态

U1 验收只证明设计契约、基线与迁移矩阵完整，不证明新路由已实现。U2–U6 的自动化和实测证据不得由本 ADR 替代。执行入口和结果见 [U1 验收记录](../acceptance/UNIFIED-MODELS-U1-2026-11-05.md)。
