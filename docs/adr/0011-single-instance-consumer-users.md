# ADR 0011：单实例普通用户与共享预算

日期：2026-11-02。状态：已采纳并实施。

## 问题与范围

M6 的分组约束密钥可以用哪些账号和模型，但分组不是用户身份，不能据此授权密钥管理或用量读取。本轮用户选择 M7 方案 1：单实例多用户。暂不引入数据库、多副本、跨进程刷新/租约或多个平台凭据所有者。

## 决定

沿用一个管理员角色，增加普通使用者 `access.User`；上游账号继续由管理员持有。普通用户强制绑定一个分组，所有密钥保存稳定 `user_id` 并跟随用户分组；原有无归属密钥保持原义。用户停用而不物理删除，避免历史归属和预算消失。

`access.Users` 管密码验证、有限并发慢哈希和摘要索引的随机会话；`storage` 唯一管理用户/密钥事务、权限复核、共享预算、日志归属和落盘。用户会话使用独立 Cookie、revision 和同源检查，认证后每次读取当前启用状态；不缓存第二份权限。API Key 不授权用户控制台，用户 Cookie 不授权管理员。

原子选号仍在原 storage 锁中复核密钥、用户及当前分组；预算沿用请求预留与软结算语义，在原 budgetActive 中以独立用户前缀累计，不增加另一把准入锁。请求认证捕获不可变用户 ID，请求结束前写入原结算账本；删除密钥不会让在途消耗丢失归属。用户预算可独立重置，预算变更与在途预留互斥。

用户用量先按稳定用户 ID 过滤，再脱敏、统计和分页。沿用全实例 100000 条历史保留；预算累计不依赖历史保留或当前密钥。平台账号/原始错误/尝试凭据信息不向用户暴露。

前端管理员新增独立响应式 UsersPage，普通 `/user` 使用 UserConsole，二者不接管遗留控制器的 DOM。接口集中到现有 OpenAPI，生成 TS 类型。三平台原生协议、凭据刷新、提示词和成长任务逻辑不修改；推理热路径不计算密码哈希，不逐 SSE 帧增加用户操作。

## 代价与约束

用户和密钥数有明确上限，读取用户采用原锁内线性查找，避免为当前容量添加缓存失效机制。密码工作最多两个并行；会话有固定总量和逐用户上限。Token / USD 限额使用户跨密钥最多一个在途，属于显式预算语义；不限额用户继续使用已有账号池并发。

这是管理员分配共享资源的使用者隔离，不是租户数据库或硬计费系统。共享账号池的容量、历史保留和管理员权限仍是实例级。已开始请求不强制终止，密码重置不撤销 API 密钥。需要独立租户凭据或多副本时另立阶段，先验证权限、预算、刷新、任务和租约的共享协调。

schema 8 阻止旧程序忽略用户权限。兼容导出只接受完全没有用户/归属/归属历史或待结算记录的最新状态，并复制最新账本；其他情况必须向前修复，禁止恢复旧轮转凭据。

## 验证

证据见 [M7 完整验收](../acceptance/STRUCTURE-M7-COMPLETE-2026-11-02.md)：跨用户拒绝、停用/改密/退出、当前分组复核、跨密钥预算并发、删除密钥后结算、账本重放、三平台三协议流式与非流式、真实浏览器流程、迁移与拒绝降级、性能和有界真实上游验收。
