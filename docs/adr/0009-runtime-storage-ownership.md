# ADR 0009：准入协调与存储事务共用一个状态所有者

日期：2026-11-02。状态：已实施（M5）。

## 背景

M3 已迁出请求编排及管理业务，原 Store 仍混合状态事务、选择算法、用量计算与兼容格式。把锁和状态分别搬入 gateway、accounts、usage 会拆开权限检查、选号、并发占位及结算的原子边界，也会增加锁顺序和重复快照的维护成本。

## 决策

- `gateway.Admission` 经使用方定义的 `AdmissionStore` 协调预算预留、请求检查与尝试准入。普通推理、外部搜索和成长付费动作共用同一实现，分别保留原有检查顺序。
- `scheduler` 只执行纯选择规则。storage 在原临界区内提供逐项读取回调，不复制候选、不缓存权限；黏性、冷却和 in-flight 仍由 storage 持有。
- `storage.Store` 是状态、锁、租约、预算预留、凭据 CAS、账本及文件提交的唯一所有者，实现各业务的窄接口。权限复核、实际型号选择和占位在同一次事务内完成。锁顺序仍为 `saveMu -> journalMu -> mu`。
- `usage` 定义用量、日志、价格和分析 DTO，执行纯成本估算及报表查询；`access` 定义预算检查与密码规则。持久化、累计计数和账本恢复留在 storage，不能异步替代已提交结算。
- `store` 只保留旧 Go 类型别名和单向委托；生产依赖检查禁止其他包导入该门面。HTTP 的具体存储读写适配暂时仍使用 storage，业务模块只依赖自己的接口，不建立包含所有方法的大接口。
- 共享账号的 `NativeCredential any` 只承载旧 CodeArts 不可变代际，不再要求所有平台实现同一凭据方法集。schema 6 的 `session` 键由兼容编码器一次解码，平台仅作类型断言；WorkBuddy/Trae 保持原不透明 JSON。新平台不得继续扩展旧槽。

## 快照与失败语义

请求计划是预检结果，实际准入必须在锁内重读当前权限。管理接口成功返回后，新尝试使用新状态；严格保存失败回滚后不发布候选。已开始的租约仍可在账号删除后幂等释放。账号快照复制元信息和外部凭据字节，共享只读 CodeArts 代际；设置别名、分组和映射等可变容器沿用原复制边界。

本阶段不引入编译权限缓存、配置版本服务或无锁发布机制。严格管理事务仍可能在原状态锁内等待磁盘；历史全局设置/启停的“更新内存、保存失败只记日志”也保持原样，不能笼统宣称所有更新都有持久化后发布保证。日志历史的外层切片是副本，其嵌套只读记录仍按原约定使用。

轮转凭据保存失败保留新代际，旧代际不能覆盖；账本写入失败保留内存用量并阻止新推理，成功保存后恢复。没有改变重试、超时、缓冲、同步写盘、schema 或上游调用次数。

## 取舍与后续

这是对原设计“gateway 持有独立运行视图”的收敛：协调和事务分属不同模块，但状态只有一份。源码迁移文件较多，事务函数体和原生协议保持原语义。引入数据库或多实例时必须实现等价的原子接口和故障测试，不能把当前单进程锁当成分布式保证。

映射预设/默认项、可见与可调用开关、公共提示词继承归 M6；数据库、跨进程租约和多用户归 M7。实测及限制见 [M5 验收](../acceptance/STRUCTURE-M5-COMPLETE-2026-11-02.md)。
