# 多上游开发版：码道、WorkBuddy 与后续 Trae

此功能位于 `develop`，版本 `0.2.0-dev`。`v0.1.0` 标签固定原码道版本。

## 使用入口

账号池保留「码道登录」，增加「添加 WorkBuddy」。WorkBuddy 可选择国内或国际地区：

1. 生成授权链接。
2. 复制链接到另一个浏览器登录；面板不自动导航、不自动保存账号。
3. 返回点击「检查授权信息」。回调地址可选，但如填写必须匹配本次 state。
4. 核对账号预览，点击「确认保存账号」。已有同地区账号须明确确认覆盖。

也可在该窗口导入 WorkBuddy 的扁平 JSON 或 `auth` / `account` 嵌套凭据；包含访问令牌、续期令牌、过期时间和 UID。导入先向官方账号接口核对身份，再原子保存。凭据不会出现在账号列表或普通 `/v1/*` 接口中，只有管理员显式导出才能得到完整值。

没有自动搬迁另一个 WorkBuddy2API 服务的账号。对使用一次性轮转 refresh token 的同一份登录凭据，应确定由哪个网关负责续期，避免两个独立进程争用。同一服务内部通过账号锁与代际检查协调刷新。

## 模型路由

| 请求模型 | 目标 |
| --- | --- |
| `deepseek-v4.1-flash` 等原有裸名 | 码道，保持原客户端行为 |
| `codearts/deepseek-v4.1-flash` | 显式码道，转换为原上游模型 ID |
| `workbuddy/cn/<上游模型ID>` | WorkBuddy 国内账号 |
| `workbuddy/global/<上游模型ID>` | WorkBuddy 国际账号 |
| `trae/...` | 尚未接入，拒绝调用 |

WorkBuddy 模型来自该地区的上游目录，不在没有账号时虚构可用模型。保存账号后面板会刷新目录，也可手动刷新。各上游刷新结果独立保留；一个目录更新不会覆盖另一个上游或地区。

三种客户端接口共用提供方路由：`/v1/chat/completions`、`/v1/responses`、`/v1/messages`。对外模型名带前缀，发给 WorkBuddy 的模型名去掉前缀。选号、粘性会话、凭据和健康状态按上游及地区隔离；明确前缀不能通过别名或强制模型静默转到其他上游。

## 用量与价格

账号池和用量页提供上游筛选。新请求记录 `provider` / `scope`；旧记录缺省视为码道。WorkBuddy 国内和国际的模型价格以完整模型名分别设置，不继承码道同名模型价格。上游 usage 缺失时继续按现有规则标记未知，费用预算不会把未知成本算成免费。

WorkBuddy 的个人积分包可读取；企业积分和达到查询分页上限的情况明确显示未提供完整额度，不伪造零余额。现有活动领取功能仅作用于码道，WorkBuddy 的签到、成长任务、福利暂未接入。

客户端推荐参数可从 WorkBuddy 返回的上下文/输出元数据生成保守建议；没有元数据时不猜测。WorkBuddy 默认不启用码道专用摘要改写；管理员也不能配置跨上游的摘要备用模型。Pi 的码道恢复适配不会错误应用到带 WorkBuddy 前缀的模型。

## 开发边界

- `internal/provider`：上游无关的模型、身份、请求、错误和 Adapter / BrowserLogin 接口。
- `internal/workbuddy`：原生 HTTP、授权、续期、模型目录、流式响应与积分读取；固定官方端点，不接受凭据 JSON 指定任意请求主机，拒绝携带凭据的重定向。
- `internal/server/providers.go`：适配器注册、凭据续期协调、统一转发及模型刷新。
- `internal/store`：按 provider/scope/external_id 区分账号；新 credentials 为独立不透明 JSON，不把 WorkBuddy token 填进码道 AK/SK。
- 码道沿用已验证的签名、桌面登录态及 Manager 路径；旧账号结构所在包名暂时保留，以减少迁移改动。

后续 Trae 需要基于实际协议实现 Adapter；如采用设备授权，再实现 BrowserLogin。还需增加该上游的导入身份核对、错误分类、协议测试和真实账号验收。界面显示「待接入」不代表已有转发能力。

## 验证与迁移

状态格式升级到 schema 3，旧记录字段自动补默认语义；版本 0.1 的程序会拒绝读新版文件。升级前备份，回退需同时处理状态版本，且不得盲目恢复已经轮转过的旧令牌。

自动化覆盖：三种 API 的流式/非流式请求、provider/地区选号隔离、命名空间模型路由、用量过滤、登录预览和显式保存、重复确认与删除后重放、导入身份检查、续期并发和取消、凭据快照/CAS、错误脱敏、重定向拒绝和截断流不重放。

界面验证：`CODEARTS_TEST_BASE=http://127.0.0.1:10088 node scripts/providers-smoke.cjs`，使用模拟数据，不添加真实账号。原码道测试也必须继续通过。

本次已验证国内与国际官方设备授权入口可返回合法链接。当前本机 WorkBuddy auths 目录没有账号凭据，因此尚未执行真实 WorkBuddy 模型生成、额度和到期续期验收；请在新入口添加账号后再做实际验证。
