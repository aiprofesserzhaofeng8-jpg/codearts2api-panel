# 全局统一模型与分组授权

当前格式为 schema 11。统一关系在“模型”页维护一次；分组只分配账号、模型及来源权限。不分组的管理员密钥也能识别全局模型，实际调用仍取决于启停、账号、能力、额度及并发。

默认使用“模型 → 默认模型目录 → 一键配置默认模型”。预览汇总 CodeArts、WorkBuddy、Trae、Qoder、Kiro、ChatGPT、Claude、TeleAgent 当前真实目录中的型号，支持搜索、平台筛选和批量应用。未接入或未刷新出目录的平台不会凭空生成可调用来源。

版本 2 按完整、带版本的厂商型号标识归并各平台来源，保留全部版本/变体后缀；大小写不产生新的模型。明确对照表处理已知历史名称。各平台同型号归为一个公开名，例如 `deepseek-v4.1-flash`。Qoder 的 auto/内部型号、TeleAgent 的 chat-pro 等未确认对应关系保留平台前缀，不冒充其他模型；未知上下文、图片和工具能力保持未知。这里的默认表版本管理预设规则，不是把所有请求强制交给一个默认模型。

应用前可选择同时授权到某个分组：仅给该组尚未授权的模型添加其账号和原始白名单允许的固定来源；已有授权、禁用和固定范围保持。未选组时仅保存全局目录，不分组密钥可用。新增来源需要扩大已有固定授权时，仍在分组页显式调整。

重复应用只追加来源，保留已有模型 ID、公开名称、停用状态和客户端策略。旧 `deepseek-4.1-flash` 定义会被复用，避免改名使客户端失效。目录或配置变化后旧预览会被拒绝；整批及可选分组授权在一次事务中保存，失败不会留下一半配置。

## 手动配置与调整

1. 在账号池添加账号并刷新目录。
2. 打开“模型 → 全局统一模型”，可手动创建公开名，从真实目录选择准确来源。每个平台/地区最多一项；公开名创建后固定，换版本应新建定义。
3. 客户端策略缺省取所有启用且授权来源的保守公共建议；缺资料时补齐原始模型的上下文/输出参数，不能凭名称猜测。来源从目录消失时保留配置，单独标记缺失。
4. 打开“账号分组”，选择账号和已有全局模型，分别设置可见/可调用；展开来源限制，选择固定来源或跟随全部。固定空集表示禁止。启用原始白名单时，来源同时受原始白名单和调用规则约束。
5. 设置请求默认和客户端偏好，再将密钥绑定到组。普通用户的密钥沿用其用户分组。

分组不能各自为同一名称重新定义来源。旧“添加映射 / 应用映射预设”编辑入口已撤下，管理接口拒绝旧 `model_mappings` 写入。迁移同名不同来源的旧组会报告冲突，管理员须明确解决，不自动合并。

## 调用与列表

```json
{
  "model": "deepseek-4.1-flash",
  "messages": [{"role": "user", "content": "你好"}],
  "stream": true
}
```

Chat Completions、Responses 和 Anthropic Messages 共用公开名称解析。响应保留公开名；运行日志记录“请求名称 → 实际型号”，费用、健康和尝试明细使用真实上游型号。

`GET /v1/models` 按授权展示公开名并去重；已覆盖的来源默认不重复推荐。列表是目录投影，不在读取时发送付费探测，也不保证账号此刻可用。`GET /v1/client-profile?model=...` 返回同一解析结果的参数；缺少必要资料返回 422，而非猜测上下文。

## 独立权限与默认值

| 设置 | 作用 |
| --- | --- |
| 可见 false、可调用 true | 列表隐藏，显式公开名仍可调用 |
| 可见 true、可调用 false | 列表可见，调用返回 403 |
| 固定来源 | 只使用所选来源；未来新增来源不自动进入 |
| 全部来源 | 跟随全局新增来源，仍受组内账号及原始 ACL 限制 |
| 固定来源为空 | 禁止调用，不能解释为全部 |
| 请求默认模型 | 只填补空 model，不替换显式或未知名称 |
| 客户端推荐模型 | 仅作客户端偏好，不改变显式请求和推理默认 |

原始型号可以隐藏但继续直调，例如 `workbuddy/cn/deepseek-v4.1-flash` 或 `codearts/deepseek-v4.1-flash`。完整型号有独立授权；没有统一模型 grant 不等于允许或禁止所有原始调用。分组 `raw_model_mode=qualified_only` 时，原始调用必须使用完整 ID；`legacy` 保留旧裸名解析。两种模式都不能绕过账号、白名单与调用规则。

停用统一模型不删除分组引用，也不自动禁止原始型号直调。固定授权仍引用某来源时，先调整组授权再删除来源；也可只禁用该来源。全局强制模型与非空统一模型目录互斥。

## 版本化管理接口

管理员先读取 `GET /admin/api/unified-models`，获得 `models` 及 `routing_revision`。创建、修改、删除均传读取时的版本条件；详情中的 `model.id` 是固定标识，`model.revision` 是定义版本。接口形状见 [完整契约](architecture/UNIFIED-MODELS-CONTRACT.md) 和 `api/admin.openapi.yaml`。

更新已有组时传该组的 `expected_revision`，统一授权使用如下结构（其余组字段略）：

```json
{
  "expected_revision": 1,
  "unified_models": [
    {
      "model_id": "um_11111111111111111111111111111111",
      "visible": true,
      "callable": true,
      "source_mode": "selected",
      "source_ids": ["workbuddy/cn/deepseek-v4.1-flash"]
    }
  ],
  "raw_model_mode": "qualified_only",
  "raw_models_visible_default": false,
  "default_model": "deepseek-4.1-flash",
  "client_default_model": "deepseek-4.1-flash"
}
```

使用真实定义 ID 和最新 revision；示例不是可直接提交的完整组对象。公开名显示/调用设置放在 grant，原始型号规则继续使用 `model_rules`。发生 409/428 时页面保留草稿，明确重新读取后核对，不能自动覆盖新配置。

## 调度、计量和恢复

- storage 在同一事务内复核当前权限、选择原始型号并占位，复用原并发和会话粘性；没有第二套权限缓存、锁或重试循环。
- 首段前按既有总次数和总期限有限切换，首段提交后不重放；取消后释放租约。重试前再次复核来源、组内账号和预算。
- 每次尝试从原请求重新准备，使用实际平台的提示词策略；不复用上个平台修改过的请求。见 [提示词配置](PROMPT-POLICY.md)。
- 图片和工具只交给明确支持它们的来源；无匹配则拒绝，不静默丢弃内容。一次文本探测不证明图片/工具能力；页面结果不冒充持久化探测历史。
- 统一名称不创造思考、摘要、搜索等能力；同平台摘要备用模型仍受授权限制，搜索沿用原独立入口。
- 用量按唯一逻辑请求结算，包含实际尝试明细；物理型号价格不改为公开名价格，历史费用不重算。

安装包中的 [统一模型运维说明](../deploy/UNIFIED-MODELS.md) 包含 10→11 预检查、显式受管升级、`recover-schema` 向前恢复和诊断。旧程序拒绝新 schema；不能手改版本或用旧备份覆盖新凭据/账本。

历史分组映射实现见 [2026-11-01 验收](acceptance/GROUP-MODEL-MAPPING-2026-11-01.md)，它的旧写入接口不再作为当前使用方法。

## 名称兼容

公开名称可与原始型号/内置别名同名，也允许 `qoder-auto` 这类没有数字的产品名。完整原始 ID 始终直达原始型号；有该统一模型授权的调用者和不分组密钥优先使用公开定义。旧 legacy 分组未获该定义授权时保留已有原始裸名解析，仍受原始权限检查；显式禁用的统一授权不能回退绕过限制。自定义别名占用名称时须先处理别名。

此更改不改变状态字段布局；应用新名称后不要退回不接受这些名称的旧程序。旧 10→11 离线迁移继续采用原来的严格冲突检查，不自动抢占旧名称。

## 版本 2：一个型号，一个用户名称

例如 CodeArts、WorkBuddy、Trae 的 glm-5.3-flash 共同归入 `glm-5.3-flash`；Kiro 和 Trae 的 glm-5 共同归入 `glm-5`。带日期、Official、flashx 等不同后缀仍作为不同型号，不按名称近似替换。平台内部代号/auto/custom_model_* 不凭猜测改成具体厂商型号。

已应用版本 1 时，再执行“归并同名模型”，会建立多来源的标准名称。旧的自动生成平台前缀名称继续可调用，保持已有客户端配置；当相同授权范围内的标准模型覆盖这些来源时，用户列表只显示标准名称。管理员可勾选“显示旧名称兼容入口”查看旧定义。已有手动名称、独立策略及分组授权保留；仅有旧名称授权的分组不会因为隐藏重复项而失去原来的可见入口。

## Qoder CN 映射（默认目录版本 3）

Qoder 的内部代号仍用于实际上游请求，公开名称使用对应标准型号。对应表位于 `backend/internal/catalog/default_models.json` 的 `qoder_cn_aliases`。`dfmodel → deepseek-v4.1-flash` 由管理员在 2026-11-06 明确确认，目录只标注 DeepSeek-Flash；其余九项依据同日官方账户目录显示名称。

## 图片能力和 Pi 同步

共享模型对已授权、已启用且明确支持的来源取能力可用性：有视觉来源即声明图片支持，有工具来源即声明工具支持。组合请求必须找到同时满足所有能力的同一个来源；不支持或未知来源不承接对应请求，禁止删除图片后转发。全部没有可用来源时返回明确错误。

上下文/输出推荐继续要求来源参数有依据，不凭空补齐。`/v1/client-profile` 在缺参数时返回 HTTP 200 的能力信息，`client_profile_status=missing_limits`，省略未知数值；`/v1/models` 继续独立返回图片能力及 client_profile_error。这不表示未知来源已经获得上下文保证。

Pi 使用当前 codearts-local 配置时，可运行 `python3 scripts/connect-client.py pi --url http://127.0.0.1:10087 --sync-models`。脚本先备份 ~/.pi/agent/models.json，更新模型名称和图片声明，保留密钥及其他 provider。参数缺失时保留原有用户参数并报告；没有原有参数的新模型跳过，未知图片能力明确报告。已有 Pi 会话应退出后重新启动以加载配置。该同步不自动改动默认模型或分组权限。
