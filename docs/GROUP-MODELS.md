# 分组统一模型

同一个分组可以把多个平台的对应型号映射为一个公开名称。客户端请求不需要指定平台，账号池同时选择账号和该平台的原始型号。例如：

| 客户端名称 | 分组内来源 |
| --- | --- |
| `deepseek-4.1-flash` | `workbuddy/cn/deepseek-v4.1-flash`、`trae/cn/deepseek-v4.1-flash`，也可加入码道 `deepseek-v4.1-flash` |

名称需带版本号。管理员应核对来源确实是希望提供的版本；网关不会因为名称相似就自动认定模型等价。

## 面板配置

1. 打开「账号分组」，新建或编辑分组，将所需平台的账号加入同一组。
2. 在「统一模型」点击「添加映射」，填写 `deepseek-4.1-flash`，多选各平台的对应原始型号。每个平台和地区在同一映射内最多选择一个型号；同平台的多个账号仍共同参与调度。
3. 如启用原始型号白名单，映射来源也必须加入白名单。保存时会检查账号范围、白名单和目录。
4. 在「API 密钥」把客户端密钥绑定到这个分组。客户端刷新模型列表后，使用 `deepseek-4.1-flash`。

映射存放在分组内，因此不同分组可以将同一公开名称配置为不同来源。未绑定分组的密钥、未配置统一模型的分组，继续使用原有模型目录和路由。

示例请求：

```json
{
  "model": "deepseek-4.1-flash",
  "messages": [{"role": "user", "content": "你好"}],
  "stream": true
}
```

Chat Completions、Responses 和 Anthropic Messages 使用同一映射。响应的模型名称保持公开名称；运行日志记录「请求名称 → 实际型号」，费用、模型健康和尝试明细使用真实上游型号。

## 展示和调用权限

配置映射后，该组 `/v1/models` 只展示去重后的公开名称。管理面板的原始型号目录完整保留，不删除或改写上游目录。

原始型号可以隐藏但继续直调，例如 `workbuddy/cn/deepseek-v4.1-flash`、`trae/cn/deepseek-v4.1-flash`、`codearts/deepseek-v4.1-flash`。直调仍须满足当前分组的账号范围和原始型号白名单。启用统一模型的分组将裸名称视为公开名称；要显式调用码道原型，须带 `codearts/` 前缀。隐藏不是授权，分组外的型号仍返回 403。

删除全部映射会恢复该组原有模型列表。映射与全局「强制模型」互斥；旧的全局一对一别名不能替代分组的多个来源映射。

## 调度和兼容边界

- 账号池在同一把锁内选定账号、原始型号并占用在途名额。直调与统一名称共用原有并发限制、冷却和会话粘性。
- 来源列表不表示平台优先级。选号沿用当前账号池策略；平台越多不意味着增加尝试次数，也不增加额外等待。
- 仅在原有错误规则允许、且还未向客户端输出时，才可能切换来源。所有来源共用一次请求的超时和重试次数。客户端错误、内容拦截不盲目跨平台重试。
- 每次尝试从原始请求重新准备，使用所选平台现有的提示词和清洗策略，避免把另一平台的提示词带入重试。本功能未新增全局提示词继承规则。
- 统一名称不创造能力。Messages 显式思考控制沿用现有限制，并在选号前排除已知不支持的 Trae 来源；不会移除客户端参数来假装支持。
- 客户端推荐参数只在各可用来源都有可靠配置时，返回保守的公共建议；不根据公开名称猜测上下文，不借用同名码道模型的能力。来源变化后应重新获取推荐配置。
- 码道已有的同平台摘要备用模型仍受原始型号白名单约束。联网搜索继续使用各平台已有搜索入口，不通过对话模型映射跨平台猜测搜索能力。

## 配置和维护

`/admin/api/groups` 增加可选字段：

```json
{
  "name": "日常模型",
  "account_ids": ["workbuddy-account-id", "trae-account-id"],
  "allowlist_enabled": true,
  "model_ids": ["workbuddy/cn/deepseek-v4.1-flash", "trae/cn/deepseek-v4.1-flash"],
  "model_mappings": [
    {
      "name": "deepseek-4.1-flash",
      "sources": ["workbuddy/cn/deepseek-v4.1-flash", "trae/cn/deepseek-v4.1-flash"]
    }
  ]
}
```

编辑旧分组时省略 `model_mappings` 会保留已有映射，显式传 `[]` 才清除。来源须为当前目录中的原始型号，不能引用另一条映射或别名。每组最多 128 个统一名称。

维护职责：`internal/store/model_mapping.go` 管配置校验，`internal/store/pool.go` 复用选号和租约，`internal/server/group_model_mapping.go` 管请求级解析和型号替换；三平台原生适配器继续只接收各自的真实型号。

状态格式升级到 **6**，旧文件自动迁移。升级前备份；旧版程序会拒绝读取新版状态，避免静默丢弃映射。回退须同时处理状态格式，保留最新账号凭据和用量，不能直接恢复可能含旧 refresh token 的历史文件。

验证结果与实际范围见 [本轮验收](acceptance/GROUP-MODEL-MAPPING-2026-11-01.md)。
