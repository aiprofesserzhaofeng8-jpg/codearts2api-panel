# 用户、分组与共享预算

M7 提供一个管理员管理多个普通用户的单实例模式。普通用户使用已有账号池推理；只有管理员可以登录平台账号、刷新凭据、领取奖励、修改模型/提示词/价格或分组。它不是多个管理员各自上传凭据的租户系统。

## 开始使用

1. 管理员打开 `/login`，使用用户名 `admin` 和原管理员密码登录；在「账号分组」选择可用账号、模型权限、统一名称及默认模型。已有分组可以直接使用。
2. 打开「用户管理」→「创建用户」，填写用户名、初始密码，选择一个分组并设置共享预算。用户名为 3–64 位字母、数字、点、横线或下划线，自动转为小写；密码为 12–256 字节。
3. 将 `/login` 统一登录地址、用户名和初始密码交给使用者。用户登录后可修改密码，在「我的密钥」创建、显示或复制自己的密钥。
4. 客户端使用同一服务的 `/v1` 地址及用户密钥，模型名从「可用模型」复制。例如本机测试实例为 `http://127.0.0.1:10088/v1`；实际端口以启动参数为准。

用户首页提供「仪表盘、我的密钥、可用模型、我的用量、个人资料、修改密码」。仪表盘和明细共享近 7 天、近 30 天或全部历史筛选，按浏览器时区统计；趋势和常用模型使用全部筛选结果，不随明细分页变化。失败请求也计入请求数，缺少用量不当作已测得零用量，费用仍为 USD 参考值。

## 并发与个人资料

管理员可设置用户并发上限 0–1024，0 表示不限；页面创建新用户默认 5，旧用户迁移保持 0，API 创建时未提供该字段也为 0。所有密钥共享该用户的在途计数，原上游账号并发和密钥限流仍同时生效。达到用户上限立即返回 429，不新增等待队列、不执行上游请求、不扣请求预算。降低上限不终止已开始请求，后续调用需等在途数低于新上限。普通用户只读此设置。

用户可以修改最多 40 字的昵称及头像；登录用户名由管理员管理。PNG/JPEG 上传时在浏览器缩放压缩到 20KB 以内，GIF 须自行控制在 20KB 内，服务端独立校验格式、编码和 1024 像素尺寸上限。只接受内嵌位图，不获取外部图片。保存资料不注销会话，也不改变分组、预算、密码或 API 密钥。统一前端允许服务端已校验的位图 data URL；脚本和连接仍仅允许同源。

一个用户必须绑定一个有效分组，该用户的全部密钥随用户分组一起更新。普通用户不能修改分组、所有者和预算；原有管理员密钥不自动分配给任何用户。不分组的管理员密钥仍保留原行为。用户关联的分组不能删除，即使用户已停用。

## 权限和会话

用户只能查询自己的密钥、用量与允许展示的模型；不能访问管理员 API、上游凭据、其他用户记录或账号运维。模型隐藏和禁止调用沿用 [分组模型](GROUP-MODELS.md) 的独立规则；隐藏的型号仍受分组调用权限约束。

所有账号使用同一个 `codearts_session` Cookie，路径为 `/`，角色由服务端会话确定，HttpOnly、SameSite=Strict，有效期 8 小时。服务重启、退出、修改密码或管理员保存用户信息后，旧用户会话失效。密码慢哈希只在登录或改密时计算，推理不计算密码哈希。客户端 API 密钥不能登录用户页面。

登录页没有角色选项。服务端仅接受用户名、密码，不接受客户端指定角色；普通用户直接请求管理 API 返回 403，匿名请求返回 401。`/admin/auth/*`、`/user/auth/*` 旧登录路径已移除，管理密码请求头、Bearer 管理密码及本机自动解锁均不再支持。管理脚本需先向 `/auth/login` 提交 `{"username":"admin","password":"..."}`，保存会话 Cookie 后再请求管理 API。推理客户端继续使用 `/v1` 和 API 密钥。

**修改或重置密码保留已有 API 密钥。** 怀疑密钥泄露时应停用用户或删除对应密钥。停用用户立即阻止后续认证和新尝试准入，不强制撤回已经开始的上游请求或已发送内容。重新启用后，保留的启用密钥可以再次使用。修改分组会更新所有密钥，已有会话需重新登录。

每用户最多 32 把密钥和 16 个会话；实例最多 1024 个用户、2048 个会话。达到会话上限时淘汰最早到期会话；用户仅支持停用，保留稳定 ID 和历史归属。

## 预算和历史

三项用户预算的 0 均表示不限。用户的全部密钥共同累计请求数、输入加输出 Token 和 USD 参考费用；管理员还可以给单把密钥设置更紧的预算，两者同时生效。

用户列表的「累计费用 / 上限（USD）」是已消耗费用与累计上限；额度管理的「当前余额」是剩余额度。两者同时生效，余额只按实际费用扣减一次；补充余额不会增加或重置累计费用上限。例如累计上限为 100 USD、余额为 1010 USD，费用累计达到 100 USD 后，即使仍有余额也会停止后续调用。若只需余额控制，可将用户累计费用上限设为 0，其他请求数、Token、密钥和套餐限制仍独立生效。

- 请求数在原锁内跨密钥预留；同一逻辑请求的重试计一次，参数错误且没有上游尝试时不扣次数。
- Token / USD 沿用实际用量结算的软预算。启用其中任意一项时，该用户跨全部密钥最多一个在途推理，单次请求仍可能超额。它不是支付系统或预扣费硬上限。
- 所有已报告尝试的真实消耗都会累计，包括失败或重试。缺少用量会阻止相应计量预算的后续调用；缺少模型价格会阻止 USD 限额调用。管理员核查后可以重置预算。
- 原生搜索缺少 Token / 费用回执，只接受不限或请求次数预算。不能用搜索绕过计量预算。
- 有在途请求时不能更改或重置该用户的共享预算。停用和更换分组仍按当前权限生效。
- 删除密钥、清空运行日志、重置预算都不会删除该用户的用量历史。记录使用不可变用户 ID 归属，已删除密钥的在途消耗也归原用户。

预算累计跟随原同步结算账本持久化，账本写入失败则停止新推理。历史明细沿用全实例最近 100000 条的保留范围，不是每个用户各 100000 条；筛选、统计和分页先按用户过滤。预算累计独立于明细保留。用户明细隐藏上游账号、完整密钥、平台内部错误和尝试详情；管理员仍可诊断实际使用的型号。

## 部署与升级

仍使用一个 Go 进程和本地 JSON/结算账本；不能让多个实例共写同一目录。多人访问时使用 HTTPS，保留管理员登录、禁用本机免登录及匿名调用。TLS 在代理终止时，在「用户管理 → 用户权益 → 登录与邮件」填写 HTTPS 公开地址，用户 Cookie 会使用 Secure；管理员 Cookie 仍应由受信代理设置 Secure。程序不信任客户端伪造的转发头。用户接口仅接受同源请求，不扩展管理员的 CORS 例外。

schema 7 自动迁移到 8、9，再升级到当前 10，原账号、密钥、分组、价格、提示词和用量不变，不创建示例用户。即使最后一把密钥被删除，只要存在用户，也不会恢复匿名推理。新增的用户并发规则不能让旧程序忽略，因此 旧程序拒绝 schema 10。当前没有提供 10→9 或 9→8 导出；使用最新状态向前修复，不能手改版本号或恢复旧凭据备份。

M6 旧程序拒绝 schema 8；历史工具 `tools/convert_state_v8_to_v7.py` 仅用于尚未升级的 schema 8 最新状态，并拒绝任何用户、密钥归属或用户历史/待结算记录，不接受 schema 9 或 10。见 [ADR 0011](adr/0011-single-instance-consumer-users.md) 和 [本批设计](adr/0012-consumer-profile-dashboard-concurrency.md)。


## 共用控制台界面

管理员 `/` 和普通用户 `/user` 使用同一套侧栏、顶栏、浅黄色明暗主题及登录外观，按所在空间显示功能。侧栏底部可切换「管理空间 / 个人空间」，主题与桌面侧栏折叠偏好会保留；手机点击左上角打开导航。用户页面支持 `/user#keys`、`/user#profile` 等直接链接，刷新保留当前功能页。

两种登录会话仍独立：管理员密码不用于普通用户登录，普通用户切换到管理空间也不会获得管理员权限。此项界面调整无需状态迁移，不改变账号池或模型转发逻辑。

## 额度、兑换码和订阅（schema 10）

管理员在「用户管理」下方的「用户权益」配置；普通用户进入 `/user` 的「额度与兑换」。旧用户默认不限余额，不会因为升级而要求充值。

- **额度管理**：选择用户、输入正数发放或负数扣减、填写原因。勾选「启用余额限制」后按已配置 USD 参考价格扣减。没有支付渠道；这是内部额度，和平台积分、上游实际账单独立。支持 8 位小数。
- **实际结算**：余额请求在调用前估算预留，结束后按真实回执结算，失败但已产生消耗也计入。取消或未调用上游不会凭空扣费。软额度可能被一次实际消耗超出，负余额会阻止后续请求；缺用量或价格则暂停，请管理员核对。预留使用请求字节数和 8192 输出 Token，超长输出和多模态无法保证严格硬上限。原用户/密钥 Token、USD 预算规则继续叠加。
- **兑换码**：管理员生成额度、并发增量或套餐码，完整值只显示一次。每码仅兑换一次，过期或停用不可兑换。并发码同时提高用户与当前套餐的有限并发上限，不改变套餐模板；已经不限并发则拒绝无效兑换。订阅到期时仍能登录并兑换续期。
- **套餐与订阅**：套餐指定分组、并发、额度周期和有效天数。分配后用户密钥一起切换分组；同套餐未过期续期保留快照与已用量，过期重开。周期为 UTC 每日、周一、每月一日或订阅总量。到期、停用立即拒绝新推理。修改模板不影响既有订阅；移除订阅限制是管理员显式操作，保留分组，恢复普通预算。
- **在途保护**：用户有在途请求时，调整钱包、兑换、切换订阅会拒绝，请结束后再试。避免把旧请求计入新权益。余额预留支持并发；Token/USD 套餐沿用单在途软预算。用户额度流水保留全站最近 10000 条范围，累计余额不随历史清理重置。

## 邮箱和第三方登录

管理员在「用户权益 → 登录与邮件」配置 SMTP（465 TLS 或支持 STARTTLS 的端口）和 GitHub/LinuxDO OAuth 应用。公开地址填写 origin，例如 `https://panel.example.com`，不要尾斜线或路径；第三方应用回调统一为 `https://panel.example.com/auth/oauth/callback`。

用户在「登录方式」发送邮件验证码并验证邮箱；登录页提供已验证邮箱找回密码。验证码 10 分钟有效、最多 5 次错误、单次使用，重启失效。找回成功撤销已有用户会话，保留 API 密钥。未配置邮件时界面显示未启用，不返回测试验证码。

第三方账号需要先密码登录，再从「登录方式」绑定；随后可在登录页选择第三方登录。不提供自动注册或按邮箱合并，以免带入错误分组权限。解绑会撤销会话，需要重新登录。OAuth 令牌只临时查询身份，不保存在用户或上游账号中。

SMTP 密码、OAuth Secret 只保存在权限受限的状态文件；读回配置不返回秘密。输入框留空保留，勾选清除后才删除。没有真实邮件和 OAuth 应用配置时，只能验证模拟流程，不能声称已完成实际邮件投递或第三方授权。
