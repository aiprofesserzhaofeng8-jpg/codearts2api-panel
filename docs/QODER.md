# Qoder 上游

Qoder 作为第四个独立平台接入现有账号池。首批覆盖国内 CN 与国际 global 的浏览器设备授权、凭据导入、自动续期、动态模型目录、对话/工具数据转发和统一计量。它使用非官方原生协议，不启动 CLI，也不会执行模型返回的工具。

## 添加与调用

1. 管理员进入「账号池 → 添加账号 → Qoder」。
2. 选择「浏览器授权」，下一步选择国内/国际地区，生成链接，在官方页面完成授权。
3. 回到面板点击「检查授权」。身份预览确认后，点击保存才会入库；关闭/取消不会保存账号。
4. 刷新模型清单，复制该账号地区的完整模型 ID，例如 `qoder/cn/<chat目录的key>` 或 `qoder/global/<chat目录的key>`。没有账号时不预置模型，展示名称也不能代替原始 key。
5. 使用已有的 `/v1/chat/completions`、`/v1/responses` 或 `/v1/messages`，均支持流式与非流式。统一模型在「账号分组」中添加映射，公开名继续带版本号，来源选择刷新得到的 Qoder 型号及其他平台的对应型号。

分组控制实际账号和型号权限。隐藏原始 ID 不代表禁用：在权限范围内仍可明确指定完整 ID；不可通过隐藏型号绕过分组。CN 与 global 不自动互换，也不把同名不同平台型号当成同一模型。

「凭据导入」接受平台自己的扁平 JSON，至少包含 `access_token`、`uid`、`expires_at`、`machine_id`、`scope`；续期需要 `refresh_token`。`expires_at` 接受 Unix 秒/毫秒或 RFC3339，`scope` 为 `cn` / `global`。只导入自己的有效凭据，面板会向官方 userinfo 核对身份后保存。推荐直接浏览器授权，以获取服务端确认的用户类型等信息。不会扫描或自动读取桌面客户端状态。

## 配置与边界

- 「配置 → Qoder」支持继承公共提示词或逐项覆盖，新平台默认继承。统一模型最终选中哪个平台，就应用该平台的策略。
- 动态目录只展示启用的系统 chat 型号，不包含 BYOK、自定义 endpoint、嵌入或编辑专用目录。上下文/输出推荐值仅取上游明确提供的元数据，不猜测模型能力或价格。
- 已接入套餐、附加和组织共享 Credits 查询，分别显示实际数值；未设上限的共享池不转换为无限积分。每日活动积分已接入，独立联网搜索尚未接入。未知计费不会算成免费；USD 预算仍需配置型号价格。见 [账号额度](ACCOUNT-QUOTAS.md)。
- 凭据解释及网络调用留在 `backend/internal/qoder`。续期锁、CAS、选号、分组、并发、重试和结算沿用现有服务，不另建调度器或模型缓存。
- 断流、错误信封或缺少完成事件会记为失败；已向客户端输出后不换号重放。客户端取消会取消上游请求并释放原有租约。
- 协议标识为 CLI 1.1.81，服务端端点可能随客户端更新；此适配不等于官方公开模型 API。签名资料及许可见 [UPSTREAM.md](../backend/internal/qoder/UPSTREAM.md)。

## 当前验证范围

自动回归使用临时状态与本机 HTTP 模拟上游，不读取现有账号、不消耗真实额度。覆盖设备授权 PKCE、预览/确认与管理员权限、续期轮转、模型目录、签名编码、三个客户端协议、工具数据/大整数、CN/global 路由、统一映射/白名单、用量与租约，以及断流/取消。

2026-11-03 本地验证通过：`make check`（含 37 项前端单元测试、Go 全包测试/vet、API 类型、架构和 86 项部署测试）；Qoder 适配器及网关集成的 race 检查；17 个浏览器场景。新增浏览器脚本为 `scripts/qoder-smoke.cjs`，已加入 `make e2e` 的测试清单，验证授权、确认保存、地区/用量筛选、提示词继承/覆盖和手机布局。

真实 Qoder 账号登录、模型生成和到期续期尚待验收。添加自己的账号后，应先以一个目录型号发送一次小请求，核对后台所用 key、用量日志和 Qoder 官方账号页面，再扩大使用范围。

## 每日活动积分

账号行「每日签到」、顶部批量领取及现有自动领取设置均可使用。CN/global 分别查询各自 OpenAPI 的 campaigns；仅领取当前活动窗口内、上游标记 CLAIMABLE、积分类型 CREDITS 且前置条件已满足的活动。活动 ID、金额来自当前响应，不硬编码每日 100 分，也不提交邀请、订阅或优惠券任务。

提交后重新查询同一活动，只有 CLAIMED 才确认；请求失败不重放领取，先只读复查。活动消失或复查失败显示待确认，不当作到账。空活动列表表示暂不可领，可在官方客户端检查资格，不借用其他账号的活动 ID。确认后失效现有额度缓存。

Qoder 的领取日期按北京时间 10:00 切换，避免零点重复领取或 10:00 后跳过新周期。未确认的结果沿用现有 30 分钟等待期，不新增后台定时器；升级不自动打开自动领取设置。

隔离 HTTP 回归覆盖 CN/global、资格过滤、同活动复查、业务失败及重定向。2026-11-09 单账号真实领取与复查通过，生产面板端到端流程仍待更新后验收；客户端风控、额外会话或设备要求应依据真实响应单独诊断，不伪造设备或活动资格。
