# Panel 增强实现

本分支基于 CodeArts2API c11aa7b，原始协议勘察和继承功能见 UPSTREAM.md 与 UPSTREAM-README.md。
原仓库文档中未提及的新行为，以本文和根 README 为准。

## 调用链

API 鉴权 → 按密钥限流与预算预留 → 校验模型 → 派生会话哈希 → 原子选号并占用名额 → 解析/刷新 STS 凭据 → 签名请求 → 聚合或流式返回 → 释放名额。

- `internal/store/pool.go`：原子租约、三种策略、有界会话绑定、暂停与冷却。
- `internal/server/routing.go`：会话键、已开始输出的错误标记。
- `internal/server/chat.go`：整个请求共用超时预算、错误分类与故障换号。
- `internal/server/admin.go`：面板池状态、配置校验、暂停/恢复操作。
- `bootstrap.go`：首次启动生成独立管理员密码和调用密钥。

## 调度规则

会话优先使用原账号。未命中绑定时，可选 round_robin（轮询）、least_inflight（最少在途，平局按轮询）、sequential_exhaust（继续使用当前账号，无法使用时顺序向后）。
单账号并发默认 2；所有账号饱和、暂停、禁用或冷却时返回 503，不提前使用冷却账号。
会话键优先取 X-Session-Id，其次 conversation_id，再按 system/developer + 首条 user 推导；所有键同时包含 API 密钥和模型的哈希。同样的首条消息可能碰到同一绑定，需精确隔离时应显式传会话 ID。
绑定默认 30 分钟滚动过期、最多 4096 个，只存在内存。并发计数同样只存在内存，进程退出后重置。暂停、冷却、失败次数存入状态文件。

错误策略：

| 错误 | 处理 |
| --- | --- |
| 429 / 上游并发限制 | 默认只冷却该账号的该模型 60 秒，不增加连续故障次数，尝试其他可用账号 |
| 上游 5xx | 该账号的该模型短冷却至多 5 秒，尝试其他可用账号 |
| 无法刷新凭据 | 冷却一个熔断周期，提示重新登录 |
| 其它账号/传输故障 | 增加失败次数；默认连续 3 次熔断 300 秒 |
| 请求参数错误 | 直接返回，不罚账号 |
| 客户端取消 / 整体超时 | 停止重试并释放名额 |
| 已向客户端输出流式帧后失败 | 发送流式错误，禁止重新开始另一次生成 |

同一请求遇到非临时故障后不会再次选择已尝试账号。rate_cooldown_sec=0 可关闭临时冷却，仍有退避与尝试次数限制。清错会解除冷却；暂停选号保留刷新余额和领取等维护能力。

## 验证范围

新增测试覆盖并发名额、策略选择、会话续期/隔离、暂停/恢复、冷却持久化、重登去重、模型请求签名与提示词/工具透传、流式部分输出后失败、鉴权隔离、配置校验和首次初始化。
上游 HTTP 使用本地内存响应模拟；测试不登录华为账号、不消耗积分。浏览器登录、真实凭据续期和实际模型可用性需要账号完成端到端验收。

当前采用单进程架构。多个实例不能共享同一个状态文件，也没有跨实例的并发名额或会话协调。

默认必须使用管理员密码登录。浏览器通过 HttpOnly / SameSite=Strict Cookie 使用 8 小时会话，不保存管理密码到 Web Storage；密码使用 PBKDF2-SHA256（600000 次，随机盐）保存，修改密码和进程重启撤销会话。只有显式设置 `CODEARTS_LOCAL_AUTO_UNLOCK=true` 才启用旧的本机自动解锁兼容模式。两种管理权限都不能代替 `/v1/*` 的调用密钥。详情见 [管理增强说明](MANAGEMENT.md)。

## 添加与删除账号的确认流程（后续修订）

10087 码道面板采用原生 HTML dialog 模态窗口。点击浏览器登录只显示窗口；生成链接、复制到另一浏览器、提交回调或凭据、核对预览、确认保存是独立步骤。没有自动打开标签页，也没有轮询自动入池。`login/poll` 只返回脱敏预览，`login/complete` 才原子保存凭据。同一流程重复确认只执行一次；删除后重放旧确认不会重新创建账号。

读取华为 caller-identity 时兼容官方扁平结构 principal_id / principal_urn / account_id，以稳定账号标识识别重新登录，不依赖每次改变的 AK。

删除操作使用面板内确认窗口，替代原生 JavaScript confirm。服务端仅在新状态成功落盘后返回成功；写入失败恢复内存账号并返回错误，界面显示具体失败。测试只使用临时状态文件与模拟账号，不删除实际部署的账号。

## 浏览器登录修复（2026-10-25）

核对本机官方 `huaweicloud.authentication` 扩展 5.4.2 的 `buildLoginUrl`、`doLoginTask`、`doGetAuthenticationByTicketId` 与 `doCreateOldLoginAuthentication` 后，修复基础实现遗漏：`secret` 并非必然是 OAuth 授权码的前置回调，而是另一条登录票据流程。

- 授权 URL 中的 ticket_id 必须保留，并与回调 secret 一起请求 `GET https://snap-access.cn-north-4.myhuaweicloud.com/snap-manager/v1/login/ticket`。
- 登录请求的 plugin-version 使用认证扩展版本 `5.4.2`，与推理接口的 IDE 版本分开。
- 响应读取 user_name、domain_id、credential.access / secret / securitytoken / expires_at；票据凭据不标记为可自动续期。
- 同一流程仅启动一次凭据交换；取消或超时会取消在途交换。OAuth 收到 code 后只展示处理中，不在换取成功前宣告登录成功。
- 前端在点击时打开标签页，弹窗被拦截则提供普通链接；sessionStorage 保存当前标签页的登录流程，刷新后继续查询；临时轮询失败不会直接丢弃流程。

新增回归测试覆盖票据等待、凭据有效性、网络错误脱敏、重复回调、OAuth 交换、账号入池持久化与去重。模拟测试通过不代表已完成真实账号认证；实际账号仍需用户在官方网页授权。
