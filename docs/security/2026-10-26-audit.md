## 结论

未在本次检查范围内发现真实密钥已泄露的证据，但存在已复现的鉴权/转发缺陷和需要保留说明的信任边界。已修复下表中的缺陷并更新本机服务。不能将本报告视为“没有任何漏洞”的保证。

当前服务仅监听 `127.0.0.1:10087`，管理密码已设置，匿名模型调用关闭，无额外 CORS 白名单。`data/` 权限 0700；状态文件、首次凭据文件、USD 迁移备份均为 0600。Pi 的模型配置（含本地调用密钥）为 0600。

## 已修复

| 问题 | 风险与触发条件 | 修复与验证 |
| --- | --- | --- |
| 无管理密码时，本机兜底鉴权仅验证 TCP 地址，不验证 Host | 条件性高风险。恶意域名解析到环回时可命中无密码管理接口；是否可从浏览器利用还取决于 DNS/PNA 等环境限制。当前已配置密码，不受此无密码分支直接影响。 | 本机匿名鉴权同时校验 Host 为 localhost/127.0.0.1/::1。模拟不可信 Host 请求从原先 200 变为拒绝。测试 `TestNoPasswordRejectsDNSRebinding`。 |
| 上游客户端默认跟随 302/307/308 重定向 | 若上游或其信任链返回恶意重定向，STS 自定义请求头可被转发；307/308 还可转发含 refresh token 的请求体。没有证据表明真实华为服务这样做过。 | 禁止认证/签名 HTTP 客户端自动重定向。两个本地 HTTP 服务器复现旧行为，新版本未访问重定向目标。测试 `TestCredentialRequestsDoNotFollowRedirects`。 |

| 管理密码认证无失败次数限制 | 对外开放管理接口且密码较弱时可无限尝试。当前随机密码、环回监听降低了实际风险。 | 每个直接连接 IP 每分钟最多 20 次失败，超限返回 429；计数器有容量限制，不信任客户端转发头。正常本机面板 capability 不受失败计数影响。 |

## 仍然存在的边界和后续优先级

1. **本机自动解锁信任本机所有可连接进程。** 本机进程可以读取页面中的 capability，然后访问管理员功能，包括显式导出上游凭据。文件 0600 不能阻止同用户进程，也不能阻止其他能连接环回服务的系统用户通过这条 HTTP 路径访问。该行为源自既有“本机打开无需密码”的需求。本次未取消此使用方式。共享电脑或远程部署应先改为强制管理员登录，并关闭本机自动解锁。
2. **状态文件和备份没有静态加密。** API key、管理密码、STS/refresh token 等可从文件中直接读取；文件权限只隔离其他操作系统用户，不能抵御同用户恶意程序、管理员权限或被外传的备份。下一步适合将管理员密码改为慢哈希，并对需要可逆读取的上游凭据/API key 采用系统密钥环或独立主密钥加密；主密钥与状态文件一起泄露时，加密没有实际隔离作用。
3. **反向代理不能依赖“程序绑定本机”来保护管理接口。** 若代理把外部请求转给环回地址，同时重写 Host 为本机且不设置转发头，服务无法从 HTTP/TCP 信息区分它与真正本机请求，可能发出本机 capability。当前未发现此类代理，但仅检查了进程监听和应用配置，未枚举所有外部隧道。对外部署必须关闭自动解锁，并由反代隔离管理面。
4. **远程 HTTP 会暴露密码、API key 和导出凭据。** 当前监听仅环回，本机 HTTP 不经过外网。若要远程访问，应使用 HTTPS 或 SSH 隧道。浏览器远程密码目前保存在 sessionStorage 并随管理请求发送，尚无独立登录会话、细粒度角色或二次验证。
5. **剪贴板/导出属于显式泄密通道。** 点击复制后，系统剪贴板管理器、远程桌面剪贴板等可能获得密钥；手动导出的 session JSON 含完整凭据。保留这些功能是用户明确要求，不能把页面的密码输入框当作加密保护。
6. **外部 URL 与资源限制仍有加固空间。** 登录回调跟随逻辑有域名限制，但管理员可指定自定义 HTTPS 门户，也允许部分回环访问；不应把它宣传为通用 SSRF 沙箱。部分管理请求仍缺统一请求体限制。权限已受管理鉴权保护，本次未重写登录协议和部署模型。
