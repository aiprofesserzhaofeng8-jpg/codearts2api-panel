# 应用装配与生命周期

- Build 只创建依赖和连接原回调；不访问上游、不启动后台或 HTTP。Store 始终是原准入、凭据提交、预算、用量和配置事务的唯一写入方。
- Start 由 main 在初始化/导入和本机管理员模式设置后调用一次。它先应用身份头，再启动原三条后台流程，随后创建 Handler 和 HTTP 监听协程。ReadHeaderTimeout=20s，不配置 WriteTimeout 或 BaseContext，不改变请求取消语义。
- Runtime.Errors 只把非 ErrServerClosed 的监听错误交给 main；main 保留原致命日志与退出码。正常停止不关闭该通道。main 仍持有 OS 信号注册、命令行/环境覆盖、首次访问文件和桌面导入/导出，后续清理应独立验收。
- Close 由进程所有者调用一次：先打印关闭日志，以独立 10s 上下文 Shutdown，随后无论 Shutdown 成败都尝试原 Store.Save，打印退出日志，最后取消后台轮询。没有新增 HTTP 强制 Close、等待任务或额外保存。它不是可重复调用或多实例协调接口。
- 后台领奖仍由 jobs.RunDailyLoop 执行：8s 延迟，首检完成后才创建 5min ticker，串行调用现有 RunDailyClaim。周期保存仍是单协程 30s ticker，失败只记录日志后继续。两者共享原取消上下文，取消不 join 已在执行的操作。
- 启动目录刷新仍只有一次，使用独立的 context.Background()+60s，失败/成功日志与原来一致，不因轮询取消而提前结束。不新增自动续期、领奖、重试或目录副本。
- 这些限制保留迁移前的生命周期保证，不承诺后台任务在进程退出前全部完成。后续若调整停机顺序、任务等待或期限，须独立设计和验证，不能混入纯迁移。
