# TeleAgent protocol references

`backend/internal/teleagent` implements the account-bound TeleAI model gateway, identity checks and credit queries. Protocol facts were cross-checked against MIT projects `liao96312/teleagent-proxy` (875a2b4080ded5f9eebada6d43c94c77ebddc5a5), `anbulang/dsh-connect-teleagent` (14bb4bb16d6961addff63ced79866f9a74391108) and `anye-99/dsh-codearts-auth` (686658793c982cd0e1baedbcfa10a396ce5d1a09). The notices are retained in `LICENSE.teleagent` and distributed with all packages/images. No desktop runtime, account files or third-party embedded gateway key are bundled. See [TeleAgent](../../../docs/TELEAGENT.md) for supported fields and unverified real-provider scope.

Browser login uses the fixed UPMS authorization/cowork callback and the callback observation described in `dsh-codearts-auth/src/teleagent-cdp-login.ts` at that revision. `scripts/teleagent-login.mjs` is a standalone standard-library helper embedded verbatim into the frontend for download. It observes only its own temporary browser and the exact callback, does not invent a code exchange endpoint, and does not copy the reference project's embedded key or speculative local signing key. Task binding, read-only upstream identity verification and final persistence reuse the existing staged login service.

Daily rewards use the v2 daily-task status and explicit `checkTask?type=daily_login` paths recorded in `dsh-codearts-auth/src/teleagent-credits.ts` and `dsh-connect-teleagent/lib/portal.js` at the revisions above. The installed TeleAgent 3.0.0-rc.4 renderer retains those path constants and separately uses v3 activity display plus an untyped first-login/monthly action. Only the explicit daily action is implemented; untyped checks and activity links are not executed by list reads. Post-claim status must positively confirm receipt; the reference's success fallback when rechecking fails is not adopted.
