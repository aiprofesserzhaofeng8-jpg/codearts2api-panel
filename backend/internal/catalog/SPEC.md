# catalog

M3.15 已迁移目录刷新、刷新状态缓存与模型测活协调。Registry 仍是唯一模型清单和解析方；本包不保存第二份目录，不解释凭据，也不进入普通推理执行。

- app 构造一个 Runtime，借用 Store 的账号/配置快照与同一 Registry。HTTP 投影现有平台操作；原生 CodeArts 包装仍使用同一 Manager/Client，其他平台仍走原凭据与 chatOnce。
- 刷新串行锁、刷新状态读写锁和测活任务锁保持独立，锁范围与顺序不变。按平台/地区刷新，失败可继续尝试同分区其他账号；成功后跳过剩余账号。失败保留旧分区，保留原部分成功与错误展示规则。
- stale 刷新仍同步完成、独立后台 Context 30s；成功和失败均记录 loadedAt。不改为异步刷新，不增加重检/合并，也不改管理员刷新 60s 的 HTTP 截止时间。
- BeginProbe 必须在 HTTP 解码前取得任务锁；成功取得的 ProbeRun 由调用者 Close 一次，任务完成前不能释放。HTTP 原有宽松解码与方法行为不在结构迁移时收紧。
- 测活仍最多 64 个去重型号，4 路模型并发，每个型号按账号顺序尝试，单账号尝试 30s。CodeArts 使用原生 Probe 参数，其他平台使用原 chatOnce 参数；保留取消、结果顺序及旧错误字段语义。不借本次迁移新增重试、账号租约或健康/账本写入。

准入、模型解析与映射产品能力、账号连通性探测、积分查询和后台任务在其他既有入口中。本阶段没有将整个目标 catalog 能力宣称为完成。

M6 的 presets.go + mapping_presets.json 维护显式建议与当前目录交叉验证；不参与推理热路径，不自动写组。Routing 解释分组默认、独立列表规则与客户端偏好，允许调用仍由 storage 原子入口复核。物理来源禁用会缩小映射候选；列表不以 callable 代替 visible。

U3 的 unified_routing.go 从唯一全局定义读取公开名称与来源，并产生带版本的单请求计划；权限来自当前 AccessScope。能力过滤只收缩本请求候选。storage 在原子准入内重新检查模型 revision、routing revision 与 grant；catalog 不取得租约、不维护第二份权限状态。旧分组映射路径仅作为阶段兼容接口，实际 Store 已使用全局定义。模型列表/profile 的全面切换已在 U4 完成。

## U4 HTTP 投影

全局列表和客户端策略从同一配置快照计算；ClientModels 不按行复制全局定义，不在列表/profiles 中占租约或刷新凭据。可见性独立于可调用性，零账号及冷却不删除可见定义。保存的缺失来源仍参与资料完整性判断；不得仅凭剩余来源提高上下文/图片/工具声明。

管理详情只提供规范定义、公共策略、引用和带时间戳的本地来源状态；Store 仍唯一持有提交和并发条件。原探测结果未留存完整记录时 last_probe 为 null，不把正常请求健康伪造成探测成功。

R5 的来源详情分别投影精确来源的能力、账号调度快照、最近保留请求与既有账号额度缓存。调度快照只读，不能代替当前分组授权或原子准入；额度快照明确时间与过期标记，失败/缺失不是零，冷却结束不是配额重置。仅管理员读取详情时计算，不探测上游、不刷新凭据、不新增持久化状态或后台任务。本页显式文本测活保留页面内结果，不扩大为图片/工具验证。

R6 的 client_metadata.go 复用同一版本化目录，为少量精确来源维护用途与有证据的客户端操作建议。通过原 ModelPolicies 的纯推荐函数装配使用，不写入运行时状态；共享策略仍受全部授权来源约束，Qoder 已审核身份变化后不产生共享数值建议。官方原文窗口标签、上游目录数值、已保存策略和实测建议分开表达，原始目录 Context/MaxOutput 不回填。ClientCompatibility 仅决定客户端自动导出建议，不修改模型可见性、推理能力、准入或健康；共享名称的公开投影隐藏精确来源，管理员详情保留证据。

R6 后续直接复用 Sub2API 的 modelmeta 纯合并/解析函数：现有聊天入口缺参时补精确原生 ID 的公开数字资料，仍缺参使用标注为默认值的 32768 / 4096 客户端模板。来源已有数值逐字段优先；管理员和已验证建议保持优先级。公开资料仅在原 Refresh 串行锁内通过注入的 HTTP 操作获取，成功缓存 6 小时、失败退避 30 分钟、5 秒截止；缓存只存公共参考资料，不能成为第二份可用模型目录。新发现模型无需先压测才能导出。原始上下文、输出、图片和工具观察不修改，缺失来源占位行和共享身份变化保护保留。没有新后台循环、数据库、文件存储、推理网络查询或第二份能力配置表。

R2 的 source_capabilities.go 读取同一 default_models.json 中带日期、证据引用的精确来源能力，只在现有字段缺失时补充。明确的上游否定值优先，别名使用其原始来源键；需要展示名称核对的 Qoder 别名变更后停止补充。缺失目录的占位行不获授已验证能力。共享模型仍受原生规格上限及同一来源组合能力筛选约束，不新增运行存储、探测循环或每请求网络查询。来源增强服务的成功不构成底模身份凭证。
