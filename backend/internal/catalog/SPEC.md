# catalog

M3.15 已迁移目录刷新、刷新状态缓存与模型测活协调。Registry 仍是唯一模型清单和解析方；本包不保存第二份目录，不解释凭据，也不进入普通推理执行。

- app 构造一个 Runtime，借用 Store 的账号/配置快照与同一 Registry。HTTP 投影现有平台操作；原生 CodeArts 包装仍使用同一 Manager/Client，其他平台仍走原凭据与 chatOnce。
- 刷新串行锁、刷新状态读写锁和测活任务锁保持独立，锁范围与顺序不变。按平台/地区刷新，失败可继续尝试同分区其他账号；成功后跳过剩余账号。失败保留旧分区，保留原部分成功与错误展示规则。
- stale 刷新仍同步完成、独立后台 Context 30s；成功和失败均记录 loadedAt。不改为异步刷新，不增加重检/合并，也不改管理员刷新 60s 的 HTTP 截止时间。
- BeginProbe 必须在 HTTP 解码前取得任务锁；成功取得的 ProbeRun 由调用者 Close 一次，任务完成前不能释放。HTTP 原有宽松解码与方法行为不在结构迁移时收紧。
- 测活仍最多 64 个去重型号，4 路模型并发，每个型号按账号顺序尝试，单账号尝试 30s。CodeArts 使用原生 Probe 参数，其他平台使用原 chatOnce 参数；保留取消、结果顺序及旧错误字段语义。不借本次迁移新增重试、账号租约或健康/账本写入。

准入、模型解析与映射产品能力、账号连通性探测、积分查询和后台任务在其他既有入口中。本阶段没有将整个目标 catalog 能力宣称为完成。

M6 的 presets.go + mapping_presets.json 维护显式建议与当前目录交叉验证；不参与推理热路径，不自动写组。Routing 解释分组默认、独立列表规则与客户端偏好，允许调用仍由 storage 原子入口复核。物理来源禁用会缩小映射候选；列表不以 callable 代替 visible。
